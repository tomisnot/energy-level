# 已验证的 UI 设计模式（科学计算软件 · 参数密集型 GUI）

这些模式在真实迭代中被用户认可，可直接套用。

## 1. 简单模式 / 上帝模式双层

- 主界面只留一个**模式开关**（高亮色）+ 一个"打开面板"按钮；
- 开关打开即弹非模态面板，简单模式行为逐像素不变、零开销；
- 高级参数**不放主界面**（挤占空间+记忆负担），放进面板里它们语义所在
  的位置（见模式 3）。

## 2. 求解过程可视化 = 处理链分页

按引擎实际执行步骤分页，每页回答一个问题：

| 页 | 回答的问题 | 内容 |
|---|---|---|
| 处理链 | 软件对我做了什么？ | 每步关键数字摘要（见模式 4） |
| 哈密顿量 | 谁耦合谁、多强？ | 热图 + 自适应物理刻度 + 分项叠加 |
| 耦合对 | 参与计算的对是否正常？ | 排序表 + 失谐直方图 + 阈值警戒线 |
| 求解过程 | 数值积分健康吗？ | 步长历史曲线 + nfev/接受/拒绝/norm |
| 扇区 | 中间量内部一致吗？ | 扇区幅值曲线 + topn 过滤 |
| 引擎参数 | 哪些阈值可调？ | params.py 默认值 + 运行级覆写表 |

## 3. 旋钮放在语义位置 + 就地重跑

- 每个可调参数放在**它能影响的那个页面**（如 AC 化阈值在"AC 化"卡片所在页），
  不集中在主界面或统一设置页；
- 每组旋钮配一个 **"⟳ 应用并重跑"** 按钮（信号 → 主窗口触发新一轮运行），
  用户改完立即看到效果，不需要回主界面找"运行"；
- 参数**空 = 默认**（占位符写"默认"），覆写仅本次运行生效，不写回全局。

## 4. 大卡片模式（步骤/摘要的主体化）

- 每步一张全宽卡片：左侧色条 + 步骤徽标与标题 + 中部 kv 明细 +
  **右侧 19px 大号关键数字**（一个数，如 `dim = 1452`）；
- 卡片平分主体空间（stretch=1），辅助表格退居底部固定高度；
- 卡片浅色底 + 数字用步骤色 + 加粗——醒目度必须压过底部辅助表格；
- 注意 QSS 选择器：`QFrame{...}` 会命中子类 QLabel（QLabel 是 QFrame
  子类），用 `QFrame#objectName` 限定。

## 5. 自适应物理刻度（大数据量图形的核心体验）

- 缩放/平移挂视野变化回调，重算逻辑纯函数化；
- **视野大**：抽稀短标签；**视野小**（span≤30 个单位）：逐维全标注
  （名称 | 分组 | 数值），密度统一 ≤10 个刻度；
- 长文本必须折行（防 boundingRect 超轴宽被整组丢弃——pyqtgraph 隐形坑）；
- 淡网格线（alpha≈0.18）提供标签↔数据的对齐参照；
- pyqtgraph 而非 matplotlib：滚轮缩放/拖拽是 GPU blit，几千维也不卡
  （组件见 pyqtgraph_adaptive_heatmap.py）。

## 6. 分项着色联动

解析公式（富文本 HTML span 着色）+ 勾选项 + 热图叠加项用**同一套颜色映射**：
勾掉某项 → 公式中该项变灰、热图重新合成。让"公式"与"图形"说同一种语言。

## 7. 零侵入诊断开关

- 引擎加 `diag=False` 参数：True 时把中间产物装进结构化 dict 随结果返回
  （`out['diag']`）；默认 False 时数值路径逐位不变、零开销；
- 哈密顿矩阵等大对象**事后重建**（独立纯函数，与内核逐项同语义），
  不在性能内核里插桩——重建本身即交叉验证；
- UI 消费 diag dict 契约；引擎没产出时面板显示**语义化占位提示**
  （"仅 mixed 引擎产出；hard/sambe 未接线"），不要让用户面对空白猜原因。

## 8. 表格的"物理含义"列

纯索引表（(10,25) | 0.04 MHz）用户读不懂——每行加一列把索引翻译成
业务语言（`态A → 态B |n=0`）。热图坐标轴同理：缩放后逐维显示全名，
大视野用短名+抽稀。

## 9. 导出兜底

每个数据面板配一个导出按钮（npz/csv/json），数值全量+元数据分存。
UI 再好也覆盖不了所有分析需求，导出是自由度的兜底。
