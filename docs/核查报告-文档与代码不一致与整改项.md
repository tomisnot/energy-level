## 一、P0：会崩 / 静默丢物理

### A1 · `sambe` 两体 AC 化：`ac_ize=True` 必崩，且位移没接线

**现象（实测）**：`E2a, A_newA = ac_ize_physical_E(...)` → `ValueError: too many values to unpack (expected 2)`，崩在 `src/core/sambe.py:1387`（第二处 `:1390`）。

```
File "src/core/sambe.py", line 1387, in evolve_sambe_pair
    E2a, A_newA = ac_ize_physical_E(E0,
ValueError: too many values to unpack (expected 2)
```

**根因**：被调方返回 **3** 元组——
```python
# src/core/evolve_mixed.py:86-90
def ac_ize_physical_E(E, f_opt, r_crit=None):
    """远失谐强对 AC 化入口（唯一消费者家族是 mixed）。"""
    A_new, shifts_list = acize_physical(E, f_opt, r_crit)
    return E, A_new, shifts_list          # ← 3 个
```
调用方按 2 个解包（`sambe.py:1387`、`:1390`）。实测：`ac_ize_physical_E(...)` 的返回 `len == 3`。

**更深一层的缺陷（读码，即使修好解包也不对）**：
- `ac_ize_physical_E` 返回的 `E` 是**未加位移**的原始能级（位移在 `shifts_list` 里；mixed 单原子把它做成时变对角 `ac_waves`，见 `evolve_mixed.py:419-426`、`coupling.py:250-267`）。
- `sambe.py:1394` 取 `E_shift = E2a - E0` → **恒为 0**；而 sambe 两体没有"时变 AC 对角"通道（`_PairSambeSetup(..., opt_terms=None)`）。
- 即：**修好解包后，sambe 的 AC 化会"删掉远强对但不补位移"**——比崩溃更糟（静默改物理）。

**影响**：
- `docs/手册-界面·原理·开发.md` §2.3.4 与 `docs/引擎能力边界-终稿.md` §3 都把 AC 化列为 sambe 处置远失谐强对的**正确手段**；实际该开关**不可用**。
- GUI 从不传 `ac_ize`（默认 `False`，`sambe.py:1361`；全仓库无 `ac_ize=True` 的调用方）→ sambe 路径的远失谐强对**从未**被 AC 化，与文档描述的"重要修正"不符。
- 与 `skills/energy-level/SKILL.md` 坑 19 的教训同型：**"写入侧通了 ≠ 引擎侧通了"**；该开关缺"True 分支至少跑通一次"的守卫。

**建议改法**：
1. 统一 `ac_ize_physical_E` 的返回契约（要么返回 2 元组并在内部把位移并进 `E`，要么调用方解 3 个）；
2. sambe 侧必须把位移真正注入（静态对角近似要写明是近似），否则显式 `NotImplementedError`，**不允许**"删对不补位移"；
3. 在 `checks/` 增加"每个布尔开关的 True 分支至少跑一次"的守卫。

**复现**（无需 GUI/ARC）：
```bash
python -c "
import numpy as np, sys; sys.path.insert(0,'.')
from src.core.sambe import evolve_sambe_pair
states=[{'label':'60S','E_mhz':0.0},{'label':'60P','E_mhz':17236.0}]
wf=lambda t: np.ones_like(np.atleast_1d(t),float)
fld=[{'omega_L_mhz':2.957e8,'A':np.zeros((2,2)),'waveform':wf}]
evolve_sambe_pair(states,fld,fld,0,1,np.linspace(0,10,11),ac_ize=True)"
```

### A2 · 单体 `mixed` 超过稠密阈值 → TypeError（两体同缺陷已修，单体漏修）

**现象（实测）**：`N=800` 态 + 1 个光场（P=3 → `dim=2400 > _DENSE_MAX=2200`）调用 `evolve_mixed`：

```
File "src/core/evolve_mixed.py", line 416, in evolve_mixed
    setup = _MixedSetup(E2, grps_opt, grps_mw, N, ...)
File "src/core/evolve_mixed.py", line 258, in __init__
    Kcw_list = self.setup.Kc_dense[gi] or []
TypeError: 'NoneType' object is not subscriptable
```

**根因**：`SambeSetup` 只在 `dim ≤ _DENSE_MAX`(2200) 时构造 `Kc_dense`，否则置 `None`（`sambe.py:194-206`）：
- **两体**已修：`evolve_mixed.py:661-672` 在稠密缺失时回退同源稀疏 `Kc_ext`（E1 事故的修复）；
- **单体**仍直接下标（`:258`）→ 崩。

**可及性**（`dim = N_phys × P`，`P = Π(2M_g+1)`）：
| 光载频数 | P（M=1 时） | 触发所需基组规模 |
|---|---|---|
| 1 | 3 | N ≥ 734 |
| 2 | 9 | N ≥ 245 |
| 3 | 27 | N ≥ 82 |

即**多光频 / 大基组**的单体 mixed 场景可达（例：5S↔6P↔60S 两光场链 + 245 态基组）。当前是**硬崩**（不是静默），但会以"演化失败"的形式甩给用户，且错误信息与物理无关。

**建议改法**：把两体的 `Kc_dense → Kc_ext` 回退抽成公共函数供单体复用（或反之），并补一条 `dim > _DENSE_MAX` 的单体回归；E1 的教训应机制化为"性能阈值绝不可改变模型/可用性"。

**复现**（无需 GUI/ARC）：
```bash
python -c "
import numpy as np, sys; sys.path.insert(0,'.')
from src.core.evolve_mixed import evolve_mixed
N=800; states=[{'label':'s%d'%i,'E_mhz':float(i)} for i in range(N)]
wf=lambda t: np.ones_like(np.atleast_1d(t),float)
fld=[{'kind':'exact','omega_L_mhz':2.957e8,'A':np.zeros((N,N)),'waveform':wf,'label':'opt'}]
evolve_mixed(states,fld,0,np.linspace(0,10,11))"
```

### A3 · sambe 两体的"自动 M"是统一 M 且从 2 起 —— 与文档口径差 2.8 倍

**代码事实**：
- GUI 默认 `per_freq_M=None`（面板留空，`ui_dynamic.py:984-1001`）；
- 两体走 `_pair_m_probe(E_pair, N, groups, 2, ...)`（`sambe.py:1475`），内部 `Mc = max(2, M)`（`:1160`）→ **所有载频组共用一个 M，且从 2 起步**；
- 逐载频解析判据 `_m_analytic`（`:545-566`，光学 M=1）**只用于单体**。

**后果**：22 态 + 2 载频（光 + 微波）→ `P = 5² = 25` → `dim = 484 × 25 = 12100`。

**文档口径不一致**：
| 来源 | 数字 | 实际对应 |
|---|---|---|
| 手册 §2.5.1 表 | sambe 两体 `7260（AC 化后 4356）` | 7260 = `per_freq_M=[1,2]`（P=15）；4356 = `[1,1]`（P=9）。**与 AC 化无关**（AC 化只删对+移能级，不改变 P/dim） |
| 手册 §2.3.2 | "软件按**逐载频**独立给 M（`per_freq_M` / 自动探针 `_m_analytic`）" | 对**单体**成立；两体自动探针不是这个 |
| `M选择指南` | "未指定 → 均匀 M 探针（历史行为）" | ✅ 这条写对了 |

**建议改法**：手册统一口径并注明代码路径；GUI 在选 sambe 两体时给出**当前 dim 提示**（面板留空 ≠ 小维度）；讨论 `_pair_m_probe` 起点是否应与 `_m_analytic` 对齐（光学组从 M=2 起是纯浪费，属设计裁决）。

## 二、P1：参数"说生效但够不到"

### B1 · `solve.*` 运行级旋钮只到 mixed；`MAX_STEP_HARD` 在 hard 侧完全不可及

**GUI 通道**（`ui_dynamic.py:1219-1220`、`1399-1400`）：
```python
gk = self._collect_god_kwargs()
pk = gk.pop('param_overrides', None)
if method == 'mixed':
    engine_kwargs.update(gk)      # ← solve.* 只在这里进引擎
```
- `param_overrides`（`engine.*` 注册表项）三条路径都生效（worker 里统一 `with params.override(...)`）；
- `solve.*`（`MAX_STEP` / `MAX_STEP_HARD` / `PER_FREQ_M` / `FROZEN_H_NS` / `COST_BUDGET`，`pm_setup.py:310-328`）经 `god_split` 变成 kwarg 后**只更新给 mixed**；
- sambe 另有自己的面板通道（`_sambe_adv_params`，`ui_dynamic.py:984-1001`、`:1393-1394`），所以 sambe 能设 `frozen_h_ns`/`per_freq_M`；
- **hard 什么 solve.\* 都拿不到**（`evolve_worker.py:41-47` 单体、`:137-146` 两体都只传固定参数）。

**矛盾点**：`pm_setup.py:315-318` 的参数说明写着
> "仅对 mixed/hard 的 DOP853 积分生效；sambe 走自带传播子"

而 `MAX_STEP_HARD` 在 hard 侧**任何正常入口都够不到**：内核 `hard.evolve_hard_fast`（`hard.py:79`）与 `hard.evolve_hard_pair`（`:470`）确实收 `max_step_hard`（`dop853.py:297-358` 每步复核），但统一入口 `hard.evolve_hard`（`hard.py:614`）签名里**没有**该参数、也没转发 → 只有直接调内核才行。

**影响**：用户/脚本以为"给 hard 压步长"能防欠采样，实际无声无效（`dop853` 的 `max_step` 只管起步，实测请求 0.05 ns 出现过 2.2 ns 接受步）。

**建议改法**：① `hard.evolve_hard` 补 `max_step_hard` 参数并透传；② `evolve_worker` 按引擎过滤后统一透传 `gk`（或对不支持的引擎把被丢弃的键**写日志**）；③ 参数说明与可及面一致。

## 三、P2：文档过期 / 归因错误

### B4 · 手册对照表的 hard 两体 dim "2420" 属于另一条代码路径

`docs/手册-界面·原理·开发.md` §2.5.1（第 856 行）写 hard 两体 `~2420 级`——2420 = 484×5 是 **`evolve_two_field_pair`**（微波也占光子块，M=2）的维度；而 GUI 的 hard 两体走 **`hard.evolve_hard_pair`**（`evolve_worker.py:137`），**无光子块，dim = N² = 484**。

**建议**：表里注明代码路径（GUI ↔ 库 API 两条），或分别列两个数。

### B5 · `get_diag` 的 "maxΩ/ω>1" 告警在光+微波混合场景失效

`diag.py:78-84` 用 `cfg['max_freq_mhz']`（配置里**最大**载频，`config_hints` 取全部波形 freq 的 max）作分母算 `maxΩ/ω`；`diag.py:130-137` 据此报警"已出 RWA 适用区"。混合场景下分母被光频（≈2.96×10⁸ MHz）主导 → 比值恒 ≪1 → **该告警几乎永不触发**（设计意图恰恰是发现强驱动越界）。

**建议**：按**逐对/逐波**计算（diag 的 `pairs` 段本来就带 `w` 字段，可用它做分母；至少对微波/光场分别判）。

### C1 · `引擎参数总表 §0b` 与 §6/注册表自相矛盾

- `docs/引擎参数总表.md:56`：`② PHASE_BUDGET | 4e4 rad | 这项付得起吗（成本）`；
- 同文 §6（第 138 行）与 §14 已写明"**已迁到运行级 `solve.COST_BUDGET`、默认空＝不限制**"；

**风险**：读者会以为"默认就按 4e4 做成本剔除"。**建议**：删/改 §0b 该行，指向 `solve.COST_BUDGET`。

### C2 · `引擎参数总表` 的"位置"列多处漂移（t80/t81 上收注册表后未同批更新）

## 四、P1：静默近似（需要记账/告警）

### D1 · mixed 丢弃远失谐光场对：不记账、不进诊断

- `evolve_mixed.py:267`（单体）与 `:689`（两体）：`|D_full[a] − D_full[b]| < BW_OPT(2e4 MHz)` 才入册，其余**静默丢弃**；
- 同族的"成本窗剔除"却有 loud 统计（`:289-305`）与诊断告警（`diag.py:146-148`：`有 N 对因成本窗被剔除（等于改了模型，结论需交代）`）。

**问题**：`BW_OPT` 被描述为"双峰分离器"（共振对 ~0 vs 反旋 ~2ω，差 4 个量级），确实安全；但**任何**落在 20 GHz~2ω 之间的光场对同样被静默删掉，且没有 `n_drop_bw` 可查。这违反项目自定的"改物理必须交代"纪律。

**建议**：与成本窗同款统计（`n_drop_bw` / 被剔项 max|v|、max|ΔD|）并入 `diag` 与 `warnings()`。

### D2 · 「椭圆偏」在三引擎语义不同，hard 侧退化且无告警

- hard（含两场引擎）：只吃 `wave.pol` 的**单个 q**（`evolve_twofield.py:99` `_POL_Q`），且复偶极相位被 `|d|` 吸收（`:49-50`）；
- sambe/mixed：走球基复系数 $(c_+,c_0,c_-)$ 相干叠加（`field_build.py:171-197`，`static_atom.py:80-108`）。

**后果**：GUI 里同一项"偏振 = 椭圆偏"在 hard 档下会静默退化为单 q（约等于线偏/圆偏），而 mixed/sambe 才是真正椭偏——**用户会以为三档只是速度不同**。历史坑记录（`field_build.py:167-176`）说旧版 `_POL_Q.get(pol,0)` 把椭偏**静默按 π** 算，属同一族问题，未在 hard 侧根治。

**建议**：hard 侧要么用复系数构建 A（与 mixed 同源），要么在选择 hard + 椭圆偏时**明确告警**。

## 本轮新引入问题

### N1（P0）· A1 的修复仍崩：`shifts_list` 是"逐场列表"，直接 `np.asarray` 得二维

```python
# src/core/sambe.py:1436（当前）
E_shift = np.asarray(sh_a, float)      # sh_a = shifts_list: list[ndarray(N,)] → 形状 (n_field, N)
```
- 有光场时：`E = E + E_shift` 把 `E` 广播成 `(n_field, N)` → 随后 `E_pair[i*N+j] = E[i]+E[j]` 抛
  `ValueError: setting an array element with a sequence`（实测 `ac_ize=True`）。
- **0 个光场时**：`np.asarray([], float)` 形状 `(0,)` → 对空数组做 `np.max/min` 归约抛
  `ValueError: zero-size array to reduction operation maximum which has no identity`（实测）。
- 实测形状证据：`type(sh)=list, len(sh)=1, np.asarray(sh,float).shape=(1, 2)`。
- **后果**：`ac_ize=True` 依然**从未跑通**——与 A1 原始结论相同，只是错误信息换了。日志还会先打印
  "AC 化位移按**静态峰值对角**注入：…"，**看起来成功**再崩。
- **正确改法**：逐场累加，例如
  ```python
  E_shift = (np.sum(np.asarray(sh_a, float), axis=0) if len(sh_a)
             else np.zeros(N))
  ```
  并断言 `E_shift.shape == (N,)`；`0 光场`时提前返回。
- **仍有设计问题（即使修好也要面对）**：峰值位移被当作**整窗静态对角**（`K_static` 与时间无关），
  脉冲之外也带着满位移——对"620 ns 窗 + 40 ns 脉冲"是定性错误；mixed 用的是 `env(t)²` **时变**对角。
  建议经 `opt_terms` 注入 `kron(I_P, Ko) × env²`（`sambe.py:176-192/237-252` 已支持该通道，传个 env² 包装
  函数即可），或明确把该开关限制为"包络近似恒定"场景并写在 docstring 里。
