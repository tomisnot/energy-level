# 交接 —— 给下一代开发者（energy-level / Re0）

> 读者画像：拿到这个仓、要在它上面**改代码**的人（或 AI 代理）。
> 目标：**20 分钟读完**，读完能自己跑起来、能定位主干、知道哪几处会踩一次。
> 规矩：本文不写任何"手抄的计数"（文件数/工具数/参数数会漂）；要规模就写"少量/一批/逐条"，
> 要准确数字就**跑一条命令自己数**。本文每条事实尽量带 `文件:行` 或一条可跑命令。
> **凡本机没核过的，本文就地标"未核实"**——别把转述当断言。

**本文对应的框架版本**：`mecha` = `v0.2.0-14-ge28b877`（本机 `git -C <mecha 仓> describe --tags` 得到；
`v0.2.0` 是发布 tag）。⚠ **面板资产现在是依赖包**（`@mecha/dsh-panel`，`file:` 依赖 ⇒ node_modules 里是 **junction**）：
本仓**不再持有副本、也不再有指纹表**——「逐字副本会不会漂」这个问题被**结构**消灭了（见 §3 / §6）。

## 1. 一句话

**Rb-87 里德堡原子的仿真软件**：静态能级 + 动态演化 + 多原子阵列，**人（GUI）与 AI（MCP）共用同一份状态、同一道写权门、同一本账**——AI 不是一个"外挂助手"，而是这台设备上的**另一个操作者**。

给谁解决什么问题：做里德堡实验/理论的人，需要"调参数 → 跑演化 → 看结果"这条链既可人手动、也可由 AI 驱动，且**人随时能看见 AI 干了什么**（只读监控端点 + 驾驶舱面板）。

## 2. 最短上手（照着做就能起来）

```bash
pip install -r requirements.txt     # 依赖声明见该文件；其中框架 mecha 是硬依赖
python launcher.py                  # 看门人：弹窗选 AI / GUI 模式
```

看到什么算成功：

* **GUI 模式**：出现主窗口，能改参数、能点"跑"；跑完有曲线。写权在人。
* **AI 模式**：起一个 headless 权威 + dsh 前台；权威把**实际端口**写进项目根的发现文件
  `.mcp-port`（MCP 端点）与 `.monitor-port`（只读监控端点）——见 `launcher.py:39`、`src/v2_bind.py:91`。
  人在 dsh 里点"切换至 GUI"就切回（看门人做进程交接）。

**只想验证环境**：`python run_checks.py --core`（秒级档）。绿=环境基本可用。
⚠ 面板资产包的自测由**框架门禁**跑（`mecha/checks/dsh_panel_selfcheck.py`，硬依赖 **Node ≥ 22.6**，
缺即红、不软跳过）；EL 侧跑自己的 `cd dsh && npm test`（**裸跑** `node --test`，无旗标、无 tsx，见 §6）。
改 dsh 插件的 client 侧代码后必须 `cd dsh && npm run bundle` 再重启 dsh（否则读到的还是旧包）。

⚠ **第一个坑（必读）**：写权**不是默认全开**。EL 的装配出厂是 **HUMAN**（`src/v2_bind.py:174`、
`V2Bridge.for_gui(mode=Mode.HUMAN)` @ `mecha_v2/bridge.py:158`）⇒ **AI 侧的写会被拒**。
AI 模式的正确开闸姿势是"**人**（或代表人意图的看门人）来切"：
`python launcher.py` 选 AI，或看门人侧 `app_entry.py:464` 的 `switch_mode('ai', actor='human')`。
自己去 `switch_mode` 时 `actor` 必须是人侧标签（`mecha_v2/bridge.py:39` 的映射表），否则被拒。

## 4. 本仓固定用语

**框架侧的本名/别名以规范源为准**：`mecha/docs/v2/使用模式与核心原则.md` §5 那张表。

| 本名（规范源） | 别名（历史上用过） | 一句人话 |
|---|---|---|
| **连接层** | 中性能力层 · **语义层** | 软件侧"承载语义、对协议中性"的那一层。**它们是同一件事**（旧称 → 本名）；本仓历史上爱叫它"语义层" |
| **人机同门** | 操作者无关层 | 同一套规则对人和 AI 一视同仁（机制名是后者，效果名是前者） |
| **账** | 域状态史 · `History` | 只追加的事件序列；"当前状态"是它的折叠 |
| **形状** | 工具形态层 | 同一个能力的多种调用形式 |
| **消费** | 具名消费者 | "真有读它的那一处"才算数（R1） |

**本仓特有的说法**

| 词 | 一句人话 |
|---|---|
| **写权门 / 门** | 所有写入的唯一入口；门里面决定"这次写允不允许、要不要留痕"。实现是框架的 `Gate` |
| **真值 / 快照** | `gate.snapshot`：`{键名: 值}`。GUI 与 AI 读的都是它（同一份） |
| **留痕** | 每次写进史，带 `actor`（谁）、`reason`（为什么）、`before → after` |
| **看门人** | `launcher.py`：弹窗选模式、起子进程、按 `.mode-request` 做进程交接 |
| **模式交接** | 从 GUI 切 AI（或反向）：terminate 当前组 → 等退出 → 起新模式；靠项目根的 `.mode-request` 传递意图（`launcher.py:35`） |
| **写权模式** | **四个值**：`locked`（都不能写）/ `human`（只人侧）/ `ai`（只 AI 侧）/ `open`（两侧都能写，代价是并发时"后写覆盖"）。枚举见 `mecha/mecha/authority.py:46-52`，交付说明见同文件 `:10-22` |
| **发现文件** | `.mcp-port` / `.monitor-port`：权威写的**裸端口文本**。客户端每次现读 ⇒ 端口漂移自愈 |
| **能力面** | 框架的 `Surface`：能跑的动作（演化、静态查询…） |
| **工具面** | AI 能调的那些动作，注册在 `mecha_v2/tools.py` |
| **驾驶舱 / 飞行记录仪** | dsh 右栏的只读面板；"飞行记录仪"页就是史的事件流 |

> ⚠ 关于"语义层"：本仓手册（`docs/物理引擎-专家手册.md`）里列举的那串
> （schema / 校验 / build_run 路由 / Result / 查询 / 产物 / 线程拆分）是**这一层在引擎里的内容**；
> 把它**投影**成框架 `Engine` 的地方是 `mecha_v2/engine.py:76 class ElEngine`。
> 换句话说：**它不是"另一个层"，就是连接层**（旧称）。本机未发现两者定义冲突的地方。

## 5. 跟着一条数据流走一遍

### 5.1 AI 改一个键，人看见（最短的一条链）

```
AI（MCP 客户端）
  → mecha_v2/tools.py 的工具体（如 set_config @ :110 注册；函数体见同文件 _set）
     → gate.set(channel, key, value, reason, call_id)     ← 唯一写入口（框架 Gate）
        → 校验（mecha_v2/engine.py:284 make_validator → :297 validate）
        → 落快照 + 追史（账）
        → 回执（tools.py:105 起：{ok, key, applied, before, resolved, readback}）
  → 史 → 只读监控端点 /history?since_seq=N（框架 mecha.cockpit 投影）
  → dsh 面板（资产包 `@mecha/dsh-panel`：取数 → 归约成唯一状态 → 渲染）
```

要点：**这条链上没有第二条写入口**。想"绕过门直接改值"的写法会被拒（`gate.set` 是唯一落地点），
判据 `checks/authority_selfcheck.py` 就在守这件事。
⚠ **端点回的字段名以实际输出为准**（框架改过事件形状，加过 `op`/`ts` 之类）——
想知道当前形状，`curl` 一下端点比读文档可靠。

### 5.2 GUI 跑一次演化（人侧同一条物理链）

```
src/ui（参数控件）→ src/ui/_mecha_bind.py（Binder @ :46；写经 _write @ :69 → bridge.write）
  → mecha_v2/bridge.py:399 class ElOps
       prepare() @ :412   ← 主线程：备料（build_run）
       execute() @ :420   ← 工作线程：evolve + 落 artifact
  → src/core/runspec.py:485 build_run(cache, params) → RunSpec（纯容器，可 pickle 跨进程）
  → src/core/runspec.py:630 evolve_run(run)  ← **唯一分派点**（引擎函数取自 :80 的 _ENGINE_TABLE）
  → src/core/runspec.py:737 result_summary(run, res) → 摘要（大数组走 artifact）
  → artifact 落盘 → GUI 用 src/v2_bind.py:45 load_artifact 取回数组绘图
```

要点：**装配面只有一个函数**（`build_run`）、**执行面只有一个分派点**（`evolve_run`，
其 docstring 自述"全仓唯一的 method×n_body 分派点"）。AI 侧走的是同一对函数
（`mecha_v2/engine.py:148 _run_on_engine`：build → check → evolve → summary）。

## 6. 改代码前必须知道的坑（每条：为什么 + 怎么避开）

**① 它没有"命令面"——权限是按全局模式判的，不是按能力判的（这是形状，不是漏做）**

工具都是直接 `define_tool` + 过 `gate.set`（`mecha_v2/tools.py:66 build_tool_registry` 起，逐个注册）。
因此本仓**没有**"某个能力只许某类操作者用"的判定，只有**全局写权模式**（**四个值**：
`locked / human / ai / open`，枚举见 `mecha/mecha/authority.py:46-52`）。
⇒ **别去"补"按能力的权限**：要收窄就把某个能力做成**查询**（读口）而不是写口。
（需要"AI 只能改这几个键"这种粒度时，先跟框架侧对齐。）

**② "人机同一道门"是一等公民，别在门上开侧门**

GUI 与 MCP 侧共享**同一个 `Gate`、同一份 `History`、同一份真值**：
GUI 经 `src/ui/_mecha_bind.py` → `bridge.write`；AI 经 `mecha_v2/tools.py` → `gate.set`；
两条都落到同一处。**actor → side 的映射表在 `mecha_v2/bridge.py:39 _ACTOR_CHANNEL`**
——出现**新的操作者类别**时**改那张表，不改库**。
怎么避坑：任何"新增一条写入路径"的想法都先问"它过门吗、它进账吗"。

**③ 工具体被 `**kwargs` 包过 ⇒ 签名侧恒为空 ⇒ `default` 必须手写**

框架的 null 垫片**只读"声明里的 `default` 键"**（不读闭包签名，因为工具体常被
`def wrapped(**kwargs)` 包一层、签名恒为空）。所以本仓**人工补了一批 `default` 声明**
（`mecha_v2/tools.py`，例如 `:119` 的 `"reason": {..., "default": "ai tool"}`）。
规则是三分法（同文件顶部注释有完整表述）：真默认**非 None** 必须声明；真默认**是 None** 一律不声明。
怎么避坑：新加/改工具参数时，**先看闭包真默认**，再决定声明什么；漏声明不会报错，
只会让"显式 null"以 None 到达工具体（症状=模型侧行为变差）。

**④ 出厂 HUMAN：AI 写不进去是**对的**，不是 bug**

见 §2 末尾。给人解释时别写成缺陷。

**⑤ 领域的边界：物理/数值语义归本仓，机制归框架**

* 归本仓：参数**值域与物理校验**（`mecha_v2/engine.py:297 validate` 拒只读键/未声明键/类型不符；
  波形与原子表的逐项真契约在 `src/core/protocol.py:239 validate_wave_list` / `:298 validate_atom_list`）、
  引擎能力边界、单位约定、RunSpec 组装与结果契约。
* 归框架：**写权与模式**、**账与留痕**、工具注册与投影、只读监控端点、Provider 层。
* 一条纪律：`src/core/` **不许 import 框架**（`src/core/protocol.py:9` 自述"本协议不 import mecha"）。
  ⚠ **但这条纪律目前无人守**：本机全仓 grep **没有任何判据在守它**（旧名
  `checks/mecha_purity_selfcheck.py` 已不存在，且**没有替代者**）⇒ 见 §8 挂起项。

**其他会踩一次的**

* **端口**：别在**监控端点**侧写死端口——那一侧的契约是"**绝不回落默认端口**"
  （`@mecha/dsh-panel/monitor-url.ts`：文件缺失/非法/越界 ⇒ 抛错、转 503）。
  但 **MCP 端点侧不是这样**：`launcher.py:68-78` 等不到 `.mcp-port` 时**会让 dsh 退回默认 `:8765`**
  并打一行警告（自述"超时不致命"）。⇒ 两边口径**不同**，别把监控侧的纪律套到 MCP 侧；
  排查"连不上"时先看 `.mcp-port` 是不是没写出来（此时**没人报错**，只是连到了默认端口）。
* **`dsh/lib/`** 是构建产物（gitignored）：改了 `dsh/src/` 下 client 侧代码必须
  `cd dsh && npm run bundle` 并重启 dsh，否则 dsh 读到的还是**旧包**。
* **面板资产是依赖包**（`@mecha/dsh-panel`，junction）⇒ 与 mecha 共用**同一份**代码；⛔ 别就地改（改它等于改 mecha）。
* ⭐ **依赖化的三条硬约束**（2026-10-01 实测，GP/ML 照抄）：① `tsconfig.json` 必须
  `"preserveSymlinks": true`——**类型检查期**经 junction 才找得到装在本仓的
  `@modelcontextprotocol/sdk`（否则 TS2307 + 连带 TS7006）；② ⛔ **运行期绝不要加
  `--preserve-symlinks`**（`npm test` 就是**裸跑** `node --test …`，**也不需要 `tsx`**）——
  那个旗标会让模块标识停在 `node_modules/@mecha/…`，而 Node 24 的原生剥类型**拒绝处理
  node_modules 下的 `.ts`** ⇒ `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`（实测：
  裸跑 23/23；带旗标连一条都跑不起来）。⚠ 名字像"该开"，其实**只有 tsconfig 那一侧该开**；
  ③ `tsdown.config.ts` 必须 `deps.alwaysBundle: [/^@mecha\//]`——`file:` 依赖**默认被外置**，
  bundle 会**缺代码**（实测：漏了它 client 产物从 41 kB 掉到 10 kB，只在运行时才炸）。
* **史里的事件字段名以框架为准**：改框架事件形状要跟着扫"属性读 / 字典键 / 按事件名筛 / 位置构造"
  四类站点（本仓为此做过一轮全仓对齐）。

## 7. 判定 / 门禁

* 跑法（档位在 `run_checks.py:64-65` 附近定义，`--list` 看清单）：
  ```bash
  python run_checks.py --core        # 秒级：改一行就跑
  python run_checks.py --fast        # 提交前档
  python run_checks.py               # 全档
  python run_checks.py --only sambe  # 单跑一条（子串匹配）
  python run_checks.py --list --core # 看某档包含哪些
  ```
* 判定在 `checks/` 下，一律 `*_selfcheck.py`，用 `checks/checklib.py` 的 `Checker`；每条判据
  **自己打印 PASS/FAIL 与子条件数**（`checks_sentinel.py` 会检查这一点）。
* **"能红"是纪律**：新守卫必须配致死性证据（把实现改坏 ⇒ 必须报）。逐条判据里常见
  `致死性` / `对偶` / `R8 非退化自证` 这类分组，就是干这个的。
* 新判据要登记进 `run_checks.py` 的 `FAST_KNOWN_SEC`（写**实测**秒数），否则不进 `--core/--fast` 内循环。
* 有判据硬依赖外部程序：面板共享单测要 **Node ≥ 22.6**（§2）；缺它**判红不软跳过**。
* 隔离约定：判据默认 offscreen Qt + 临时数据根（别污染 `.mecha-v2/`）。

## 8. 已知问题 / 挂起项（含**故意挂着**的）

**故意挂着（有理由，别当 TODO 顺手做）**

1. **本仓没有 `pyproject.toml`**：只上 GitHub、暂不发 PyPI；EL 不是包状结构（没有对外导入名）。
   代价已记账：陌生人没有 `pip install -e .` 入口 ⇒ 安装走 `pip install -r requirements.txt`。
   解的条件：真要发 PyPI 时再补。
2. **`.dsh/` 下的工作区副本不入库**：不用 dsh 的人不需要它们。**这是有意的本机态，不是缺失。**
3. **依赖声明指向的 `mecha` git URL 可能解析不了**（上游仓未建/未推 tag）——
   `requirements.txt` 里写了两种装法（发布版 / 本机 editable），照注释选一条。
4. **分支 `arch/model-as-truth`、tag `v2-replaces-v1`**：本地保留、**不推**（推的是 `main`）。

**真问题**

* ⭐ **`core ↛ mecha` 这条纪律目前无人守（空缺，不是被取代）**：本机全仓 grep 没有任何判据在守它
  （§6⑤）。⇒ 要么补一条 AST 判据，要么把它降级成"约定"并写进这里。**现在处于两者之间。**
* ⭐ **数据/账的保留期与回收没有实现**：`src/v2_bind.py:25` 自述"gc（数据回收）在 v2 未实现
  （D-9 保留策略等第二项目）"；`gc_report()` @ `:59` 是**如实报告的垫片**（`:62` 的 note 明说
  "本目录未清理"）。⇒ **journal 与 artifact 会一直涨**，长期跑之前先想清楚存储。
* GUI 侧的"人机共用"还在收口：写权门控有定义，个别控件在迁移后暂无人消费（静默失能）。
* `checks/` 里存在少量陈旧的注释与行号（文档/注释漂移是本仓反复付代价的一类问题）。

## 9. 与另外三个仓的关系

```
mecha          —— 框架：操作者无关层（写权门 / 账 / 能力面 / 只读监控 + Provider 层）
energy-level   —— 本仓：物理仿真，用 mecha 的 CodeAct 通道跑 AI 演化
get-paper      —— 论文管理与推荐，用 mecha 的命令面 + 工具面（MCP）
ml-toolbox     —— 机器学习方法试验台，用 mecha 的宿主适配 + 面板
```

* **谁依赖谁**：EL **硬依赖** mecha（`from src.v2_bind import make_v2_bridge` 是顶层 import，
  缺它就 ImportError 起不来，无降级路径）。另外三个项目不依赖 EL。
* **账本**：每个项目各自一本（EL 的落在数据目录的 journal；`Gate`/`History` 是框架机制）。
* **端口**：本仓用**发现文件**（`.mcp-port` / `.monitor-port`），不写死端口；dsh 插件 host 半按项目根解析。
  ⚠ MCP 侧有默认端口回落（§6 其他坑），监控侧没有——两侧口径**不一致**，读别人文档时注意。
* **协议**：AI 侧统一走 MCP 工具面；工具面"能写什么"由框架的写权门 + 本仓的校验共同决定。
* **SKILL**：`skills/energy-level/SKILL.md` 是给 AI 的操作指南权威源，其「工具清单」表与
  真注册表**互钉**（`checks/ai_surface_selfcheck.py` 的 C 组 + C2 致死性）。

### 9.1 ⚠ 四仓的**出厂写权模式不一样**（别以为一致）

| 仓 | 出厂模式 | 依据 |
|---|---|---|
| 框架 `mecha` | **LOCKED**（都不能写） | `mecha/mecha/authority.py:17`（"出厂默认"）、`:52` |
| **本仓 energy-level** | **两条入口，出厂模式不同**：GUI 装配点 = **HUMAN**（AI 侧写会被拒）；headless Hub = **LOCKED**（`--open-gate` 可开） | `src/v2_bind.py:174`（`mode=Mode.HUMAN`）；`mecha_v2/hub.py:99`（`mode=Mode.LOCKED`）与 `:199-210`（`--open-gate`） |
| get-paper | 据横向检查：库默认 LOCKED，**CLI 默认 `open`** | **未核实**（本机没有 GP 仓；转述横向检查） |
| ml-toolbox | 据横向检查：LOCKED | **未核实**（本机未核到 ML 的对应构造点） |

⇒ 跨仓讨论"AI 怎么又写不进去"之前，先确认**是哪一仓、哪条入口**。

### 9.2 ⚠ 跨仓验证的真实覆盖（唯一的真实耦合缺口）

框架自己的门禁 `mecha/checks/run_all.py` 通过环境变量 **`MECHA_EL_ROOT`** 找 EL 仓
（`:59-86`：`NEEDS_EL` 一组判据，缺 EL 根时**响亮跳过**，严格模式"跳过即失败"）。
⇒ **只有本仓被框架侧门禁验证**；**ML 与 GP 从不被框架侧验证**。
所以"框架改了、另两个仓烂了"这件事**没有任何自动信号**（见 §9.3）。

### 9.3 框架改了之后，三个接入仓按什么顺序同步（**建议**，非本机验证过的流程）

> ⚠ 下面是我给的**建议顺序**（本机**没有**验证过跨仓实施流程）；四仓的交接文档都没写可执行步骤。

1. **框架侧先落地并打 tag**（三个下游以 tag 为准，别追 HEAD）；tag 里要含"形状变更"的迁移说明。
2. **三个接入仓各自先跑一遍自己的门禁**（本仓 `python run_checks.py --fast`）——先看红在哪，
   别先改代码（红的位置就是"被形状变更打到的地方"）。
3. **按"被共享的部分"优先改**：事件形状/写口/端口机制这类**跨仓同形的部分**先改
   （本仓在 `mecha_v2/` 与 `checks/`），**再改** SKILL/文档这类描述性内容。
4. **面板资产是依赖包**：不用重抄、不用指纹表——`npm install` 一次，junction 就指向 mecha 那份；
   升级时留意 §6 的三条硬约束。

## 10. 这份文档的维护规矩

**必须更新它的时刻**（任何一条变了就来改对应段落）：

1. **入口/跑法变了**（`launcher.py` / `app_entry.py` / `run_checks.py` 的用法或档位）
2. **主干目录或装配点搬家了**（`mecha_v2/`、`src/v2_bind.py`、`runspec.py` 的职责变化）
3. **依赖声明方式变了**（`requirements.txt` 的装法、是否新增 `pyproject.toml`）
4. **§6 的坑被修好或被新的坑取代**（坑清单要删旧的、加新的——别只加）
5. **§8 的挂起项解掉或被替换**（例如 `core ↛ mecha` 补了判据、gc 实现了）
6. **框架换了事件形状 / 写口 / 端口机制**（§5、§6、§9 都要跟着改）
7. ⭐ **面板资产包升级时**（`@mecha/dsh-panel` 改了 = mecha 改了）：本仓 `npm install` 重装 +
   跑 `npm run typecheck` / `npm test` / `npm run bundle`；§3 的说明与 §7 的 Node 口径跟着改
8. ⭐ **规范源（`mecha/docs/v2/使用模式与核心原则.md`）改术语表时**：那张表明确要求
   "**四个仓的注释与文档里的旧词要按此表改过来**"（同文件 §5 末）⇒ 本文 §4 要跟着改，
   并顺手扫一遍本仓其它文档/注释里的旧词

⚠ 维护时同样**不写计数**；引用代码位置优先用 `文件:行`（行号会漂，但比"某处"强；漂了就顺手改）。

## 附：给 AI 代理的三条

1. **从哪道门进**：只经**工具面**（`mecha_v2/tools.py` 注册的那批）动手；先 `query_params`
   看可写键、再 `set_config`。**没有第二条写入口**——不要试图直接改快照、不要绕过 `gate.set`。
2. **不许它做什么**：不许改面板资产包（junction ⇒ 改它等于改 mecha）；不许在 `src/core/` 里
   import 框架；不许把"按能力的权限判定"当成待办去补（那是形状，见 §6①）；不许在只读监控端点上写。
3. **最易违反的纪律**：
   * **"绿"不等于"对"**——守卫要能红（改坏就报）才算证据；
   * **别静默**——拒绝/失败要留痕（日志 + 一条史），"没发生"与"被吞掉"必须可区分；
   * **别写手抄的计数与行号**（会漂）；要数字就现场跑命令。
