## 一、项目是什么（30 秒版）

PyQt5 桌面应用「原子能级计算器」（Rb-87 默认）：静态能级（Zeeman/超精细/AC-Stark Floquet/DC-Stark）
+ 两体耦合雷达图 + 单/双原子含时演化。物理核心 `src/core/` 无 UI 依赖；三套演化引擎并存：

| 引擎 | 定位 | 状态 |
|---|---|---|
| ip4/Lindblad（`evolve.py`/`pair_evolve.py`） | 生产默认（RWA/旋转系/secular，快） | 有 P1 静默失效（见 §3.2） |
| exact Python（`evolve_exact.py`/`evolve_exact_pair.py`） | 第一性原理（无 RWA/旋转系/secular），tol 单旋钮 | 小体系成熟，大场景不可用 |
| Julia 内核（`julia/`） | 性能/算法探索（Wosc 解析振荡权重、分块） | 算法完备，真实场景未达标 |

## 三、项目目标与核心难点

### 3.1 目标链
1. **物理**：两体里德堡动力学（近简并交换 + 远失谐 vdW 通道 + 光学退泵 + 寿命丢失）做
   "第一性原理准确"——无 RWA/无 secular/无旋转系/无近远分流，误差由单旋钮 tol 控制且随
   error_report 可见（区别于 ip4 的启发式经验常数）。
2. **工程**：GUI 内真实场景（22 态/原子、3 载频、1500 ns）可用——验收指标
   **N=20/400ns/tol=1e-6 ≤ 60 s**（至今未达成）。
3. **架构**：Julia=内核加速 / Python=权威验证 双轨可持续（跨语言对拍方法论已被证明
   价值最高：抓出共轭转置/列主序/投影维度三个逻辑审查不可见的 bug）。

### 3.2 核心难点（逐条带证据）

**① 段长 vs 振荡求积（数值硬瓶颈，第一代就撞上）**
- 相互作用绘景被积函数频率 ~C·ΔD（光子块间 ~C·ω、对态间 ~C·ΔE_pair）；GL 求积需
  n ~ C·ΔD_max·h 节点 → 段长上不去（N=20 场景接受段长 ~0.0156 ns，400 ns 需数万段）。
- Wosc 把**核**求积解析化后，**φ 的微运动插值**（幅度 ~R/ΔD、频率 ~C·ΔD）仍是同一标度
  天花板（Julia 文档 §8.4：EP6 尺度 Wosc 2.147e-4 ≡ gen-3 2.14e-4，段数仅 −13%）。
  → **段长的正解不在求积方法，而在消除 φ 微运动**（分块局部旋转系/二阶 Sambe，大研究项）。

**② ip4 静默失效 P1（用户正确性底线）**
- 基组含能量远移旁观者组（如 6P₃/₂ 超精细，对角能量 −296.7 THz）时：6P₃/₂ 旁观者 ref=0 →
  旋转系能量 −1.86e6 rad/ns；RK4 步长（按共振驱动 ~0.1 ns 设定）每步转角 1.86e5 rad →
  完全混叠 → 微波 π 脉冲**零激发**、假尖峰 0.996@262ns、mJ 泄漏 1.1%；**守恒诊断 3.8e-9 完美掩盖**。
- 对照：去光学场故障依旧 → 元凶是微波驱动与旁观者对角跨度的混叠，非光学场。
- **影响**：method=auto（GUI 默认）跑含低激发态组的存档 = 错误物理且无任何告警；
  GUI 侧无运行时检测/回退（exact 回退仅存在于 Julia→Python 方向）。

**③ 维度爆炸与降维两难（当前最大卡点）**
- 真实场景：22 态/原子（60S×2 + 60P₃/₂×4 + 6P₃/₂ hfs×16）→ 484 对态 × 光子块 5³=125 → **60500 维**。
- 6P₃/₂ 16 态**物理必需**（光学退泵通道，Ω/Γ=12.4 强饱和，移除即丢退泵物理）但 ×12 维。
- **mF-光子荷分块架构性失效**：I=mF_sum+Σs_g·n_g 分块后，同一 k 的不同光子块被分到不同类，
  而物理重建 ψ_k=Σ_p e^{−inphase_p·t}X_(k,p) 需**跨光子块相干求和** → 单类内布居为零
  （normdev=1.0）。M1 通过只因 2 态场景退化单类。block.jl 保留但应标注废弃。
- 绝热消去被否定（Ω_opt/Γ=12.4 ≫ 1 不可控）。
- Wosc 全空间 60500 维成本估算：每 GMRES ~6G 复数运算（权重应用 60500×16²≈62M×40-100 次
  matvec）→ 25 分钟 ~ 7 小时。**用户实测"Wosc 也超级慢"**与此一致。

**④ 两体耗散功能缺口**：仅寿命/丢失通道（NonHermitian −iΓ/2）；显式落点/纯退相
NotImplementedError（需密度矩阵回写）。

**⑤ 门体系缺口（可信度问题）**：G5（Wosc 段传播子）、G6（bench_n20 ≤60s）无正式 gate 代码；
`julia/benchmark/bench_n20.jl` 全库不存在；M2 testset 代码完整但分块废弃后失效未重设计；
文档"G1 18/18、G2 27/27、35 项"与现代码（G1 14 @test、G2 14 项检查）不可复现；
block.jl 无废弃标记（文档 §12.5 称已标注）。

**⑥ 检测代码慢（用户已反馈）**：实测 exact 单体一项 485 s（E7 STIRAP 主导），全量远非文档
所称"约 2 分钟"；core 54s + 耗散 17s + exact 485s + exact_pair + UI 35 项 + julia 门 + pair_evolve
→ 预计 10 分钟以上。回归要快必须拆分慢项。

**⑦ 工程环境**：BaiduSyncdisk 同步冲突（历史多次文件清空/横跳；本调研亲历文档被改写）、
僵尸 python/julia 进程（曾累积 51h CPU）、`__pycache__` 失同步（改了没生效）。

## 五、针对性方案（算法级 / 内核级 / 架构级）

### A. 立即落地（算法级，低风险，Julia 文档 §17 已认可的路线）

**A1. 单原子基组截断（P0，解锁真实场景的唯一直接路径）**
- 在 `build_states` 层加可达性过滤：按 |V|/Δ 截掉 6P₃/₂ 弱耦合超精细态，保留光学共振驱动
  可达的 F=3 子集 → N 22→~8 → 对态 64。
- 误差界 = 二阶微扰 Σ|V|²/Δ（可控、可量化：全基组 vs 截断基组布居差，EP6 尺度验证）。
- 配合 A2：扩展维 60500 → ~64×45 ≈ 2900 → **稠密路径（≤700 不满足，但 ~3000 仍可本征分解；
  或走 Julia 稠密/GPU）直接接管**，从小时级降到秒级。

**A2. 逐载频光子块阶数（Fock 层截断，收益大改动小）**
- 现实现用统一 M（P=D^G，M=2 → 125 块）。光学载频 Ω/2ω~1e-7 → M=1 即够（截断 ~1e-14）；
  微波 r=Ω/ω~3e-4 → M=2/3（5/7 块）。
- 改混合进制 stride（n_g ∈ 0..2M_g，D_g=2M_g+1）：125 → 3·3·5=45 块（光子维 ×0.36）。
- 改动集中：`_SambeSetup`/`_PairSambeSetup` 的 stride/对角/耦合构造（Julia 侧同构）。

**A3. Python 回灌 m_analytic（一行公式修探针低估）**
- Python 两体 M 探针无解析下界 → tol=1e-7 下真实截断误差 4.29e-5（探针误选 M=2）；
  Julia 侧 `m_analytic`=(r/4)^{2(M−1)}≤tol 已修（同场景 → 6.3e-10）。直接回灌。

**A4. ip4 失效守卫 + 自动回退 exact（用户正确性底线）**
- 运行时检测：基组含 |E_rot| 远超步长可解析频率的**旁观者组**（不被任何场耦合且对角跨度
  ≳1e5 rad/ns）且 method=auto → 日志告警。
- 截断+稠密路径就绪后：小场景（dim ≤ 阈值）自动改 exact 或提示用户切换；
  大场景保留 auto 但显式红字警告 P1 风险（对齐 Julia 文档 §13.3 的"最高优先级"判断）。

### B. 内核级（数值方法，性能余量）

**B5. 闭合 G5/G6 门 + bench_n20.jl**：Wosc 段传播子正式门（现仅 work/ 调试脚本）、
性能验收基准文件（缺失）；以截断后场景定验收（500 ns 先行，1500 ns 全套）。

**B6. Chebyshev 多项式传播子**（领域标准，Tal-Ezer–Kosloff 型）：冻结段 e^{−iC·H·h}
只做矩阵-向量乘，**免本征分解/expm**，谱精度，天然适合大规模稀疏（替代 gen-3 的
expm_multiply/Krylov 与稠密 eigh 的高维部分）；与 Magnus 结合处理时变。参考：
[The Chebyshev propagator for quantum systems](https://www.sciencedirect.com/science/article/abs/pii/S0010465598001799)、
[A Chebychev propagator with iterative time ordering](https://www.researchgate.net/publication/41426140_A_Chebychev_propagator_with_iterative_time_ordering_for_explicitly_time-dependent_Hamiltonians)。

**B7. 高阶 Magnus 积分器**（Hochbruck–Lubich）：现"冻结中点 + Duhamel 缺陷"≈ 一阶 Magnus +
修正；2/4 阶 Magnus（含对易子项）可系统提升段长且误差有严格界，与节点阶梯/细分框架兼容。
参考：[On Magnus Integrators for Time-Dependent Schrödinger Equations](https://www.researchgate.net/publication/220179937_On_Magnus_Integrators_for_Time-Dependent_Schrodinger_Equations)。

**B8. 微运动吸收（长期研究）**：按 ΔD 分块局部旋转系 / 二阶 Sambe——段长天花板的正解
（Julia 文档 §8.4 明确指出）；仅当截断+稠密后仍有性能需求再启动。

**B9. GPU 稠密**：截断后 dim~3k，CuPy/JAX 批量 eigh/expm 可 10–100×（文档 §16.3 已列）。

### C. 架构级（组织收敛）

**C10. 收敛裁撤**：Wosc 过一致性门后退役 gen-3；Julia=内核 / Python=验证 双轨定责；
Python 侧回灌已验证改进（m_analytic、探针外推校准、厄米绝对容差约定）。

**C11. 两体耗散完整化**：显式落点/纯退相（密度矩阵路径；单体参考路径已有 BDF 实现，
两体扩展为段内超算符）。

**C12. GUI S7 收尾**：截断后小场景端到端出图验证；use_julia 探测→失败回退已有；
补 exact 默认化策略（小场景默认 exact，大场景红字提示 P1）。

**C13. 回归提速**：加 `--fast` 模式（跳过 STIRAP 等慢项/降 tol）；exact 单体 485 s 是
全量耗时主导项，文档"约 2 分钟"口径需修正。
