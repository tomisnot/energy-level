## 第 1 刀：统一返回契约（治病症【D】）

### 改了什么

**键名一名到底**：`pops_2d` → **`pops`**，`states_2d` → **`states`**。
单体与两体**同一个键**——两体只是 `pops` 的列数是 N² 而不是 N。

| | 改前 | 改后 |
|---|---|---|
| 单体 | `{t, pops, states, loss, method, backend, error_report}` | 不变 |
| 两体 | `{t, **pops_2d**, pops_A, pops_B, loss_A, loss_B, **states_2d**, method, backend, error_report}` | `{t, **pops**, pops_A, pops_B, loss_A, loss_B, **states**, …}` |

`pops_A` / `pops_B` / `loss_A` / `loss_B` **保留**——两体有两个原子的边缘分布与损失通道，
那是**物理上真实存在**的差异，不该为"整齐"抹掉。

### 为什么这是治本

`runspec.result_labels` 旧写法必须特判：

```python
pops2 = res.get('pops_2d')
if pops2 is not None:            # ← 漏判就会把 N² 维布居标错
    s2 = res.get('states_2d')
    ...
return [s.get('label','?') for s in (run.get('states') or [])]
```

源码里留着那次事故的伤疤：**「直接照搬单体标签会把 N² 维布居标错（server._res_labels 的
2026-09-10 教训）」**。

契约统一后，那个分支**消失了**：

```python
st = res.get('states') or (run.get('states') or [])
return [x.get('label','?') for x in np.asarray(st).ravel()]
```

**一类事故写不出来了**——不是"记得判一下"，是"没有可判的分支"。

### 迁移面（可复核）

| 位置 | 处数 |
|---|---|
| 生产者（4 个引擎的结果字典） | `sambe.py` / `evolve_mixed.py` / `hard.py` / `evolve_twofield.py` 各 2 处 |
| 消费者（`runspec`） | `result_labels` / `result_summary` |
| 消费者（判据） | 6 个文件 / **28 处下标读** |
| 文档字符串 / 注释 | `hard.py` / `evolve_mixed.py` / `evolve_util.py` / `tensor.py` / `evolve_sambe_pair_gpu.py` |
| 判据侧支撑模块 | `checks/pair_evolve.py` 自己的结果字典 |

迁移**只动"作为 dict 键"的形态**，**不动裸标识符**（引擎内部局部变量名）——
那是实现细节，不是接口。

**验收**：基线 `##RE0_SUMMARY scripts=14 fail=0 seconds=269`。

### 顺手接上一个"入口不通"的破口（治病症【E】的一部分）

`runspec` 里 `solve.MAX_STEP_HARD` **一路收上来却在这一跳被整包丢掉**，
旧文案只好写：

> 「method=%s 不接收这些运行级参数，已忽略：%s（仅 mixed 生效；
>  **hard 的 max_step_hard 请经库 API 直调 `hard.evolve_hard`**）」

**产品自己承认入口不通。** 现在：

1. 新增 `_HARD_KW = ('max_step_hard',)`（照 `hard.evolve_hard` /
   `hard.evolve_hard_pair` 的签名抄）；
2. `build_run` 的单体与两体分支各加 `elif meth == 'hard':` → 走 hard 白名单；
3. `evolve_run` 的 hard 两个分支把 `max_step_hard=ek.get('max_step_hard')` 传给引擎。

⇒ `solve.MAX_STEP_HARD` 与 mixed 的 `max_step_hard` **同等待遇**，
可经 `build_run`/`evolve_run` 正常下发。

## 顺带记录：一个第一次必踩的接口摩擦点

`runspec.build_run` 的 `dynamic.psi_single` 收的是**身份键**（`state_key()` 的 6 元组），
**不是能级组的 label**。喂 label 会被 `resolve_psi` 明确拒绝（**不静默回落 0 号态**）。

这是本仓"初态必须可复现"的设计，不是坑——但**调用方第一次一定会踩**。
写进这里，免得下次再撞。

## 第 3 刀：删掉第二套入口 `evolve_engine.py`（治病症【A】）

### 为什么是"删"而不是"合并"

`src/lab/` 那层的思路是**给引擎加一个规范入口**（在 `src/core` 外面套皮）。
本刀走反方向：**把多余的入口删掉**。

改前有**三个** method×n_body 分派器：

| 分派器 | 谁在用 |
|---|---|
| `evolve_engine.py::evolve_engine`（54 行） | **只有判据**（产品代码零调用） |
| `src/ui/evolve_worker.py` | GUI 旧路径 |
| `runspec.py::evolve_run` | **产品真走这条**（GUI + 并行 runner） |

而 `runspec` 的注释自己写着「GUI worker 与并行 runner 的**同一条**引擎调用路径」，
docstring 又承认「**逐分支照抄 `src/ui/evolve_worker.py`**」——**两份手抄 + 一份没人用的**。

**唯一分派点 = `runspec.evolve_run`**（`build_run` 的对称面）。
这一条被 `energy-level` 技能独立印证：「runner 用的是 `src/core/runspec.py`（无 Qt）：
`build_states` / `build_fields_*` / `resolve_psi` / `resolve_decays` /
`god_kwargs_from_params` / **`evolve_run`**」。

### 改了什么

1. **删** `src/core/evolve_engine.py`（54 行，引擎 25 → **24 个文件**）。
   它的 docstring 还宣称支持 `method='ip4'` 而代码里没有该分支——随文件一起消失。
2. **沙盒内 2 个判据共 12 处调用改成直调引擎**：
   - `mixed_nolight_selfcheck.py`（7 处）：`evolve_engine('mixed', s, fields=F, psi0=P,
     t_grid=T, n_body=1)` → `evolve_mixed(s, F, P, T)`；两体同理 → `evolve_mixed_pair` /
     `evolve_hard_pair`。
   - `mixed_arb_mw_selfcheck.py`（5 处）：同上。
   **引擎函数本身就是公开面**——判据本来就该直调，不必经一层 method 字符串间接。
3. 同步 `src/core/__init__.py` 的模块地图与 `README.md`。
