# MCP 使用体感 —— 不适清单

> 作者视角：**AI 侧的 MCP 使用者**（不是开发者、不评架构、不评物理）。
> 只写"我拿这套接口干活时，哪里硌手、哪里被迫绕路、哪里不得不猜"。
> 每条都带**我实际发出的调用**与**实际收到的回应**（2026-09-16 实测，软件
> `code.stale=false`、36 个工具全可用、`.mcp-port=8765`）。开发者要复现，
> 照抄"我当时想干什么"那一行即可。
>
> 排序 = 我遇到的**频率 × 疼感**，不是实现难度。
> 我在这里只描述"难受在哪、我期待什么"，**不给实现建议**——怎么修是别人的事。

## 一、让我直接卡住的

### #1 「我要曲线」这件事，脚本里做不到

- **我当时想干什么**：一次调用里"取包络 → 算统计 → 顺便再设个参数"，典型的
  多步编排。
- **我发出的调用**：
  ```python
  env = get_envelope('dynamic.waves_A', 2)
  ```
- **我收到的回应**：
  ```
  NameError: name 'get_envelope' is not defined
  ```
- **难受在哪**：上面 `run_python` 的工具说明里列了一长串可用名字
  （`list_params`、`job_status`、`cancel_job`、`sweep_status` 都在），我**因此
  以为它是全的**。唯一能取原始数组的那个名字，恰好不在里面。
- **实际后果**：看曲线这件事被迫变成"跳出脚本 → 单独调一次 → 把数组拼回代码
  字面量"。多步编排的意义就没了；而且我是在**执行之后**才知道它不存在。
- **我期待**：要么它能用；要么白名单里**明确写出"不在其中的重要名字"**，
  让我一眼看到边界，而不是靠撞。

### #2 我下了一条大包络，回程被撑爆，而我不知道

- **我当时想干什么**：验证"大波形经过 MCP 会不会把响应撑大"。
- **我发出的调用**：`set_waves` 下发 `env=['file', t, amp]`，`t`/`amp` 各
  **12001 点**，然后 `list_params('dynamic.waves_A')`。
- **我收到的回应**（同一状态，三条路径三种口径）：

  | 我读的地方 | 拿到的大小 |
  |---|---|
  | `list_params` 的 `value` | **292 B**（已摘要，很好） |
  | `list_params` 的 `last_committed` | **241041 B** |
  | `get_state('dynamic')` | 整份采样数组，原样 |
  | `run_python` 返回的 `changes.old/new` | 整份新旧数组（那条响应被上层截掉 **576589 B**） |

- **难受在哪**：我**无法从接口本身知道**哪条路径是安全的。工具描述里
  `list_params` 明说"波形包络只给摘要"，我信了，结果同一个响应的另一个字段
  给了全量。而 `run_python` 的响应被截断时，**没有任何提示告诉我被截了**——
  我以为我看到了完整结果。
- **实际后果**：我从此对所有涉及波形的调用都**先怕一下**，得凭经验挑着读。
  这不是能力问题，是我在**迁就接口的不一致**。
- **我期待**：同一份数据，不管我从哪个工具读，**安全口径一致**；被截断时
  **明确告诉我被截了、原文在哪**。

### #3 我在脚本里下了大波形，回程也带了一份

- **我当时想干什么**：就是上面 #2，脚本里一句 `set_waves(w, 'A')`。
- **我收到的回应**：`changes.params[0].old/new` 各自附**整条包络**。
- **难受在哪**：我要的是"你改了哪一条"，不是"改前改后的全部内容"。我知道
  操作流水（journal）那边对这件事有体积闸（留形状 + sha1），**但 AI 的回程
  没有**——同一个软件，两套口径。
- **我期待**：回程的 `changes` 也**只给"哪一条变了 + 怎么确认它是它"**，
  完整内容按需另取。

## 二、让我猜和填错的

### #4 打错一个键名，它把 60 个名字全倒给我，却不给最可能的那个

- **我发出的调用**：`set_param('dynamic.tmax', 500)`
  （我记的别名，想设 `dynamic.t_max`）
- **我收到的回应**：
  ```
  未知参数 'dynamic.tmax'；可用: dynamic.decay_index, dynamic.decays,
  dynamic.frozen_h_ns, ...（共 58 个名字，一整屏）
  ```
- **难受在哪**：我打错的正是**注册表里明确登记的别名**
  （`dynamic.t_max` 的 `aliases = ["tmax", "时长"]`）。这个信息**就在同一个
  接口里**，`list_params` 会返回它，可错误消息**只字未提**。它给我 58 个正确
  名字，但没有一个是我要找的提示"你是不是想写 `dynamic.t_max`"。
- **实际后果**：我得自己在 58 个名字里找相似项；而更常见的错法是**拼写差一两个
  字母**，那种情况下这一屏名字毫无帮助。
- **我期待**：错误消息里**先给最可能的那个**（含别名线索），再给"要我列全部
  就调 `list_params('<前缀>')`"。

### #5 `aliases` 有一半是没用的碎词

- **我读到的**：
  ```
  engine.PHASE_TOL                 → ["phase", "tol"]                    ✅
  engine.AC_EFFECT_THRESHOLD_MHZ   → ["ac","effect","threshold","mhz"]   ❌
  engine._M_MAX                    → ["m","max"]                         ❌
  ```
- **难受在哪**：36 个参数带别名，其中大部分是**按键名里的下划线机械切出来的
  分词残余**，还有 `m`/`max`/`n`/`tab` 这种会到处撞的短词。真正像"人会怎么
  称呼它"的只有少数（`tmax`/`时长`/`B`/`磁场`/`光`）。
- **实际后果**：我不敢信任这个字段去猜键名——**它是噪声**，用了它反而更容易
  写错。一个字段有一半不能用，就等于没有。
- **我期待**：别名要么是**人真的会打的写法**，要么就空着。

### #6 同一个旋钮有两个键，我不知道该写哪个

- **我读到的**：
  ```
  dynamic.frozen_h_ns   desc:"Sambe 冻结段长（0=默认）"        group:""       value:0.0
  solve.FROZEN_H_NS     desc:"纯冻结段长（两体 sambe；0=全自适应）" group:"solve"  value:null
  ```
  同类还有 `dynamic.per_freq_M` vs `solve.PER_FREQ_M`。
- **难受在哪**：两个都能写、都返回 `ok`、都不会互相报错。**谁的设置会生效、
  另一个是不是过时了，接口里没有任何一句话说明。**
- **实际后果**：我只能靠外部文档的暗示去赌（"solve.* 是运行级真值源"），
  赌错就是"以为改了、其实没生效"——而这类错**结果看起来完全正常**。
- **我期待**：只留一个；或者**两个都在时明确写出优先级**，过时的那个在
  desc 里标出来。

### #7 想弄清一个参数的范围，得读散文

- **我读到的**：
  ```
  engine._DENSE_MAX    range: null   desc: "...（典型范围 100~20000 ）"
  engine.PHASE_TOL     range: null   desc: "...（典型范围 1e-09~0.1 rad）"
  ```
- **难受在哪**：范围写在**给人读的句子里**。`range` 字段是 `null`，
  `options` 是 `null`，`default` 也是 `null`。我能读懂，但**我越界时没人拦**——
  写下去照样 `ok`，要么等到算完才发现不对，要么根本发现不了。
- **我期待**：范围作为**结构化字段**给出（和 `options` 一样），越界时在写之前
  就被拒，并告诉我合法区间。

### #8 想知道"还有哪些参数"，只能一次全要

- **我发出的调用**：`list_params('')`
- **我收到的回应**：**60 个参数 × 每个约 16 个字段**，一次 35 KB 上下。
- **难受在哪**：① 我想看的只是"有哪些键"，却拿到每个键的全部 schema，
  里面 `pending` / `last_error` / `commit` / `external` / `scientific` 这些
  我几乎从不用；② 我知道按前缀能省，但**要有"我正好猜对前缀"的前提**，
  想浏览就没有轻量办法；③ 名义上有个 `group` 字段可以归类，但
  `dynamic.*` 的 `group` 是**空串**、只有 `engine.*`/`solve.*` 才填了，
  **我按 group 过滤会漏掉一大半**。
- **我期待**：先给我一份"**键名清单**"（轻量），要细节再按前缀/字段取；
  `group` 要么填全，要么别让我指望它。

### #9 `list_levels` 也没有裁剪和分页

- **我发出的调用**：`list_levels()`
- **我收到的回应**：当前 3 个组 → **22 个子能级**，每条 7 个字段。
- **难受在哪**：现在这套基组还小。项目文档里随手就是 7 组 / 13 组
  （`N=84`）的配置，那时这个响应会到百条量级；再往后（含光学场、超精细
  全展开）只会更大。**我看不到"能按组取"或"只要键名"的入口。**
- **我期待**：按组/按前缀取，或者轻量模式只回键。

## 三、让我没法复现和没法预览的

### #10 作业跑完了，我手里没有"它是什么配置"的记录

- **我读到的**（`runtime/ai_results/job_job40.json`）：
  ```
  t_ns / n_steps / two_body / states / ...
  ```
  里面有态标签、有网格；**没有** `B_gauss`、`E_vpcm`、原子间距与角度、
  波形表、初态、`engine.*` / `solve.*` 的覆写值。
- **难受在哪**：我按住一个作业的编号，**答不出"这是用什么配置跑的"**。
  我当时改过 `dynamic.waves_A`（并写了 reason）、用过 `npts=801`，
  可作业记录里一个字都没有。
- **实际后果**：同事问"你昨天那个结论是什么条件下得的"，我只能回去翻
  操作流水、靠时间戳和 reason 去拼。**更糟的是**：`get_config()` 只覆盖
  groups/mode/psi/t_max/npts/方法/波数，`field.lights`、完整波形表、
  `engine.*`/`solve.*` 覆写**都不在快照里**——所以连"重读一次配置"都补不齐。
- **顺带一个不一致**：并行扫描那边（`spec.json`）**能复现**，单体作业这边
  不行。同一个软件，两种待遇。
- **我期待**：每个作业自带一份**能重跑它自己的配置**（哪怕只是一个指针）。

### #11 提交长算之前，我看不到任何东西

- **我当时想干什么**：确认一条脉冲到底会驱动哪些跃迁，再决定要不要花时间。
- **我能做的**：只有 `estimate_cost()`。它做得不错——单次调用就给了
  `basis_n / dim / est_seconds / est_peak_gb / advice`。但它只说**代价**，
  不说**行为**。
- **难受在哪**：**"频率对、强度对，却一点都踢不动"** 这类事（项目自己记过
  这个坑），我是**提交 → 等到算完 → 看结果全零**才知道的。二十分钟换一个
  "哪个中间态不在基组里"。
- **我期待**：一个纯查询的入口，回答"这条脉冲会驱动哪些跃迁、各有多强、
  基组里缺谁"。哪怕只覆盖"基组够不够"这一问，也能省掉一整类返工。

### #12 跑了半天，我分不清"哪个活是我的"

- **我看到的**：作业号 `jobNN`（全局递增）与脚本号 `run_YYYYMMDD_HHMMSS_NNNNNN`
  是**两套编号**。
- **难受在哪**：一次脚本里提交 3 个作业，我拿回 3 个 `jobNN`，但**没有一条
  记录说"这 3 个属于哪次脚本、那次脚本基于什么配置"**。`list_jobs` 在我这个
  会话里回的是空的（登记表只管本次进程、只记在跑的），所以我连"我刚才提交过
  什么"都得靠自己的对话历史。
- **我期待**：作业能回指启动它的那次调用，让我顺着编号一路查到配置和产物。

## 四、让我多花回合的

### #13 诊断信息是散装的，得自己拼三张图

- **我读到的**：`get_diag` 有 `pairs` / `steps` / `sectors` / `traj` / `H`
  五种 scope。
- **难受在哪**：我为了回答"为什么布居没动"，要依次调**三次**（空 → `pairs`
  → `steps`），每次都在自己的上下文里拼。没有"**一次给我这次运行的关键结论 +
  可疑点**"的入口。而这恰恰是最需要一眼看全的地方。
- **我期待**：一个默认就把"该看的都看了"的摘要（尤其是异常与警告），
  分项留给我按需深挖。

### #14 大响应回来之前，我无从预防

- **难受在哪**：上一条大响应被截掉 576 KB 时，**是在结果出来之后**才知道的。
  调用前没有任何"这次大概多大"的提示，也没有阈值告警。我的上下文被吃掉了，
  而且是在我毫不知情的情况下。
- **我期待**：要么事前可估，要么事后明确告知"已省略 N 字节，全文在 <路径>"。

## 五、口径与命名上让我反复确认的

### #15 GUI 显示的单位和参数面的单位不一样

- **我看到的**：截图右栏光强显示 **`55.000000 nW`**；同一个量在参数面是
  `intensity = 5.5e-5`（`mW/cm²`）；旁边还有一条显示 **`200000000.000000 W/`**。
- **难受在哪**：文档只钉了参数面的单位。**人和 AI 说"光强 55"时，说的不是
  同一个数。** 我要是照着截图上的数字往参数里填，会差好几个数量级。
- **我期待**：单位换算关系**写在接口能读到的地方**（例如参数 desc 或
  `screenshot` 的返回里带一句"GUI 该栏以 nW 显示"）。

### #16 时间戳三种形态混着

- **我看到的**：`get_activity` 给 `ts: 1789521069.85`（Unix 秒）；
  `list_runs` 给 `started_iso`（ISO 字符串）+ `elapsed_s`。
- **难受在哪**：我想把"我改的"和"我跑的"对齐到同一根时间轴上时，得自己做两次
  换算，还得猜时区。
- **我期待**：至少所有"给 AI 读"的时间戳带一个**通用形态**。

### #17 关键结果的字段口径没有一句话说明

- **我看到的**：结果里同时有 `final_pop` 与 `top_states_avg_pop`。
- **难受在哪**：两个都能读，但**"avg 是对什么平均"接口里没说**。我知道项目
  自己有明确定义，可我拿到结果时没有。
- **我期待**：这两个字段各自一句话口径，写在我看得到的地方。

### #18 `screenshot` 给了路径，我还得自己想办法看

- **我发出的调用**：`screenshot()`
- **我收到的回应**：`{"ok": true, "path": "..._ai\\shot_20260916_092844.png"}`
- **难受在哪**：这个工具的说明是"**了解人眼所见**"。但我的工具面里它只给路径，
  **要另外找一个读图能力**才能真的看见。对"只能调这一个 MCP 的 agent"来说，
  它等于不可用——而这恰好是设计它的初衷。
- **说明**：我这边（本 harness）**能**用另一个工具读它，所以对我它是通的；
  我写进来是因为**接口本身没保证这一点**。
- **我期待**：返回里直接带图，或者至少带一句"用你的读图能力看这个路径"。

## 六、我为什么还是愿意用这套接口

写上面这些是因为项目要我提意见（G4），不代表它是难用的。反过来：

- **`estimate_cost()` 是这条接口里最舒服的一次调用**——一次拿全
  （`dim / est_seconds / est_peak_gb / advice / mem_advice`），还附带一句
  "建议 run_python_async"。**这就是我期待的形态**，其余工具照这个标准对齐就很好。
- **`set_groups` 的回执**（`added/removed/kept` + `resolved` 里每组的
  实际子能级数与身份键）让我**写完就敢确认**，不用再取一次状态对账。
- **`summary()['code'].stale`** 让我能自己发现"我看到的行为是旧的"。
- **`engine.*` 的 `desc`** 写得比多数软件的 API 文档好（判据公式、极限、
  调大调小的后果都在）。
- **`screenshot` 真的能看到 GUI**：我据此确认了横幅、状态栏"● AI 在线 :8765 /
  撤销AI"、以及右栏 `波形3 包络文件 · 2.96e+08MHz · π` 和"6 点 · dt_min=0.1 ns ·
  时长=800 ns"——**我的写操作在界面上长什么样，我是真看见了。**

**一句话体感**：每次单个调用都挺可靠，**一组成任务就开始硌手**——看数据、
看配置、看预览、看诊断，四处都要我绕。上面 18 条里，真正让我**白烧回合**的是
#1、#2、#4、#10、#11；其余是让我**多确认几次**。
