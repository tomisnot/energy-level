## 一、已查证的事实（动手前必须知道）

| 事实 | 位置 | 含义 |
|---|---|---|
| 初态从 GUI 出去时是**整数索引** | `ui_dynamic.py:1042` `psi0 = self.psi_combo.currentIndex()`（两体为 `:1158-1159`） | 引擎层的 `psi0` 参数接受 int，**int → 复向量**的转换发生在引擎/worker 内部（尚未定位到具体函数） |
| 统一入口把 psi0 原样透传 | `src/core/evolve_engine.py:12-46` | 单体 `evolve_mixed/sambe/hard`、两体 `*_pair` 都吃同一个 psi0 |
| 语义身份键由 `state_key(st)` 构造 | `ui_dynamic.py:693`；键形如 `['mJ', n, l, j, m, E]` | 叠加态应复用同一身份表示，而不是自造一套 |
| 两体的 psi 是**逐原子**的 | `dynamic.psi_A` / `psi_B` | 逐原子叠加只能表达**直积**叠加；纠缠态（交换后的真实结果）需要额外通道 |

**关键结论**：叠加态必须落在"索引/键 → 复向量"的那一步；只要那一步支持
`{state: amplitude}`，GUI 与脚本、单体与两体、所有引擎都会同时获得该能力。

## 二、接口设计（AI 面先做）

### 2.1 逐原子叠加（本节可立即实现，覆盖直积叠加）
```python
set_superposition(atom, components, normalize=True, reason='')
#   atom: 'single' | 'A' | 'B'
#   components: [{'state': [n,l,j,m], 'amp': [re, im]} | {'state': …, 'mag':…, 'phase_deg':…}, …]
#   返回 {ok, atom, n_matched, norm, populated: [[label, |amp|²], …], missing: [...]}
```
规则（P1/P5）：
- 每个 component 的 `(n,l,j,m)` 必须在**当前基组**内，否则**报错**并列出 `list_levels()`
  中的合法项（不许静默丢项——上次静默选错能级的教训）；
- 未给 `normalize=False` 时按 `Σ|amp|²=1` 归一，并在返回里报告归一前范数；
- 存储形如 `['sup', [[n,l,j,m,re,im], …]]` 写进 `dynamic.psi_*`（**复用现有 param**，
  不新增登记项；GUI 的 combo 匹配不到该形态时会回落，不会崩，稍后 GUI 再适配）。

### 2.2 两体纠缠叠加（"交换后的结果"需要它）
```python
set_pair_superposition(components, reason='')
#   components: [{'pair': [[nA,lA,jA,mA], [nB,lB,jB,mB]], 'amp': [re, im]}, …]
#   索引按 k = iA*N + iB 落到两体基（与引擎 states_2d 的约定一致）
```
- 物理动机：`|60P_A,60S_B⟩ ↔ |60S_A,60P_B⟩` 的交换结果**就是**这两个两体态的叠加，
  逐原子直积写不出来 → 必须有这条通道；
- 实现要点：(a) 逐分量解析成 (iA, iB)（不在基组 → 报错）；(b) 组装 `psi0_2d`；
  (c) `evolve_engine(n_body=2)` 增开 `psi0_pair` 入参（两体四件套已有，加一件）。

## 四、用它验证 freeze（用户指定路线）

1. **参照（无 freeze）**：初态取交换结果 `(|60P_A,60S_B⟩ + e^{iφ}|60S_A,60P_B⟩)/√2`
   → 观察"谁被激发"的不对称度 `S(t)` 如何演化（自由演化下应当在 −1…+1 间摆动，
   摆动频率 = V_dd 交换率）；
2. **加 freeze**：同一初态 + freeze 脉冲（7380 MHz / I=5 / 40 ns 高斯 / ⊥B 线偏）
   → 判据三条：
   - `S(t)` 在脉冲后**停止摆动**（冻结成功）；
   - 58G 合计 > 0（kick 真的发生）；
   - `model_card.warnings` 为空（且若出现"零候选对/缺中间态"就必须先修基组）；
3. **对比量**：`S(t)` 后半段的平均摆动幅度（加 freeze vs 参照）——这是我上一轮
   在 `_t_result_states` 里已经实现的取数能力，这次能直接算。

### 四.1 实测结论（使用者 2026-09-12，已互验；详见工作稿 `docs/freeze-纠缠态验证与基组收敛.md`）
- **因子化预言**（freeze 远快于交换，两分支被独立作用、终态正交 → 无干涉）：
  ```
  P_end(60S) = ½[ret(+0.5)+ret(−0.5)] = ½(0.9994+0.9945) = 0.9969
  P_end(60P) = ½[surv(−0.5)+surv(+1.5)] = ½(0.0012+0.0088) = 0.0050
  P_end(58G) = ½[kick(−0.5)+kick(+1.5)] = ½(0.9891+0.9816) = 0.9853
  C_ent      = P_end(60S) − P_end(60P)   = 0.9919
  ```
  ⚠ **族归一化提醒**：两体族对"两个原子的标签"各记一次 → `N(60S)=N(60P)=1.0`
  （不是 0.5），族和最大 2；**`C_ent` 与单原子同尺度、无因子 2**
  （第一版写成 ×2 得 1.98，已纠正）。
- **对交换细节稳健**：ΔM=+1 通道（本轮实际）→ `C_ent=0.9919`；ΔM=0 通道 →
  P 原子恒 m=−0.5、S 恒 m=+0.5 ⇒ `C_ent=C(−0.5)=0.9982`；相对相位 i / −i / 实
  **不影响**族求和（两分支终态正交、无干涉）。
  ⇒ "freeze 在交换后的纠缠态上仍干净"**不依赖**交换通道与相位，也**不依赖**
  交换本身的基组收敛性（那是另一件事，见待办 E1）。
- 参数抖动（纠缠态口径，45 点 (ω,I) 网格）：工作点 `C_ent=0.9919`，但平坦区很窄
  （±1% 只有 1/45 格点；相邻 5 MHz 摆 ±0.15），而 60S 保留单调平滑
  → 窄结构出在**踢出**那一路。**已定性 = 物理**（使用者 `tol` 复核：同 ω 下
  `tol` 1e-7/1e-9 与 `npts` 1501/3001 的 `C` 极差仅 **3×10⁻⁷~6×10⁻⁷**，
  比 5 MHz 步长引起的 0.15 小六个数量级）：工作点是**窄三光子共振**
  （宽 ≈ 1/(3τ) ≈ 4 MHz）⇒ 交付必须给**频率精度要求（~1–2 MHz 级）**，
  "参数抖动平坦"在当前方案下不成立。
  机制（裸共振 7219–7347 MHz、同 J 子能级间隔/3 ≈ 9–11 MHz、实测峰比裸共振高
  ~+40 MHz 的 AC Stark 位移 ⇒ 必须扫频布点）与平坦化路线（**纯圆偏振已被否掉**：
  σ+ 全窗口 `C_ent ≤ 0.42`、σ− ≤ 0.37；倾向**啁啾/绝热脉冲**，微波任意波形经 `hard` 支持）
  见待办 §10 与分工文档 §六 #10。
  另外：椭圆偏在 **7355–7400 MHz 有宽的高平台**（`C_ent` 0.74–0.99，叠 ~5 MHz 精细结构）
  ⇒ 平坦性的正确表述是"**保证 0.79、标称 0.99**"（±10 MHz 窗口保证值 = **0.786 @ 中心 7375**），
  而不是"完全不平坦"。

### 四.2 两体实算验证（使用者 job3，2026-09-12 成功）
**主结论 = freeze 作用在"交换后的纠缠态"上仍然干净。**

`(|P_A(−0.5)S_B(+0.5)⟩ − i|S_A(−0.5)P_B(+1.5)⟩)/√2`：

| 量 | 两体实算 | 因子化预言（单原子） | 差 |

| `P_end(60P)` | **0.0354** | 0.0050 | +0.030 |
| `P_end(58G)` | **0.9644** | 0.9853 | −0.021 |

- npz：`tempsimu/ai_job3_205454.npz`；2026-09-12 起 AI 作业**完成即自动落盘**（SKILL 坑 10）。
- **两条交给 T2(E1) 的线索**（使用者点名）：① 该配置 `n_pairs=**50351**`
  （对比：3 组纯 V_dd 仅 **50** 对、3 组+光学波 **1233** 对）⇒ 这个规模下极可能混入
  大量非物理对；② 逐原子约化**轻微不对称**（A 末 60S 0.595/58G 0.392；B 0.402/0.572），
  比单原子 m=−0.5 与 m=+1.5 的差别（0.9988 vs 0.9912）**大得多** ⇒ 这部分差异

## 五、已知障碍与绕行（2026-09-12 实测）

- **两体 + 光学场会爆维数**：8112 = 2704（两体 52 态）× 3（光子块 P），
  求解器要建 8112² complex128 稠密矩阵 = **1004 MiB** → 分配失败（弹过框）。
  **绕行**：把验证拆成两次运行——
  ① 交换部分：4 组 + 频移光（小维数，已跑通）；
  ② freeze kick：7 组 + **纯微波**（P=1 → 2704² ≈ 58 MB）。
  依据：频移光只把 60S/6P 移动，对 60P 仅 1–2 MHz 影响（用户判断），故 kick 的
  共振点基本不变。
- **不是分流 bug（2026-09-12 查明，此处更正我上一轮的推断）**：
  `_DENSE_MAX` 只被 `sambe.py` 读（104/433/930/1509），`_TF_DENSE_MAX` 只被
  `evolve_twofield.py:1054` 读 —— **`evolve_mixed.py` 从不读这两个，但它也没有
  稠密 eigh 路径**（走 DOP853 积分），所以"没走分流"本身不是缺陷。
  **真凶是诊断通道无尺寸保护**：`evolve_mixed._assemble_H_snapshot`
  （t75 诊断，`diag=True` 才走；单体 :523-581、两体 :1016-1078）按
  `np.zeros((dim, dim), complex)` 建**稠密分项矩阵**——`8112² × 16 B = 1004 MiB`，
  与弹窗数字**逐位一致**；AC 对角/耗散/微波/光场/V_dd 多项叠加即爆。
  **且 AI 发起的运行默认 `diag=True`**（人点运行未开上帝模式诊断则不会踩）。
  **已修**：加 `_H_SNAPSHOT_MAX_MB = 256.0` 尺寸闸，超过只回
  `{too_large, dim, term_mb_each, note}`，诊断的配对/步长/扇区部分不受影响；
  自检 `checks/ai_h_snapshot_guard_selfcheck.py`（10 项，含 8112 → 1004.1 MB）。

**已实现（AI 侧）**

  `('sup', [(spec, amp), …])`，分量递归复用既有 spec（索引/(n,l,j,m)/dict），

**坑（已实测）**：`_as_vector` 对 `tuple/list` 先判 `len(psi0) == N`（整向量），
再判 `len(psi0) == 4`（(n,l,j,m)）。因此**当基组恰好 4 态时**，`(n,l,j,m)`
会被当成整向量解释（实测得到 n²,l²,j²,m² 的错值 [3600,1,2.25,0.25]）。
真实基组（≥18 态）不会触发；但这是既有的尖锐边角，值得记一笔。
**自检请用非 4 态基组**（本次测试脚本 `tempsimu/_test_sup.py`，已随 2026-09-14
草稿区清理移出仓库；该边角现由 `checks/ai_superposition_selfcheck.py` 覆盖）。

## 七、T1 两体纠缠初态：实现清单（2026-09-12）

**接口（AI 面，已可用）**
```python
set_pair_superposition(components, reason='')     # MCP 工具 + CodeAct 同名
#   components: [{'pair': [[nA,lA,jA,mA],[nB,lB,jB,mB]], 'amp': [re,im]}
#                | {…, 'mag': 0.7, 'phase_deg': 45}, …]     传 [] = 清除
#   → {ok, path:'dynamic.psi_pair', spec, info:{n_components,norm_before,
#                                               populations}, [mode_warning]}
```

**落地面（一条链，四个文件）**
| 位置 | 改动 |
|---|---|
| `src/core/evolve_util.py` | `_resolve_level_idx` / `_as_pair_vector` / `pair_psi0_vector`：spec→N² 向量，索引 **k=iA·N+iB**（与 `states_2d` 同），Σ\|amp\|²=1 归一，缺项**报错点名** |
| `evolve_mixed.py` / `hard.py` / `sambe.py` | 两体入口各加 `psi0_pair=None`，初态行统一改 `pair_psi0_vector(...)`（psi0_pair 优先） |
| `src/core/evolve_engine.py` | 统一入口加 `psi0_pair`；`n_body=1` + 它 → 明确报错（不静默忽略） |
| `src/ai/sim_state.py` | `build_pair_sup_spec`（纯函数）+ `SimState.set_pair_superposition`；设逐原子初态时**清掉** psi_pair（防静默覆盖）；`set_groups` 的 `psi_warnings` 也查 psi_pair（A8 教训） |
| `src/pm_setup.py` | **新登记项 `dynamic.psi_pair`**（默认 None，无控件 → 无指示灯）→ 自动进 `list_params`/`get_state`/存档 |
| `src/ui/ui_dynamic.py` + `evolve_worker.py` | 两体运行读 `_pair_psi0_spec()` → `EvolveWorkerPair(psi0_pair=…)` → 三引擎 |

**设计取舍（已选，供复议）**
- **新登记项而不是复用 `dynamic.psi_A`**：逐原子 psi 的读回通道是 combo 的身份键
  （`_psi_key_for`），塞不进 10 元 spec；复用会让 `list_params('dynamic.psi_A')` 的
  值形态随内容变化。新项是**纯增量**（旧进程没有它，只报"没登记"，不影响任何旧行为）。
- **spec 存 (n,l,j,m) 而非索引**：跨 B/能量漂移稳定，和身份键同一哲学；报错能点名。
- **psi0_pair 优先于 psi0_A/B**（而不是报错）：物理上纠缠态一旦给定，逐原子初态就无意义；
  为免"静默覆盖"，AI 面设逐原子初态时会主动清 psi_pair 并回执 `pair_spec_cleared`。

**坑（新增，已实测）**
- **对称组合 `(|ab⟩+|ba⟩)/√2` 是交换哈密顿量的本征态（暗态）**：布居恒定、只吃全局
  相位——自检 `checks/ai_pair_superposition_selfcheck.py` 的 E4 就锚这条（摆幅 <1e-6）。
  想看交换摆动要**相对相位**（如 `amp=[0,1]` = i）或直积初态。
- **逐原子 `set_superposition` 写了不生效**（本文 §2.1 的既有实现只在写入侧成立）：
  GUI 运行读 `psi_combo.currentIndex()`（整数索引），`['sup', …]` 只走
  `_pending_psi_keys`，`find_state_index` 匹配不到 → 静默回落 0 号态。
  已登记为分工文档 §六 #3（修法：让 psi spec 成为持久真值，同 psi_pair 的做法）。
