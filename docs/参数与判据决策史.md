## 1. 判据的两次换代：固定能量窗 → 累积相位

### t78：V_dd 静态耦合

**旧**：`_VDD_MIN_FRAC = 1e-4`，幅度阈值 |V| ≥ 1e-4·max|V|。

**问题**：判据随基组标度漂移；且管不住"|V| 大但远失谐"的元素——34.6 GHz 双翻转
Förster 通道被误剔，这是 hard ↔ mixed 的 V_dd 结果差 1.1e-5 的根因（换判据后
降到 4.3e-8）。

**新**：`Θ = C·T·|V|²/max(|ΔE|,|V|) ≥ PHASE_TOL`。

物理含义 = 该耦合在演化窗口内累积的二阶相位（耦合自身的观测量）：

| 极限 | Θ | 对应 |
|---|---|---|
| 共振（\|ΔE\| ≲ \|V\|） | C·T·\|V\| | Rabi 相位 |
| 远失谐（\|ΔE\| ≫ \|V\|） | C·T·\|V\|²/Δ | 色散 / vdW 相位 |

**取值依据**：实测两类耦合的 Θ 相差 3 个量级以上（共振 ~3.9 rad vs 双翻转
~5e-4 rad），故判据对取值在 1e-2~1e-3 区间**不敏感**；1e-4 属保守侧
（保留数 66~84 vs 50——多留弱耦合，不丢任何强耦合）。

### t79：微波耦合对

**旧**：固定窗 `| |ΔD| − ω | < MW_NRES_BW_MHZ`（原 5e3 MHz），与 |Ω| 无关。

**问题（实测锚，freeze 场景）**：三光子梯子 60P→59D→58F→58G（7.5 GHz 驱动；
梯级 10.223 / 11.226 / 0.420 GHz → 单光子失谐 −2.72 / −3.73 / **+7.08** GHz）
的**第三级 Δ=7.079 GHz > 5 GHz 被整条删掉**——400 ns 演化布居零变化、
**无任何报错**。

**新**：同一 Θ 判据（失谐换成相对光子的 Δ=||ΔD|−ω|），外加成本预算。
实测该梯子三级在 5.5e-5…1 mW/cm² 全区间保留（Θ=0.05…1391）。

> 与 t78 **同因**：|Ω| 无关的能量窗会误删强场下的远失谐多光子通道。

### t80：固定频率窗 → 相预算

`MW_NRES_BW_MHZ` 虽然降级为"兜底上限"，但它仍然与 T 无关：

- T 小 → 本来就不用走那么多步，固定窗白付步数；
- T 大 → 同样的频率要多走很多周期，固定窗反而误删可分辨的慢项。

**新**：`ΔD_max = PHASE_BUDGET / (C·T)`（`coupling.mw_cap_mhz`）。

最坏总步数 = `PHASE_BUDGET`/0.5 ≈ 8e4，**与 T、与体系无关**——这正是"预算"该有的
性质。标定：t79 的 1e4 MHz 窗在 T=620 ns 下等价（C·1e4·620 = 3.9e4，
故取 `PHASE_BUDGET = 4e4`）；T=400 ns 时给 1.59e4 MHz ⊇ freeze 梯子第三级
7.08 GHz，故 t79 的结论不回退。

## 2. 为什么有些参数**刻意不合并**

### `R_CRIT`(0.0135) vs `RWA_TOL`(1e-4)

同为 Ω/ω 型比值，但要求不同：

- `R_CRIT` 问"这个远强对能不能留在光子块里"（块截断）；
- `RWA_TOL` 问"旋转波近似本身够不够准"（反旋转误差 ~(Ω/ω)²）。

相差 2 个量级是**物理要求不同**，不是历史漂移。

### `BW_OPT`(2e4) vs `M_EST_BW_MHZ`(2e4)

数值巧合相同，含义完全不同：

- `BW_OPT` 是 mixed φ-帧光场对的**双峰分离器**（共振对 |ΔD|~0 vs 反旋
  ~2ω≈7.6e8，差 4 个量级）——窗宽在 [1e3,1e6] 取谁都一样；
- `M_EST_BW_MHZ` 是 M 判定时 **r 的取样窗**（决定哪些对算"近共振"）。

### `OPT_NRES_BW_MHZ`(2e3) vs 微波候选窗

微波对在 mixed 里带完整 `cos(ωt)` / `φ(t)` 时变相位 → 删对只损失精度 →
可以换 Ω/T 自适应的相位判据。

两场引擎的**光场**耦合则被冻结成常量矩阵 ½Ω（`build_two_field` 里 `A = 0.5*A`，
旋转系里无 Δ 依赖）→ 远失谐对塞进去是**系统性错误**，不是"更慢"。
所以那里是**正确性边界**，必须用固定窗。

### `_DENSE_MAX`(2200) vs `_TF_DENSE_MAX`(3000)

不可合并：标准两场两体 22 态为 N²×P = 484×5 = **2420 维**，必须留稠密，
否则 `backend` 翻成 `tf-sambe-sparse`（有两场自检断言该契约）。

| `_TF_MW_M_BW_MHZ` | 1e4 | 同上（取最宽者只增 M，最保守：sambe 行为不变） |
| `_M_ANALYTIC_BW_MHZ` | 2e4 | 同上 |

| `IP4_RWA_THRESH` | 1e-4 | 改名 `RWA_TOL`（进入控制面命名），值不变 |

  `4001` 三处行内魔法数 → `_RHS_ENV_TAB_N` / `_AC_ENV_TAB_N`。

## 4. 被考察后**决定不动**的项

| 项 | 结论 |
|---|---|
| `BW_OPT` 换相位判据 | 光学 ω 下 Θ≈C·T·Ω²/(2ω)≈0.03 ≫ 阈值 → 反旋/Bloch–Siegert 项会被**全保留**（更准更慢）；而相预算判据（∝1/T）会在长 T 下把共振对本身也误删。故保留固定窗 |
| 查表点数按 rtol 派生 | `_TAB_N` 是**接口契约**（任意波形可驱动带宽 = 0.5·(N−1)/T 报给用户，见 `waveforms.f_max_mhz` / `ui_waves`），不能按 rtol 缩；`_RHS_ENV_TAB_N` / `_AC_ENV_TAB_N` 是内存预算。派生式还需上下限夹取（尖沿 SquareEnv edge=1 ns 会算出 ~7e6 点）→ 复杂度不值，只登记为预算/契约常量 |
| `AC_EFFECT_THRESHOLD_MHZ` 移出 params.py | **不移出**：参数集中管理优先；已在 params.py 内标注为"UI 显示阈值，非引擎精度旋钮" |
| `_DENSE_MAX` / `_TF_DENSE_MAX` 合并 | 不可合并：标准两场两体 22 态为 484×5 = **2420 维**，必须留稠密，否则 `backend` 翻成 `tf-sambe-sparse`（有两场自检断言该契约）；反向合并到 2200 同理会改变 sambe 侧 backend |
| `MW_MAX_MHZ` 与 `adaptive_split_threshold` | 同一件事的固定/自适应两条路；自适应已 clamp 到 [1e4,1e6] 并以 `MW_MAX_MHZ` 兜底，视为一式 |
| `evolve_mixed_pair` scipy 对照路径的 `atol=1e-11` | 刻意比生产路径（`DEFAULT_ATOL=1e-10`）更紧：这条路的用途就是与 numba 驱动逐位对照 |
| `_ENV_PROBE_N`(2001) 与 `_ENV_SAMPLES`(64) 合并 | 都是"包络恒常判断"，但 64 点探针在长窗口上会漏掉窄包络 → 误判为恒常 → 物理错误。粗粒度只在 field_build 的特定上下文安全 |

## 6. 已做：裸全局变量 → 参数注册表（t81）

**动因**：控制参数要能长期从 GUI 调，而"`from .params import X` 在 import
时绑定值"使得任何运行时覆写都对消费者无效——这正是旧上帝模式必须为每个
旋钮单独加 kwarg 透传的根本原因。

**数据结构**（`params.py`）：

| 组件 | 作用 |
|---|---|
| `ParamSpec` + `SPECS` | 声明式元数据：默认值 / 分层【A~E】/ 标签 / 单位 / 类型 / 说明 / 典型范围 / 是否可调 |
| `DEFAULTS` | 默认值表（由 SPECS + `_DERIVED` 生成） |
| `ALIASES` | 旧名 → 规范名（如 `POP_PHASE_TOL` → `PHASE_TOL`），不进 UI |
| `_DERIVED` | 派生量（`DEFAULT_ATOL = DEFAULT_RTOL × ATOL_RTOL_RATIO`），不占独立自由度 |
| `get(name)` | 就近优先读覆写栈 → 派生 → 默认 |
| `override({...})` | **线程本地**上下文管理器；退出即还原；未知名 `KeyError` |
| `coerce(name, raw)` | UI 用：文本 → 类型化值 + 错误信息 |
| `specs(tier)` | UI 用：按层取可调参数 |
| `__getattr__` | PEP 562：`params.X` 回落到 `get()`，旧代码零改动 |

**读取点改造**：11 个核心模块、83 处 `_P.get('X')`；签名默认值（def-time
求值）19 处改为 `None` + 体内解析（插在 docstring 之后）。
**已知边角**：跨模块再导出（`from .sambe import _M_MAX`、
`from .evolve_mixed import R_CRIT`）随转发站消失而断裂——已改为直接走注册表；
`static_atom` / `evolve_rwa` / `sambe` / `evolve_mixed` 另加 PEP 562
`__getattr__` 回落，使旧的 `core.RYDBERG_N_MIN`、`from .evolve_rwa import RWA_TOL`
这类**属性访问**继续可用（且同样响应覆写）。

**GUI 链路**：检视器「引擎参数」页（由 `SPECS` 自动生成、按层分组）→
`param_overrides()` 快照 → `engine_kwargs['param_overrides']` →
`EvolveWorker.run()` 里 `with params.override(snapshot): 引擎(...)`。
线程本地栈保证工作线程读到覆写、主线程不受影响。

**与旧上帝模式的关系**：旧「引擎参数」页只有 4 行、按 kwarg 名手工登记
（`bw_opt`/`mw_cap`/`mw_nres_bw`/`mw_max`），且**只有 mixed 路径吃得到**
（hard/sambe 分支从不把 `engine_kwargs` 透给引擎）。现在：
- 页面内容由 `SPECS` 生成（32 项、按【A~E】分组、逐项说明与校验）；
- `param_overrides` 对**三条引擎路径都生效**（worker 里统一 `override`）；
- 引擎侧的显式 kwarg（`bw_opt` / `mw_cap` / `phase_budget` / `mw_max` /
  `r_crit` / `tol` …）仍然保留，作为"脚本直调"的入口；
  优先级：显式 kwarg > 注册表覆写 > 默认值。
