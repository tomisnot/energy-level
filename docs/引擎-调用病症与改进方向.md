## 0. 先记住三条好消息（决定改造可行）

1. **`src/core/` 完全自洽**：没有任何 `from src.X`（core 之外）的绝对导入，也没有
   `from ..` 越界。⇒ **可以整块搬走**，不需要拖着 GUI/AI/内核。
2. **引擎不 import `arc`**。`ArcCache`（`static_atom.py:216`）是**包装调用方传进来的
   ARC 原子对象**（`core.ArcCache(Rubidium87())`）；核心文件里所有 `arc` 字样都是注释与
   错误消息。⇒ 引擎的第三方依赖只有 **numpy / scipy / numba / torch**。
3. **`~/.arc-data` 可用**（本机 73 个文件）。⇒ 沙盒不需要项目内的 ARC 补丁，
   `import src.core` 从**原来带补丁的 ~5.9 s 降到 ~1.9 s**（实测）。

## 1. 病症（按严重度排序）

### 【A】调度层：同一件事三份实现，而且已经走偏 —— **最严重**

| 分派器 | 位置 | 谁在用 |
|---|---|---|
| `evolve_engine`（54 行） | `src/core/evolve_engine.py` | **只有 `checks/` 与 `ui_design/`**（我用 AST 全仓核过，产品代码零调用） |
| `EvolveWorker`/`EvolveWorkerPair` | `src/ui/evolve_worker.py` | GUI 旧路径，逐个 import 六个引擎函数 |
| `evolve_run`（L580–656） | `src/core/runspec.py` | **产品真走这条**（GUI + 并行 runner） |

`runspec.py:578` 的注释写着「GUI worker 与并行 runner 的**同一条**引擎调用路径」，
而 `evolve_run` 的 docstring 自己承认「**逐分支照抄 `src/ui/evolve_worker.py`**」。
⇒ **两份手抄 + 一份没人用的"统一入口"。**

**而且三份已经不一致**（可复现的最硬证据）：

| `method` | `evolve_engine`（单体） | `runspec.evolve_run`（单体） |
|---|---|---|
| `mixed` | `evolve_mixed.evolve_mixed` | 同 |
| `sambe` | `sambe.evolve_sambe` | 同 |
| **`hard`** | **`hard.evolve_hard`**（`evolve_engine.py:36`） | **`evolve_twofield.evolve_hard`**（`runspec.py:633`） |

⇒ **同一个 `method='hard'` 在两个入口调用的是两个不同的函数。**
（这不是理论风险：`hard.py:614` 与 `evolve_twofield.py:699` 各定义了 `evolve_hard`。）

**附带**：`evolve_engine` 的 docstring 写 `method: 'mixed' | 'sambe' | 'hard' | 'ip4'`，
**代码里没有 `ip4` 分支**（只有 L30/33/36 与 L41/45/49 六个分支）⇒ 传 `'ip4'` 直接
`ValueError`。`ip4` 实际在 `evolve_rwa.evolve(method=...)` 里。

### 【B】跨文件重名：公开名字各有两个实现

AST 扫 `src/core/*.py` 的顶层定义，**7 个重名**：

| 名字 | 位置 1 | 位置 2 | 说明 |
|---|---|---|---|

| **`env_at`** | `evolve_util.py:17` | `sambe.py:285` | **公开**，两份包络取值实现 |
| `_embed` | `evolve_twofield.py:460` | `sambe.py:479` | 私有 |
| `_pops_of` | `evolve_twofield.py:456` | `sambe.py:514` | 私有 |
| `_reconstruct` | `evolve_twofield.py:467` | `sambe.py:776` | 私有 |
| `_decay_ops` | `evolve_rwa.py:572` | `evolve_util.py:229` | 私有 |
| `_split_waves` | `evolve_mixed.py:719` | `route.py:20` | 私有 |

### 【C】静态能级与动态基组是**两套独立实现**

| | 走的路 |
|---|---|
| **静态页（能级）** | `ui_single.py:119` → `core.build_level_rows(...)`；`:540/546` → `core.spectrum_lines(...)`。**全程 `static_atom`，不建 RunSpec、不进引擎** |
| **动态页（布居）** | `runspec.build_states` → `get_hyperfine_levels` + `_sublevel_energy` + `dc_stark_shift_mhz` + `make_levels` → 引擎 |

`build_states` 的 docstring 说"与静态页/两体页**同基准**"——**那是约定，不是同一段代码。**
一旦两边漂移，症状是"静态页显示的能级不是动态页算的那个"，**这类错最难查**。

### 【D】引擎返回值契约不统一

- 单体：`res['pops']`
- 两体：`res['pops_2d']` + **`res['states_2d']`**（成对标签）

`runspec.result_labels` 里的注释就是伤疤：
> 两体**必须**用 `res['states_2d']`——直接照搬单体标签会把 N² 维布居标错（**server._res_labels 的 2026-09-10 教训**）。

摘要层 `result_summary` 因此要 `pops` / `pops_2d` 两个都判。

### 【E】引擎参数的作用域是隐式的，靠 warning 兜

`god_kwargs_from_params` 收来的运行级参数，**只有 `mixed` 会真正接收**；
其它 method 一律 `warnings.append('...已忽略：...')`（`runspec.py:476-482 / 525-532`）。
⇒ "设了参数却没生效"这类静默错，是**后来补的警告**，不是设计出来的约束。

### 【F】判据绑死私有 API —— 这是重构的直接障碍

18 个物理判据大量直接调用下划线名字：

```
core._sublevel_energy        core._group_sublevel_rows
_assemble_H_snapshot         _as_vector / _as_pair_vector
_e_rot / _evolve_full / _CONV / _MixedSetup
_field_geometry / _sublevel_row / _group_by_freq / _pack_pair_hard
evolve_pwc / evolve_floquet（来自 src/_archive）
```

⇒ 它们是**白盒测试**：验得深（好事），但**任何内部重排都会碎**（坏事）。
**重构前必须先把这一步处理掉**，否则你改一行内部就要修三个判据。

### 【G】死代码与"零公开面"的模块

| 模块 | 行数 | 状况 |
|---|---:|---|
| `project.py` | 33 | **全仓无人 import**（我用 AST 全仓核过） |
| `route.py` | 100 | **产品侧无人用**，只有 `checks/route_auto_selfcheck.py` 在守它 |
| `dop853.py` | 423 | **零公开 API**（全是 `_` 前缀），却是 `hard.py`/`coupling.py` 的核心 —— 名字说它是内部件，实际是承重墙 |

### 【H】一个 109 行的可选模块把 `torch` 变成硬依赖

`evolve_sambe_pair_gpu.py`（109 行）在模块顶层 import `torch`。
⇒ 整个 `src/core` 被迫依赖 torch（约 1 GB 级），而绝大多数运行根本不用 GPU 路径。

### 【I】引擎参数是全局注册表 + 上下文栈

`params.py`：`override(values)` 是上下文管理器，`effective()` 读**全局栈顶**。
跨线程 / 跨进程 / 嵌套调用的语义靠约定，没有显式传递。

## 2. 改进方向（对应的刀）

> **⚠ 方向 1 与 3 已在执行中被否决/改写**（2026-09-18 实际决定，见
> `docs/引擎接口规范化-第1-3刀.md`）：
> - **方向 1 反过来了**：不是"让 `evolve_engine` 成为唯一分派"，而是
>   **删掉它**。产品真走的是 `runspec.evolve_run`，`evolve_engine` 只被判据用
>   且已经走偏（对 `method='hard'` 单体指向了两个不同函数）。**删多余的入口
>   比统一到一个没人用的入口更直接。**
> - **方向 3 被否决**：`Engine` 协议 + adapter 是**套层**。改为**直接统一各引擎的
>   返回契约**（`pops_2d`→`pops`、`states_2d`→`states`），把分叉从"靠 adapter 抹平"
>   变成"根本不存在"。

## 3. 重构纪律（沿用本仓已验证有效的三条）

1. **先证明等价，再换路**——每次改动都要有**逐位对拍**（`max|Δ| = 0`），不接受"接口通了"。
2. **覆盖只迁移，不删除**——判据要**换锚**到新结构，不是删掉那条断言。
   子条件数只增不减。
3. **每步一个可回滚提交**，且**先跑基线绿再动手**。
