# 多体接口与维护约定

本说明是当前多体接口与维护契约；能力以代码、能力表与运行结果为准。

## 代码职责

| 模块 | 负责的事实 |
|---|---|
| `model.py`、`assemble.py` | 模型和原子标定；完整或指定基空间的 CSR 共用装配实现 |
| `backends.py` | 后端规范名称、别名、执行入口、支持的任务/能力、配置到形参的映射 |
| `schema_mb.py` | 产品可设置参数、单位、默认值和值域 |
| `basis.py`、`hamiltonian_plan.py` | MSB 位序、原子身份、受限基、约束图及编译入口 |
| `state.py` | 初态语法、在指定基中准备态矢、MPS 接续与 checkpoint |
| `runtime.py`、`resources.py` | 时间网格、分段跳变、协作取消/进度、工作区预算 |
| `runspec_mb.py`、`eq_engine.py` | 产品配置适配，标定与纯数值执行的线程边界 |
| `eq_route.py` | 通用任务路由；gs、thermal、DOS、ramp 分开执行，共用 QMC 适配 |
| `engine_*.py`、数值算法模块 | 后端实现、模型相关适用条件和算法诊断 |
| `results.py` | 结果数据含义、坐标轴、单位、身份和兼容字段 |

配置默认值用 `mb_get` 读取，不能用 `value or default`，否则合法的 0 会被覆盖。新增后端先修改能力声明，再实现数值函数；schema、GUI 选项和公共分派从声明派生。动态适用条件仍在求解器内检查，不能把所有物理判断塞进注册表。

ARC 标定必须在 cache 所属线程执行。RunSpec 携带数值标定快照；工作线程/进程不重新访问 ARC。标定缓存键包含能级、位置、周期长度、相互作用项、B、窗口、截断及标定精度，不包含 Ω/δ/Γ 等运行级驱动。

## 产品模型与研究 API

**多体 RunSpec 只认一种模型输入：`manybody.calib`（行内字典）。** 文件与 ARC 都不是
RunSpec 的写法——它们由构造器 `el_build_calib` 转成数之后写进同一个键。

`manybody.calib` 结构（单位 µm / MHz）::

    {"atoms": [{"id": 0, "pos": [x, y, z],
                "Omega_mhz": 0.0, "Omega_phase_rad": 0.0,
                "delta_mhz": 0.0, "gamma_mhz": 0.0}, ...],
     "pairs": [{"i": 0, "j": 1, "V": 0.0, "J": 1.0, "A": 0.0}, ...]}

`atoms` 的 Ω/δ/Γ 字段是**运行级可选驱动**（缺省 0，不参与任何标定缓存键）；
`pairs` 只需 `i/j` 与 `V/J/A`（J/A 可为复数=Peierls 相位，V 只取实部）；其余键
（`boundary`、`J0`、`notes`…）原样透传。

**没有 `terms` 输入**：活跃通道由数值推导（V≠0→I1，J≠0→I2，A≠0→I3）。不用某通道就把
系数写成精确 `0.0`；手写 `terms` 且与数值不一致会当场报错。引擎内部的 `terms` 参数
仍然存在（研究 API 显式选择，优先级高于推导）。

**RunSpec 不接受的输入**：`manybody.atoms`、`calib_file`、`B_gauss`、`n_window`、
`r_cut_um`、`second_order`、`guard_mhz`、`periods_um`。它们是 `el_build_calib` 的
ARC 构造入参（`manybody.build.arc`），不是运行键；多体运行不读 `field.*`。

**哪些键只对哪条路有意义**：

- 只对 ARC 构造器：`B_gauss`、`n_window`、`r_cut_um`、`second_order`、`guard_mhz`、
  `periods_um`（进 `manybody.build`，不进 RunSpec）。
- 两条路都有效：`solver`、`eq_backend`、`charge_sector`、`psi0`、`constraint`、
  `distance_cutoff_um`、`drive_segments`、`drive_interp`、`loops`、`link_pairs`、`chi_max`/`truncerr`/`max_sweeps`、
  `return_state`、`memory_budget_mb`、`dtype`、`device` 等运行与后端选项。

构造 calib 的通用小工具在 `manybody/calib_build.py`（不含任何具体物理模型）：
`lattice_positions`（格子 → 点云）、`distance_pairs`（点云 → 距离/周期像诊断）、
`from_positions`（点云 + 耦合核 → calib，支持周期像加和）。耦合核由调用方给：
`coupling(r)` 返回 J 标量或 `{V,J,A}`。

平衡态 `want=gs` 在 ED/Lanczos 且 `2^N ≤ CORR_MAX_DIM` 时**同时返回 `corr`**
（连通占据关联，与含时结果同一定义）；DMRG 后端默认只给 `n_atom` 与纠缠熵——
需要关联时显式声明 `manybody.mps_diagnostics={"corr": true}`（代价 O(N²) 次
MPS 收缩，不默认跑）。超出维度上限时结果里**没有** `corr` 字段（不填零）。

## 任意阶 Pauli 字符串（`manybody.pauli_strings`）

通用高阶观测原语：把"任意站点 × 任意单格点 Pauli 轴"的乘积做成**可请求的观测量**，
而不是把某个具体物理量（手性、环乘积、Wilson 线……）写进引擎。引擎只返回
`⟨σ^{a1}_{i1} σ^{a2}_{i2} …⟩`，**物理含义由调用方组合**——与 `manybody.source`
（"引擎不解释算符的物理含义"）同一纪律。

```jsonc
[[[0,"x"],[1,"y"],[2,"z"]], …]                        // 每条 = 若干 [站点, 轴]
[{"label":"chi_A","terms":[[0,"x"],[1,"y"],[2,"z"]]}]  // 可混用，label 可选
```

| 项 | 约定 |
|---|---|
| 站点 | calib 的**原子原序**（与 `n_atom` 同口径）；一条串内不得重复 |
| 轴 | `x`/`y`/`z`（接受 `σx`/`sx` 等别名）；单格点矩阵是标准 Pauli，基 `(|g⟩,|r⟩)` |
| ⚠ sp/sm | 本仓 `sp/sm` 是 `|r><g|`/`|g><r|`（Rydberg 意义的激发/退激发），**与 σ± 的教科书编号相反**（`σ⁺_本仓 = (σˣ−iσʸ)/2`）。只用 x/y/z 时不受影响 |
| 结果（含时） | `observables.pauli_strings`：复数组 `(n_t, n_strings)`；标签在 `observables.pauli_string_labels` |
| 结果（平衡态） | 顶层 `pauli_strings`（`(n,)` 复数）+ `pauli_string_labels` |
| 支持面 | 含时 `ed`（全空间/投影基）、`tebd`/`tdvp`/`tdvp-single`/`tdvp-adaptive`、`tebd-gpu`/`swap-tebd-gpu`、`tdvp-trajectories`（系综平均）、`classical-spin`（因子化）；平衡态 `ed`/`lanczos`/`gpu-lanczos` 的 gs、`dmrg` 的 gs。PEPS/QMC/KPM/free-fermion/gpu-batch 明确拒绝并给替代 |
| 语义 | 纯态后端统一走 `observables.measure_pauli_strings`（内部 `PauliPlan` 预编译索引/相位，跨时刻复用）；轨迹标 `approximation='trajectory ensemble average'`，经典标 `factorized classical spin`。近似值不与纯态期望混用而不标注 |
| 校验 | `schema_mb.validate_pauli_strings` 在 **build 阶段**点名第几条/哪个站点/期望什么 |

求值有**全空间 / 受限基 / 有限 MPS** 三种形态，由 `observables.PauliPlan` 与
`measure_pauli_strings` 统一：引擎只调入口，纯态路径预编译索引/相位并跨时刻复用。
判据用**独立稠密参考**与跨形态对拍（`checks/manybody_pauli_string_selfcheck.py`）：

- **全空间态矢**：逐算符作用（σᶻ 逐位相位、σˣ/σʸ 位翻转 + 相位），O(len·dim)，不建矩阵；
- **受限基**（固定荷扇区 / 投影 Plan）：按位编码映射；打到基外的分量按 0 计
  （受限基就是截断空间；这是定义，不是近似）；
- **有限 MPS**：展开成局域算符之积（σˣ=P+M、σʸ=iP−iM、σᶻ=SZ），逐项
  `MPS.expectation_value_term`；代价 ∝ 2^(非 z 轴个数)。**必须用簇模型自己注册的
  SZ/P/M**：TeNPy 在 `conserve='Sz'` 下会按电荷重排局部基（`state_index('up')=1`），
  自带 `Sigmaz`/`Sp`/`Sm` 会差符号或互换；模型注册的矩阵是固定的，与 calib 同序。
  不要用 `get_rho_segment`：它返回的轴序**随 segment 是否连续而变**，不能作为
  稳定契约。

**用之前要知道的两件事**：

1. **实哈密顿量的基态必有 χ≡0**（时间反演 + 厄米 ⇒ 期望纯虚 ⇒ 与实性矛盾）。
   想看到非零手性，要么复模型（Peierls 相位/流），要么非本征态（制备末态）。
2. **近简并基态上单态期望值没有唯一值**。实测 12 点 kagome、`k=4` 的 gap 只有
   `5.7e-5`：ED 与 DMRG 会落到简并子空间的不同组合，χ 差可达 `1e-4`。要拿 χ 做判据
   （或做 ED/MPS 对拍），先确认 `gap` 远大于数值误差，必要时加一个小场劈开简并。

**不变量（踩过的坑）**：

- `conserve='Sz'` 的 TeNPy 站点会按电荷重排局部基（`state_index('up')=1`）；MPS 路
  必须用簇模型注册的 `SZ/P/M`，不能用自带的 `Sigmaz/Sp/Sm`（会差符号/互换）。
- `get_rho_segment` 的轴序随 segment 是否连续而变，已弃用；不要再接回去。
- 默认 `pauli_strings=None` 时，所有后端的结果字段、体积与 `data_schema` 不许变。
- MPS 的站点下标对外是**原子原序**；内部按 `order` 映射。映射错会静默错位。
- 不支持的后端必须拒绝并给替代，不允许 `**kwargs` 吞掉。

## 源态谱（`manybody.want="spectrum"`）

通用能力：**H、|0⟩、φ=O|0⟩ → 展宽谱 + 未展宽求积 + 收敛诊断**。引擎不解释
"哪个算符是质量算符"，源由调用方给；峰值/束缚态判定也留在调用方。

| 配置 | 说明 |
|---|---|
| `manybody.source` | `{kind:"vector",values}` / `{kind:"psi0"}`（\|0⟩ 本身） / `{kind:"diagonal",values}` / `{kind:"sparse",rows,cols,values}` / `{kind:"full_sparse",…}`，都在**当前基**里（固定扇区时=该扇区基）；`full_sparse` 在扇区模式下投影回扇区并报 `error_report.projected_leak` |
| `manybody.spectrum` | `{eta, n_krylov, n_omega, omega_min, omega_max, reortho}`；窗与展宽是显示参数 |
| 源态 | 省略 `source` 时默认用 `manybody.psi0` 作 \|0⟩（模式串/向量会先物化）；`psi0` 为空则用基态；原生 MPS 初态明确拒绝 |
| 后端 | `ed` / `lanczos`（`auto` 按维度选）；DMRG/QMC/KPM 明确拒绝 |

结果：`energies`（ω 网格）、`spectral`（S(ω)，1/MHz）、`evals`（Ritz 节点，相对
E0）、`spectrum_weights`（未展宽权重，程序化用）、`source_norm`、`krylov`
（步数/收敛/正交性/是否降级）。**和规则**：`Σ weights = ‖φ‖²`；
`error_report.integral_ratio` 是窗内积分比（窗不够宽会 <1，属诊断不是误差）。

实现：`manybody/spectrum.py`（Lanczos + 连分式）。内存超预算时把全重正交降级为
不重正交，并在 `krylov.note` 里写明（不静默换算法）。判据：
`checks/manybody_source_spectrum_selfcheck.py`（对精确对角化逐项核对节点、权重、
峰位、和规则、扇区投影泄漏与拒绝路径）。

## 卡片轴单位

`data_schema.axes.<axis>.unit` 会随 dataset 下发为 `axis_unit`，前端优先用它、
内置常量表只作兜底（`web/run_monitor/visualization.js: unitOf`）。于是无量纲格点
（a=1）的卡片可以声明自己的单位，不必被迫显示 μm/ns。

## 淬火/制备态初态（`manybody.psi0={"kind":"ground_of",…}`）

初态 = **另一个模型**的基态，演化用本次运行的模型（通用，不含任何领域预设）：

```json
{"kind": "ground_of", "calib": {...}, "terms": ["I2"]}
```

- 两个模型同一种货币（calib），原子数必须一致；
- ED 后端 → 全空间态矢（维度上限 `2^20`，超出请用 MPS 后端）；
- MPS 后端 → 同 `manybody.mps_order` / `charge_sector` 的原生 TeNPy 态
  （DMRG 准备，`chi_max`/`max_sweeps` 沿用同名配置）；
- 准备结果与来源进 RunSpec 的 `quench` 字段（`prepared_by`/`E0`/`terms`），并写一条
  warning；`solver=auto` 仍按维度选后端。
- Python API 也可以直接给**态矢**（`manybody.psi0 = np.ndarray(2**N)`），用于
  `exp(-iεO)|0⟩` 这类脉冲初态；JSON 路径下用 `ground_of` 或 `vector`。

判据：`checks/manybody_quench_selfcheck.py`——ED 与 MPS 两条准备路都与**精确时间
演化**对照（占据误差 <1e-10 / <1e-6），并覆盖原子数不一致、缺 calib 的拒绝路径。

## 分支初态：置换扇区（`manybody.psi0={"kind":"permutation_sector",…}`）

把任意初态投影到**显式站点置换**的 ±1 本征空间（要求对合 `U²=I`）：

```json
{"kind": "permutation_sector", "base": "rrrr…gggg",
 "permutation": [18,19,…,17], "sign": -1}
```

- `base` 用任意已有初态语法（模式串 / `ground_of` / 原生 MPS / `null`）；
- ED → 全空间态矢按比特置换投影；MPS → `mps_symmetry.project_permutation_sector`
  （构建**与本次运行同 `mps_order`/`charge_sector`** 的原生态，不隐式重排）；
- 返回 `projection_weight`、`base_overlap`（基态自身 ⟨P⟩）、`sector_overlap`（投影后 ⟨P⟩=±1）；
  权重 ≤1e-12 的扇区明确报错（说明 base 落在相反本征空间）。
- **投影只约束初态**：DMRG/演化不施加扇区约束，而且**实测扇区守不住**——N36 2×6 从
  ⟨P⟩=−1 出发，末态 ⟨P⟩=+0.9999984。要声称"某扇区的基态"，必须同时满足末态 ⟨P⟩ 匹配
  且 `diagnostics.solver_converged=true`；否则能量差只是数值差异（实测同一扇区的两次
  运行差 7.7e-6，较高的一次撞了 sweep 上限）。
- 扇区约束求解（求解中保持对称性）**尚未实现**，是已知能力缺口，别把"投影初态 + DMRG"
  当成"扇区基态"。
- 平衡态路径（`want=gs` + `eq_backend=dmrg`）同样支持。

判据：`checks/manybody_prepare_selfcheck.py`——ED/MPS 的 ⟨P⟩=±1、权重、演化保持对称、
`mps_order` 跟随、非对合/长度不符/sign 非法的拒绝路径。

## 装配：`manybody.build` 是构造器的入参（RunSpec 之前的一步）

快照里唯一"不是 calib"的装配物是 `manybody.build`，它与 `el_build_calib` 收的是**同一份**数据
（不存副本，避免退化）；构造器据此产出 `manybody.calib`，回执由 calib **现算**（`build_receipt`）。
另有 `manybody.label` / `manybody.notes` 两个短字段，只服务卡片阅读。

```jsonc
{"source": "file", "file": "n36_mass_g0.1.json"}   // 读 <EL>/.mecha-v2/calib/ 下的 JSON
{"source": "arc", "atoms": […g/r…],                 // ARC 标定
 "arc": {"B_gauss":21.7,"n_window":3,"r_cut_um":7.0,"second_order":true,
         "guard_mhz":1.0,"periods_um":null}}
```

- 文件目录限定 `<EL>/.mecha-v2/calib/`（`$EL_CALIB_DIR` 改根），越界/坏 JSON/缺文件当场报错；
- 返回 `{calib_summary{fingerprint,n_atoms,n_pairs,sum_abs_J,max_abs_J}, build_receipt, build}`；
  `build_receipt` 由 calib 现算（含 `tail_norm_bound`/`n_dropped`/`n_guarded`）；
- N≈36 的 630 对 J 表约 27 KB，走构造器比塞进工具参数更稳（也避开 DSH 参数层对超大
  payload 的"必须可无损序列化"检查）；
- **判断某字段该不该进 build**：它是不是构造函数的入参？是→进；只是"想给人看"→不要进，
  由 web 只读侧从 calib/回执里取（`label`/`notes` 是唯一允许的例外，且只限短文本）。

## MPS 顺序规则（否则数值会静默变差）

- **通用 calib 的 DMRG/CPU-MPS 必须显式给 `manybody.mps_order`**，用 rung 顺序
  `[(m*ln+n)*3+sub for n in range(ln) for m in range(lm) for sub in range(3)]`。
  默认 `cylinder_order` 会把同一物理 rung 拆开（实测 `n_legs=8`、腿长不等），
  χ=512 时截断仍达 4e-4 并触发 `max_trunc_err`。
- 初态的 `order` 必须与运行一致（否则 `Warm-start order mismatch`）；`ground_of` /
  `permutation_sector` 已自动跟随。
- 同进程接力：`DMRG(... return_state=True)` 取 `state.kind="mps"`，下一点作为
  `manybody.psi0={kind:"mps", ...}` 传入；`order`/`charge_sector` 由 state 携带，
  不要手改。判据：`checks/manybody_dmrg_warmstart_selfcheck.py`。

## 无限体系 iDMRG（`eq_backend="idmrg"`）

当前 DMRG 的有限路径仍是 `Chain(..., bc_MPS='finite')`；iDMRG 是独立路径，
不改变有限 `calib` 与有限 DMRG 的行为。

输入是**通用单元胞**，不是阵列形状枚举，也不是有限 `calib`：

```jsonc
"manybody.idmrg": {
  "cell": [{"site": 0}, {"site": 1}],
  "terms": [
    {"kind": "onsite", "site": 0, "op": "Z", "coeff": -1.0},
    {"kind": "pair", "i": 0, "j": 1, "dx": 0,
     "op_i": "X", "op_j": "X", "coeff": -1.0},
    {"kind": "pair", "i": 1, "j": 0, "dx": 1,
     "op_i": "X", "op_j": "X", "coeff": -1.0}
  ]
}
```

- `cell` 至少 2 个 site（TeNPy 两站点 DMRG 的硬件限制）；`dx` 是 j 相对 i 的单胞偏移；
- 只支持一个平移方向；无限方向周期，周向开放/周期由 terms 是否包含对应键决定；
- 局部算符 `I/X/Y/Z/N/P/M`；首版局部维数 2；
- `dx` 上限 64；非平移不变/负 `dx`/未知算符/与 `manybody.calib` 同时给 → 拒绝；
- `charge_sector` 是**每 cell** 的激发数；组合判据按整项净 ΔN（`P_i M_j` 放行）；
- `manybody.pauli_strings` 支持 cell 内任意阶 Pauli；X/Y 展开成 P/M，有扇区时只留净 ΔN=0 的组合；
  结果给 `pauli_strings (n_strings,)/pauli_string_labels`，可用于手性三体串；
- Rydberg 单元胞可用 `src.core.manybody.idmrg.from_rydberg_cell(cell, pairs)` 转成
  `terms`；这只是构造器，iDMRG 引擎本身不绑定 Rydberg。

结果语义和有限体系不同：`E_per_site`（每 site，MHz）、`E_per_cell`（每 cell）、
`S_per_bond`、`n_atom (cell,)`、`corr_length`、`chi`、`trunc_err`；**没有**
有限体系的 `E0` 总能量，也**不输出** `gap`。`describe_result` 已登记这些字段。

## 有限温关联（`want="thermal"`，exact ED）

`eq_backend="ed"` 在 **N≤12** 时返回 `n_atom (n_beta,n)` 与连通占据关联
`corr (n_beta,n,n)`：

```
corr_ij = ⟨n_i n_j⟩ − ⟨n_i⟩⟨n_j⟩
        = (⟨σz_iσz_j⟩ − ⟨σz_i⟩⟨σz_j⟩) / 4
```

`data_schema.quantities.corr.axes = [beta,site,site]`。N>12 仍给 `E/C/F`，但
**不物化稠密本征矢**；结果带 `corr_unavailable_reason`，不填零。
局域场线性响应不是引擎 API：对 `delta±` 各跑一次 `thermal`，对 `n_atom` 做有限差分
即可；这属于调用方组合。

## 系综驱动（Python API，不是 MCP 工具）

`src/core/manybody/ensemble.py`：

```python
run_ensemble(params, sampler, n_samples=..., seed=...,
             observables=('pops_atom', 'corr'),
             conditional=None, return_samples=False)
```

- `sampler(rng) -> calib` 或 `(calib, overrides)`：替换 `manybody.calib`，可用 overrides 改 `manybody.psi0` 等（初始缺陷）；原子数/ID/pair 由 `validate_calib` 校验；
- 内部走既有 `protocol.build_run + evolve_run`，不新写求解器；
- 返回 `unconditional` 与 `conditional` 两套 `mean/stderr/n`，外加 `acceptance`、
  `rejected`、`error_report`；`n=1` 的 `stderr=NaN`；
- **速度**不是 calib 字段：若只是 shot 间初始位置偏移，折进 `sampler` 的 `pos`；
  真正的时变位置/Doppler 属于新物理模型，不支持。
- 因为 `sampler` 是 Python callable，本功能不暴露为 MCP 工具；MCP 的批量扫描仍用
  `run_actions` 的 `spec_patch`。命令行薄包装：`scripts/run_ensemble.py --params … --samples … --sigma-pos-um … --flip-prob …`。

## 有限温 MPS：调研结论（未接线）

TeNPy 1.1 的 `PurificationTEBD` / `PurificationTEBD2` 的 `prepare_evolve` 把
`type_evo='real'` **写死**，它们做的是"纯化态的实时演化"，不是热化。要做热态得
自己调 `calc_U(order, dβ, type_evo='imag')` 再 `update_imag/update`，并且还需要：
① 对纯化态可用的 MPO 期望（能量与关联）；② 热力学积分求 F（`Z/Z₀ = ‖ψ(β)‖²`）；
③ 截断/χ/β 的收敛契约。这三件都不是接线，而是新算法模块，应单独一轮做，附带
与精确对角化小体系的对照判据。

## 当前含时能力边界

| 后端 | 分段驱动 | 投影基 | gamma/跳跃 | 返回态 | 固定荷 | Pauli 串 |
|---|---|---|---|---|---|---|
| ED | 支持，精确分割跳变 | 支持，共用稀疏/稠密路径 | 非厄米 no-jump | 态矢与基身份 | 含时暂不提供；平衡态支持 | 支持（全空间/受限基） |
| CPU TEBD/TDVP 系列 | 支持 | 拒绝 | gamma 必须为 0 | 有限 TeNPy MPS | 支持，检查守恒 | 支持（TeNPy MPS） |
| 稠密 CPU TDVP（tdvp-dense） | 支持 | 拒绝 | gamma 必须为 0 | 支持（dense 原生态） | 拒绝 | 支持（有限 MPS） |
| GPU TEBD/SWAP-TEBD | 支持 | 拒绝 | gamma 必须为 0 | torch MPS 张量快照 | 拒绝 | 支持（torch 收缩） |
| 量子轨迹 | 明确拒绝 | 拒绝 | 局部跳跃通道 | 暂不提供 | 暂不提供 | 支持（系综平均，带 approximation） |
| 经典自旋 | 明确拒绝 | 拒绝 | gamma 必须为 0 | 自旋时序 | 不适用 | 支持（因子化，带 approximation） |
| PEPS | 明确拒绝 | 拒绝 | gamma 必须为 0 | 暂不提供 | 暂不提供 | 拒绝并给替代 |

TEBD/PEPS 还需满足各自的相互作用几何要求。原生 MPS 只能交给匹配的后端；全空间纠缠向量/叠加式与一般局部乘积态不是同一种输入。整数乘积态索引按 site0-MSB 展开，无需分配全空间向量。

不支持的物理输入必须明确拒绝。新实现不得通过 `**kwargs` 接受后静默丢弃；保留扩展参数的入口要拒绝未知键。进度与取消在输出/内部步的协作检查点处理，单个线性代数库调用通常不能中途打断。

## 含时后端与自动选择

- `auto` 只在 ED 与 TDVP 之间选（按有效基维度 vs `ed_max_dim`）；**不会**把量子问题
  静默降级成经典自旋。
- `classical-spin`：每原子单位 Bloch 向量，解经典 Poisson/LLG；`pops_atom=(1−s_z)/2`；
  链路关联是因子化近似；代价随原子数/键数线性，不产生纠缠。
- `tdvp-mpo`：独立 finite MPO-TDVP 后端（TeNPy `TwoSiteTDVPEngine` + MPO 环境）；
  只支持显式乘积初态、静态驱动、厄米演化；拒绝 segments/Pauli/固定荷/return_state。
- `tdvp-dense`：CPU 稠密两站点 TDVP（`manybody/tdvp_dense.py`，numpy + BLAS，
  不经过 TeNPy `np_conserved`/`SingleSiteH`）。有限开链、任意长程 MPO、显式
  `manybody.mps_order`、乘积初态；默认局部传播用 Taylor（小相位）并回退 Lanczos。
  支持 `manybody.drive_segments`（每个分段边界只重建 onsite MPO 与环境，状态连续；
  `manybody.drive_interp='midpoint'` 把段条目当线性 ramp 控制点取段中点，ED/MPS/本后端均可，
  ramp 精度二阶；默认 `left` 与旧结果逐位一致）
  和 `manybody.pauli_strings`（有限 MPS transfer 收缩，原子序/显式 mps_order 均可）；
  支持原生 MPS `return_state`（`backend='tdvp-dense'`，可继续喂给同一后端）；拒绝固定荷/corr/link_pairs/loops/gamma；可选局部 `observables`。
  可用环境变量 `EL_TDVP_BLAS_THREADS` 限制本次运行的 BLAS 线程
  （本机小体系 1、N≥24 约 8 更快；不设则沿用进程默认），`error_report.blas_threads`
  记录实际值。与 `tdvp` 同阶对拍：N=12（χ=64，t=20 ns）max|Δpops|≈4.3e-7、
  墙钟约 0.85 s vs 11.6 s；N=24（χ=64，t=20 ns）max|Δpops|≈9.6e-7、
  墙钟约 18.5 s vs 87.3 s（本机 RTX 4050 Laptop / 16 核；数值随机器与热状态变）。
- `tdvp-trajectories`：两站点 TDVP + 局域 collapse 通道；无跳跃/跳跃一阶分裂；
  输出轨迹平均、MC `stderr`、`jump_counts`、`survival_weight`；误差同时来自 χ、
  内部步长与抽样。
- `peps-real-time`：矩形网格、最近邻、simple-update SVD；非网格/长程键明确拒绝；
  `discarded_weight`/`norm_drift` 是结果的一部分。
- PXP/blockade 投影当前只允许 ED；其它后端拒绝，不假装编译了受限 MPO。

## 通用观测与时间步长

- `t_grid` 只定义**输出**时刻。`manybody.max_step_ns` 是 MPS/PEPS/经典/轨迹的内部
  积分步长上限；ED 直接传播到输出时刻，不需要内部细分。
- 公共观测键：`pops_atom`、`sx/sy/sz/sp/sm/phase`、`link_pairs`/`link_corr`、
  `loops`/`loop_phase(_series)`/`loop_winding(_series)`、`S`、`corr`。
- `link_corr[t,q]` 的列序与 `link_pairs` 完全一致；`loops` 的边会自动并入
  `link_pairs`。`phase=arg(sm)`，相干幅度低于阈值时为 NaN。
- 量子后端给真实链路关联；经典自旋给 `<σ⁺ᵢσ⁻ⱼ>≈<σ⁺ᵢ><σ⁻ⱼ>`；轨迹给系综平均。
  这三类必须在 `observables.approximation` 或 `error_report` 中标注。
- MPS 的完整 `N×N` 关联只在显式 `want_corr=true` 时算；逐时链路用 `link_pairs`。
- 收敛性用改变 `max_step_ns`/χ 交叉检查，不能把"跑完"当"收敛"。

## 状态接续与 MPS 资源

- `manybody.return_state=true`：ED 返回 `psi_amp`，DMRG 返回 `kind=mps, backend=tenpy`，
  CUDA MPS 返回 `backend=torch` 的 `(left,2,right)` 张量列表；不支持的算法明确拒绝。
- 接续要求站点数、原子顺序、局部基/荷一致；不隐式重排、不隐式转换 TeNPy ↔ torch。
  跨会话用本地 HDF5 checkpoint（`state.save_mps_checkpoint`）。
- `manybody.mps_dtype=auto/real/complex`：`auto` 只有张量虚部严格为零才用 float64；
  `real` 遇到非零虚部拒绝；时间演化在 `exp(-iHt)` 前显式升复杂。
- `manybody.mps_diagnostics={variance,permutation,blocks,corr}`：精确方差/置换期望/
  分块收缩是**显式 opt-in**，按 `memory_budget_mb` 估工作区，不够就拒绝；
  诊断不认证基态唯一性或 Hamiltonian 对称性。
- 有限 MPS 的详细资源契约见 [有限 MPS 分析与资源契约](有限MPS分析与资源契约.md)。

## 拓扑原语

`manybody/topology.py` 是模型无关的诊断原语：`twist_pairs`/`twist_calibration`
（显式跨胞元 winding）、`wilson_loop`、`spectral_flow`、`entanglement_spectrum`、
`fukui_chern`、`loop_flux`；统一 `topology_result`/`topology_report` schema。
扭转如何进入 Hamiltonian 由模型层提供；引擎不把单粒子 Chern 数或单个闭环相位
自动宣称为多体拓扑序。

## 基空间与资源

原子 0 对应最高位，`r=1`、`g=0`。`basis_bits(N, codes)` 是将基矢身份映射到原子占据的公共函数。编译器不修改共享 Plan。

受限基按独立集生成，设有最大输出状态数；图计数使用带预算的删除/收缩递归，避免直接遍历所有 `2**N` 构型。计数预算不足时，预估端回退到保守全空间估计并说明原因。后端选择按有效基维度进行。

`memory_budget_mb` 使用 MiB，是主要数组和工作区的保守估计，不是操作系统/CUDA 分配器峰值的硬保证。ED 根据预算调整稠密阈值与联合概率输出；GPU/PEPS 检查自己的张量工作区。KPM DOS 不再先计算完整谱，谱界在较大矩阵上使用迭代求解；显式 exact/ED 热态与 DOS 仍需要谱分解并检查预算。

投影态的纠缠熵在实际 Schmidt 行列身份上计算；超过临时矩阵预算时返回 NaN 并给出说明，关闭计算时返回 None，不能填零假装没有纠缠。

## 结果数据契约

旧字段保留以兼容既有调用方，新消费者读取 `data_schema.version=1`。`data_schema.quantities` 按数据路径描述 `quantity`、`axes`、`unit`；描述不复制数值数组。未定义的相位或未求得的量用非有限值表示，描述会标记 `missing_values`。

紧凑摘要不再按量名手写：descriptor 的 `summary` 声明 scalar/top/final/head/list/rows/first_last/first_last_axis 策略，`summarize_result` 只执行策略；heat bath 的 `corr` 给首/末 β 的 n×n 矩阵，`n_atom` 按 β 给行，不把二维关联拍平；二维逐项曲线由 descriptor 的 `items.labels` 声明，Web 投影按该规则拆分，不按路径名特判。有效驱动（静态/分段）由 `runtime.describe_drive` 统一给出，MCP preview、运行卡片和驱动曲线共用，不在消费者里各自重算。

| 数据 | 语义与坐标轴 |
|---|---|
| `pops` + `pops_kind` + `states` | 兼容输出；明确为 `(time,basis)` 的联合概率或 `(time,site)` 的逐原子占据，标签必须逐列对应 |
| `pops_atom` | `(time,site)` 原子激发占据 |
| `basis_probabilities`、`basis_states` | 已物化的联合基概率及受限基编号；完整基由 MSB 约定确定 |
| `basis`、`sector_idx` | 态矢所在的基空间、位序与索引，避免把受限向量误作全空间向量 |
| `sites` | 稳定 site_id 与可用的位置，供二维点阵图映射 |
| `S`、`corr` | 纠缠熵与关联矩阵；缺失值有明确含义 |
| `observables.*` | 局部自旋、复值升降算符、关联与环相位，保留真实复数 |
| `stderr`、`E_err` | 对应观测量的标准误差 |
| `E0`、`gap`、`evals` | 基态、本征能量和能隙；QMC 低温近似不伪造能隙 |
| `E/C/F` + `betas` | 逆温度轴上的热力学数据 |
| `rho` + `energies` | 真实能量轴上的归一态密度 |

`loss` 是兼容别名。新消费者必须区分 `physical_loss`、`norm_drift`、`no_jump_weight_deficit` 和 `survival_weight`。PEPS 数值范数漂移不表示原子离场，GUI 不再将这些数据统一标为离场损失。

RunSpec 结果记录 `requested_backend`、`resolved_backend` 与传递的 `used_options`；算法实际步长、截断、收敛等信息在 `error_report` 中。直接数值调用同样附加数据描述。存档保存完整引擎结果，不再维护第二套容易遗漏新字段的白名单；原生态的大数组由求解器的显式返回选项控制。

通用有限 MPS 实数静态路径、原生基态接续、显式顺序与精确诊断见
[有限 MPS 分析与资源契约](有限MPS分析与资源契约.md)。新增诊断仍由数值模块负责，
置换的物理含义与模型对称性由调用方提供。

## 性能基准

`scripts/bench_mps.py` 是 MPS 的显式基准入口（不进入默认判据）：

```powershell
python scripts/bench_mps.py --calib checks/fixtures/kagome_n12.json --chi 64 \
    --t-max 20 --npts 3 --dt 2
python scripts/bench_mps.py --calib checks/fixtures/kagome_n24.json --gpu \
    --chi 128 --t-max 10 --npts 2 --dt 10
python scripts/bench_mps.py --calib checks/fixtures/kagome_n24.json --chi 64 \
    --pauli 96 --pauli-order 3 --t-max 10 --npts 3 --dt 10
```

输出含墙钟、内部步数、`engine_builds/reuses`、`measure_s` 占比、GPU 峰值显存。
同段分段驱动复用 engine；段边界才重建 model。当前机器上的微基准只作基线，不是性能承诺：
12 点 χ=64 的 10 个内部步约 11.5 s；24 点 GPU χ=128 的单步约 211 s；
96 条三体串在 12 点 χ=32 上测量占比约 62%（>20%，调用方应优先只算关心的串）；
36 条六体串在 24 点 χ=32 的单步约 1.8 s，尚未到需要专门缓存的量级。
CPU TDVP 的 `krylov_tol` 从 1e-10 放宽到 1e-6 只省约 12%，不是数量级来源；
真正的热点在 TeNPy 的 `np_conserved.tensordot`/Krylov 纯 Python 收缩。

硬件/编译实验（同一 12 点 χ=64 模型；只作当前机器证据）：

- CPU OpenBLAS 线程 1/2/4/8/16：墙钟 12.07/11.89/11.65/11.74/11.77 s，**没有收益**；
  小张量收缩 + Python 控制流吃掉了并行度。
- TeNPy `OptimizationFlag.skip_arg_checks`：10.86 vs 11.02 s，**没有收益**。
- `torch.compile(TorchMPS.apply_two)`：默认模式 14.6 s vs eager 6.2 s，且 CUDAGraph
  因 `.item()`/复数 SVD 失败；**不作为产品路径**。
- GPU `swap-tebd`：24 点 χ=128 单步 float64 约 211 s、float32 约 95 s；
  12 点短程 χ=8 的 profile 中 `apply_pair/apply_two` 占主要时间。
  `swap-tebd` 对每个长程 pair 做 O(distance) 次 SWAP/SVD，是**算法代价**，不是编译问题。
- GPU `dtype=float32`（complex64）在 24 点 χ=128 单步约快 2.2×；12 点短程
  float32 vs float64 的 `pops_atom` 最大差约 5e-7。它是**显式近似开关**，长时窗/
  强纠缠需与 float64 对拍，不能默认替换。
- JAX（本机 CPU）、Numba（`np.tensordot`/SVD 支持不完整）没有可用的整链替代；
  `cupy` 可做核级试验，但 TeNPy 的 block-sparse `np_conserved` 不能直接替换。

结论：硬件/编译只能拿到常数级；要真正解决 24 点长程，需要 **GPU 上的 MPO-TDVP**
（避免每个 pair 的 SWAP 链）或 Cython/Numba 的稠密两站点内核，属于算法/内核工程，
不是打开一个编译开关。

## 维护与验证

新增能力至少验证一个公开配置入口和一个拒绝案例。矩阵/观测交叉验证使用不对称失谐、复耦合和非平凡初态；不要只使用全 g 初态和对称点阵。

`checks/manybody_contract_selfcheck.py` 集中验证能力声明、配置转发、缓存失效、投影身份、分段边界、资源拒绝、数值后端入口和存档完整性，并纳入 `run_checks.py --core`。既有物理基准继续独立保留，不能用契约测试代替 ED/解析解参照。
