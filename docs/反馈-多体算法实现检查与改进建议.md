## 2. 建议

### P0-1｜DMRG 没有打开 U(1) 量子数（最容易修、收益最大）

**现状**：`dmrg.py` L45 与 L110 都是

```python
return SpinHalfSite(conserve=None)
```

**影响**：TeNPy 在 `conserve=None` 下**不使用量子数块稀疏** ⇒ 同等 χ 精度更低、同等精度更慢，
且失去"荷区保护"（变分过程可能跨荷区游走）。

**改法**（几乎是一行 ＋ 两处配套）：

1. `SpinHalfSite(conserve='Sz')`（或用 `'parity'`，取决于算例）；
2. 模型初始化给 **`total_charge`**（例如目标 Sz=0 扇区 ⇒ `total_charge=[0]`；开边界有限 MPS 用 `bc_MPS='finite'` 时按 TeNPy 惯例放进 `MPS`/`DMRG` 的初始化参数）；
3. 初始乘积态选在**目标荷区**（如 Sz=0 的 Néel 型 `up/down/up/down...`），避免初态与目标荷不匹配。

**预期收益**：2~10×（TeNPy 常规经验），并同时改善 χ 收敛曲线。

**验收**（建议写进 `checks/`）：同一算例固定 χ=64/128/256，对比
（a）`conserve=None` vs `'Sz'` 的 E0 与 truncerr 随 sweep 的曲线；
（b）耗时曲线；两者 E0 应收敛到同一值（差异应只来自精度）。

---

### P0-2｜代价模型完全不认对称性（系统性盲点）

**现状**：`cost_mb.py` L7 开宗明义"**维度 `dim=2^N` 是唯一主约束**"，标定（L13/L15）也全部按 `dim` 与 `n_atoms`。

**影响**：凡走扇区/守恒的算例，代价被**系统性高估**：

| N | 2^N | C(N,⌊N/2⌋) | 高估倍数 |
|---|---|---|---|
| 20 | 1,048,576 | 184,756 | **5.7×** |
| 22 | 4,194,304 | 705,432 | 5.9× |
| 24 | 16,777,216 | 2,704,156 | **6.2×** |
| 30 | 1.07×10⁹ | 1.55×10⁸ | 6.9× |
| 40 | 1.1×10¹² | 1.38×10¹¹ | **8.0×** |

⇒ 会把**本来可行**的算例判为不可行（尤其 20 ≤ N ≤ 30 这一段）。

**改法**：代价函数接受 `sector`/`conserve` 标记，引入

```
sector_ratio(k) = C(N, k) / 2**N        # 扇区维占全空间的比例
```

并把 `dim_eff = dim × sector_ratio`（ED 的 Krylov/稠密档）与 `chi_eff = chi × f(conserve)`（DMRG 档，块稀疏的等效收益）
一并计入；缺省行为保持原样（不破坏现有标定）。

**验收**：取 3 个对称算例与 3 个非对称算例，预测耗时 vs 实测耗时的比值应落在 [0.5, 2]。

### P1-1｜扇区入口不统一（外部调用方会掉进全空间陷阱）

**现状**：
- `eq_route.py` 的 `want='gs'` **有** `sector=int`；
- 但 `equilibrium.py` L33 `def ground_state(H, dense_max=2048, seed=0, k=2, v0=None)` **没有** `sector` 参数，
  它只吃 `assemble.build_H_sparse` 出来的**全空间稀疏 H**，大维走 `eigsh`（L53-54）；
- `thermal` / `dos` / 传播路径也都不用扇区（文档已注明"sector 仅 'gs'"）。

**影响（我们实际踩到的）**：外部调用方（我们的 XY 生成器）自然会用 `equilibrium.ground_state`，
于是**只能在全空间建 CSR** ⇒ N=22 峰值 **7.8 GB**、N=24 需要约 **28 GB**（不可行）。
本库明明有扇区切片，却因为入口不在这里而用不上。

**改法**：
1. 给 `equilibrium.ground_state` 加 `sector=None, sector_labels=None` 参数，内部**复用** `eq_route` 的切片实现与守恒校验；
2. 把 `sector` 推广到 `thermal` / `dos`（至少给"仅在扇区内求迹/求和"的路径）；
3. 文档里把"哪些入口支持扇区"做成一张表（现在只有散文说明）。

**预期收益**：调用方**零改动**获得 5~8× 的内存/时间下降。

### P1-2｜缺 GPU 后端（本项建议单独排期，收益最大）

**现状**：整个多体层是 CPU——`scipy.sparse` + `numpy`，DMRG 是 TeNPy（CPU/BLAS）。
`grep` 全模块：**无 torch / cupy 后端**（0 处）。本项目实测 GPU 化后的量级差异见 §3。

建议按"改动量从低到高"分档实施：

**(a) 矩阵自由算子作用（收益最大、可增量、不用改算法）** ⭐ 优先
把"按耦合项用位运算/散射作用在态向量上"实现成 torch（或 cupy）核，态向量常驻显存，
**不构造 CSR**。扇区切片与之一拍即合（只在 C(n,k) 维上作用）。
- 我们实测（GPU、矩阵自由、扇区内 Lanczos）：**N=24 半填充，扇区维 1,307,504 ⇒ 47 秒/样本**；
  同问题显式 CSR ≈ 28 GB（不可行）。
- 建议接口：`engine_ed`/`eq_route` 增加 `backend='cpu' | 'gpu'`，语义完全不变，只换内核。

**(b) 小维稠密档上 GPU**
`dim ≤ ~2^16` 时稠密 `eigh` 走 `torch.linalg.eigh`，通常 5~20×。
- ⚠ 注意：`torch.linalg.eigh` 在三对角/退化矩阵上会报 `error code 81`（我们踩到过），
  需要"退化为 numpy.eigh ＋ 1e-9 对角抖动"的回退路径。

**(c) KPM / 谱函数 GPU 化** ⭐ 优先
KPM 天然是"矩阵-向量乘 ＋ 多项式展开"，无需求逆、无可变精度损失 ⇒ GPU 收益大且稳妥。
建议 `kpm.py` 作为 GPU 化的第二个目标。

**(d) 显存预算纪律（接口层强制）** ⭐ 优先
我们踩过的**原生崩溃**：一次物化 `R × 2^n` 的中间量（探针 R=120、M=2^20）⇒ **61 GB** ⇒
`c10.dll` 访问违例（`0xc0000005`，fault offset 恒定）。这是"接口不设预算"的典型后果。
- 建议：凡接受"多行负载"的入口（探针/批量传播/KPM 批量）都提供一个
  **`max_tensor_mb` 或"行×构型预算"** 参数，内部据此**自适应分块**（我们最终方案：
  `chunk = max(512, min(echunk, budget // rows))`，内存恒定，代价只是循环次数）。

**(e) 混合精度**
能量/本征矢用 float32 可省一半显存（生成训练数据只需 E0 收敛到 ~1e-3）。
- 建议：给 `dtype='float32'` 选项，**并附精度自检**（与 CPU float64 对比 E0 ≤1e-3、振幅重叠 ≥0.999）。

**(f) DMRG 的 GPU（长期项，不建议硬改）**
TeNPy 无 GPU；建议**不硬改**，而是：
- 短期：小 χ / 稠密场景提供 GPU 备用路径；
- 长期：若要 GPU-MPS，考虑独立后端或 `quimb` 之类，明确标注为实验性。

### P1-3｜对称性只用了 N_exc 这一半

**现状**：全模块只有"激发数守恒"（`sector`）＋ 守恒校验；**无平移（动量）扇区、无宇称扇区**。

**影响**：
- 周期环（平移不变）本可**再降 n 倍**；均匀场下还有 `k ↔ n−k`（粒子-空穴/自旋翻转）配对；
- 对开边界 + 格点无序的算例（我们的情况）这些用不上，所以**不伤我们**，但它是库的通用能力缺口。

**改法**：在 `assemble`/`runspec_mb` 里显式声明"该模型可用的对称性"，让 `eq_route` 消费（哪怕先只做动量分块）。

### P2-1｜没有自由费米子 / BdG 精确路径

**现状**：全模块无 `pfaffian` / `slater` / free-fermion / BdG（我们已 grep 确认）。
近邻 XY、1D 横场 Ising、Kitaev 链这些**本来就是二次型**的模型，目前会走 ED/DMRG，
而它们有 **O(N³) 精确解**（JW + N×N 对角化；振幅 = 行列式；|ψ|² = DPP 可多项式采样）。

**建议**：加 `want='gs', method='free_fermion'`，并明确适用判据：
- 适用：跳跃/配对二次型（近邻 XY、TFIM、Kitaev 链……）；
- **不适用**：长程 XX+YY（我们已实测：JW 串不相消 ⇒ 不是二次型，自由费米子解只在 k=1 扇区精确）。
- 收益：这类模型从"分钟~小时"变"毫秒"。

## 3. 与我们的实测对照（供定标参考）

| 场景 | CPU + 显式 CSR（现状路径） | GPU + 矩阵自由 + 扇区切片 |
|---|---|---|
| N=22 全空间生成一个基态 | 峰值 **~7.8 GB**，~1147 s/样本 | ~130 s/样本，~1 GB 显存 |
| **N=24 半填充（扇区维 1,307,504）** | 需约 **28 GB** ⇒ **不可行** | **47 秒/样本** ✓ |
| 扇区解的正确性 | — | 与全空间真值**振幅重叠 1.000000**（n=16 验收标准） |
| 分块预算缺省的后果 | 探针 R=120 × 2^20 一次物化 ⇒ **61 GB** ⇒ `c10.dll` 访问违例 | 按"行×构型预算"自适应分块 ⇒ 峰值降一个数量级 |

**另附一条"自检"经验**（支持把校验做成默认行为）：
我们最初用**自由费米子单粒子谱**估最优扇区，该估计**系统性偏低 1~2 格** ⇒ 造出**错误扇区**的"真值" ⇒
得出"模型在 N=24 完全崩塌（保真度全 0）"的**假结论**，浪费了一轮排查。
最后是靠"**同一配方跨尺寸一致性自检**"（n=19…24 全 0，而 n=20/22 明明正常）才抓住。
⇒ 与贵库 `_check_sector_conserving` / "非块对角则回退"是**同一种纪律**，建议把它推广为：
**凡"按某个守恒量做切片/筛选"的入口，默认先做一致性自检，并允许显式关闭。**

## 4. 建议的实施顺序（低风险 → 高收益）

1. **P0-2** 代价模型加对称因子（纯算式，零风险）
2. **P0-1** DMRG `conserve='Sz'` ＋ `total_charge` ＋ 初态（1~2 行 + 一处配置）
3. **P1-1** `equilibrium.ground_state` 加 `sector`（复用现成切片与校验）
4. **P1-2(a)** 矩阵自由 torch 后端（收益最大，可只覆盖 Krylov 类路径）
5. **P1-2(c)** KPM GPU 化
6. **P1-2(d)** 分块预算参数化（防原生崩溃）
7. **P2-1** 自由费米子/BdG 路径
8. 其余（P1-2(b)/(e)/(f)、P1-3、P2-2）

## 5. 验收清单（改完怎么证明变好了）

- **DMRG**：同算例 χ=64/128/256 的 E0 与 truncerr 曲线；开/关 `conserve` 的耗时比（期望 ≥2×，E0 一致）。
- **扇区**：与全空间解对比 E0 与**振幅重叠**（我们用的验收线：重叠 ≥0.99999，实测 1.000000）。
- **GPU**：与 CPU float64 对比 E0（≤1e-3）与振幅重叠（≥0.999）；记录峰值显存并断言 ≤ 预算。
- **cost 模型**：≥6 个算例（对称/非对称各半）的预测 vs 实测耗时比落在 [0.5, 2]。
