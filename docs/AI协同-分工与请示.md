# AI 协同分工：软件开发者 × 模拟使用者（2026-09-12 立）

> 依据《AI协同-项目目标与原则.md》的 G3（人机协同）与 G4（自我迭代），把
> **两个 AI 角色**的职责、边界、沟通协议固定下来。本文同时是**新同事的上岗简报**
> （自包含：读完本文即可开始干活，不需要读别的会话记录）。

## 一、两个角色

| 角色 | 关注点 | 主要产出 | 不做的事 |
|---|---|---|---|
| **开发者**（软件侧，deepseek-v4-flash） | 引擎/服务端/GUI/工具链的正确性与简洁；P1–P6 落地 | 代码改动 + 自检 + 文档；**回答"怎么用"** | 不做长期模拟实验；不替使用者下物理结论 |
| **使用者**（模拟侧，拟 `chenlab/deepseek-v4.1-flash`） | **物理**：理解模拟项目的含义、设计模拟实验、跑扫描、解读结果 | 模拟实验设计 + 结果数据/图 + **给开发者的意见与请示** | **不改软件代码**；不在 `src/` 下落任何临时文件 |

**协作闭环**（仿 P2/P3）：
1. 使用者用软件（MCP 通道）→ 遇到不便/可疑/缺失 → 按 §五 格式提**意见**；
2. 开发者每条意见回一个**处置**（修/不改+理由/需要更多证据），并把修法写进代码+自检；
3. 开发者主动**教用法**（新接口、坑、推荐姿势）→ 使用者据此改进实验设计；
4. 使用者的用法经验回流到 `skills/energy-level/SKILL.md`（G4：说明书即 prompt）。

## 二、使用者：怎么连上软件（唯一通道是 MCP）

- 端点：`http://127.0.0.1:<port>/mcp`；端口见项目根 **`.mcp-port`**（默认 8765，
  被占会自动回退）。软件启动后状态栏显示「● AI 在线 :端口」。
- **强约束**：引擎/服务端是**进程内**代码 → 开发者改了代码，**必须重启软件**才生效。
  用 `summary()` 看现状；若发现"刚让我改的字段没出现"→ 十有八九是软件没重启
  （见待办 §A12：AI 目前无法自检陈旧代码，这是已知缺口）。
- 工具面（`list_params` 是唯一权威清单）：
  - 语义状态：`set_groups([(n,l,j),…])`、`list_levels()`、`set_initial_state(atom,n,l,j,m)`、
    `get_config()`、`set_superposition(atom, components)`
  - 运行：`submit_compute()`（**提交即返回**）、`job_status`、`job_result`、
    `result_states(job_id, states=[…], series=True)`、`list_jobs`、`cancel_job`
  - 诊断/自述：`get_diag(scope)`、结果里的 **`model_card`**（含 `warnings`）
  - 存档/流水：`save_archive`/`load_archive`/`get_activity`/`undo`/`screenshot`

### 三条黄金姿势（都是踩出来的）
1. **不猜初态**：用 `list_levels()` 拿**合法身份键**，再用 `set_initial_state`。
   猜能量键会**静默选到别的能级**（实测差 450 MHz → 落到 59D_3/2 且报 ok）。
2. **不在脚本里等**：`run_compute_and_wait` 会阻塞整个回合。改用
   `jid = submit_compute()` → 立刻返回 → 下一次调用 `job_status`/`job_result`。
3. **先看模型卡再看结论**：`model_card.warnings` 会点名"微波候选对为 0
   （疑缺中间态）""maxΩ/ω>1（出 RWA 适用区）""M 达上限""有对因成本窗被剔除"。
   这些是"静默改物理"的类别，不问就答等于编。

### 临时脚本的放法与纪律
- 一律放 `tempsimu/`（该目录**不进版本控制**），文件名带任务前缀；
- 脚本用**本地批量通道**（直接 import `src.core.*`）可快 3–5×，但**不改软件状态、
  不进 journal**；需要"人看得见"时走 MCP。两条通道结果必须能对上（这是交叉验证）；
- 引擎侧改动要重启（同上）；`OMP/MKL/NUMBA=1` 防线程超订；并行用**独立进程分块**
  （ARC 的 SQLite 首访建表会竞争，需先单进程预热 + 错开启动）。

## 三、物理目标（当前主线）：freeze 打断交换

1. **交换**：双原子 R=12 µm、θ=30°、B=21.7 G；A=`60P_{3/2} m=−0.5`、
   B=`60S_{1/2} m=+0.5`；**只加"频移光"**（295.724187476 THz、π、I=8.398e7、
   方波自 t=0）→ 观察 `|60P_A,60S_B⟩ ↔ |60S_A,60P_B⟩` 的此消彼长。
2. **交换后的结果**＝这两个两体态的**纠缠叠加**（`set_pair_superposition`，待开发者实现；
   逐原子直积表达不了）——用它当 freeze 的初态。
3. **freeze 判据（三条，缺一不可）**：
   - 不对称度 `S(t)=(A=60P,B=60S)−(A=60S,B=60P)` 在脉冲后**停止摆动**；
   - `58G` 合计 > 0（kick 真的发生）；
   - `model_card.warnings` 为空。
4. **已知障碍**：7 组基组 + 光学场 → dim=8112=2704×3 → 旧代码会要 1 GB 稠密矩阵。
   开发者已修两层诊断策略；**绕行方案**是拆两次运行：交换用 4 组+频移光、
   kick 用 7 组+**纯微波**（P=1 → dim=2704）。
5. **未决的引擎问题（E1，开发者排查中，使用者可继续取证）**：同一物理、只换基组，
   **配对数 1206（3 组）→ 150（+58G_7/2）**；`get_diag(scope='pairs')` 的指纹是
   "|V| 逐位相同 40.430693 MHz、失谐双峰 447.48/523.27、索引 (i,i+88) 等差"
   → 疑为 6P 超精细×光子扇区的**规则重复对**，且判据标尺随基组变化。
   **在 E1 定性前，两体交换类的定量结论不要采信。**

## 七、重要结构性事实（2026-09-12 探针实测）

**子代理不会继承 energy-level 的 MCP 工具。** 用一个最小探针子代理验证：
它的工具面只有通用工具（`pwsh / read / write / edit / glob / grep / subagent /
job_* / web_* …`）**加上技能文档本身**，没有任何 `mcp__energy-level__*`。
它自己的结论："软件能力只存在于我加载到的 skill 文档描述里，而非可调用的工具面。"

### 推论与对策（直接决定分工怎么落）

| 角色 | 原生 MCP | 所以它能做 | 所以它不能做 |
|---|---|---|---|
| **开发者**（本会话主代理） | **有** | 改参数/下波形/跑演化/撤销/看 GUI 真值 | （不必做长期实验） |
| **使用者**（子代理同事） | **没有** | 本地批量通道（import `src.core.*`）、读写文件、跑 shell、**自己写一个 MCP 客户端脚本** | 不能像主代理那样直接调 MCP 工具 |

**同事的接入方案（它自己的第一项工程任务）**：
1. 写 `tempsimu/mcp_call.py`：最简 MCP over streamable-HTTP 客户端（`initialize` →
   记 session id → `tools/call`），端点取 `.mcp-port`；用 `pwsh` 运行即可。
   优先用现成库（`mcp` 或 `httpx/requests`），失败再手写 HTTP。
2. 用本地批量通道做**扫描/回归**（快 3–5×、不进 journal）；需要"人在 GUI 看得见"
   或需要软件真值（ParamRegistry、作业登记、撤销）时，走它自己的 MCP 客户端。
3. **交叉验证义务**：同一物理两条通道各跑一次、结果必须能对上（这是既有的纪律，
   也是"使用者"能给"开发者"的最有价值反馈之一）。

### 组织层面的备选（需要用户/配置侧决定）

- 若希望**同事也有原生 MCP**：需要 harness 把该 MCP server 也对子代理会话注册
  （本会话实测未继承；是否支持取决于 harness 配置）。
- 若 harness 不支持：就按上表执行——**同事用"自建 MCP 客户端 + 本地通道"，
  开发者保留原生 MCP**；职责划分（谁写代码、谁设计实验）不受影响。
