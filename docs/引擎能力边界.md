 # 引擎能力边界
 
 本文帮助使用者选择 Energy Level 的计算路径，并说明结果需要怎样解释。边界由体系规模、场类型、频率尺度、耗散、时间范围和所需观测共同决定。
 
 ## 1. 选择顺序
 
 1. 明确原子态、体系规模和初态；
 2. 明确外场、频率、极化和时间范围；
 3. 先运行 preview 检查输入和适用条件；
 4. 使用 estimate 评估维度、内存和时间；
 5. 选择路径并保存运行规格；
 6. 对关键结论用更高精度或参考路径核对。
 
 ## 2. 路径特征
 
 | 路径 | 适合 | 主要代价 |
 |---|---|---|
 | reference | 小体系、验证其它路径 | 维度和时间成本高 |
 | RWA | 满足旋转波和频率分离的驱动 | 依赖近似条件 |
 | mixed | 不同频率/耦合尺度需要分层处理 | 参数选择和诊断更复杂 |
 | two-field | 光场与微波场共同作用 | 场分解和带宽控制 |
 | ED | 小到中等多体 Hilbert 空间 | 内存随维度快速增长 |
 | DMRG | 可利用低纠缠结构的体系 | 需要合适的链和截断 |
 | KPM | 谱和大稀疏系统的统计量 | 结果是近似展开 |
 
 ## 3. 结果必须带的上下文
 
 - 使用的路径和 backend；
 - 状态数、截断和相互作用范围；
 - 时间网格、容限和最大步长；
 - 外场规格和初态；
 - 近似条件、诊断和警告；
 - 是否使用 GPU、分块或缓存；
 - 是否为部分完成或取消的结果。
 
 ## 4. 不应做的推断
 
 估算时间不是物理结论。单次运行的数值稳定不等于模型近似成立。较高分辨率不自动意味着更准确；应结合 reference、收敛性和误差指标解释。
 
 ## 5. 开发者更新要求
 
 增加或修改求解路径时，同步更新参数 schema、preview/estimate 的诊断、用户手册和最小对照测试。文档只描述当前可用能力，具体字段以运行时查询为准。
