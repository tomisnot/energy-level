## 0. 三句话结论

1. **物理接口是好的**：核心入口是"状态列表 + 场 + 初态 + 时间网格"的纯函数，与 GUI 无关；
   而且**纯微波场景下引擎是精确的**（见 §5.3），脚本可以放心用。
2. **工程外壳不好**：基组装配只存在于 GUI、没有扫描抽象、并行会被 ARC 的建表竞争打死、
   入口签名/容器不统一。我因此重复了 ~5 段基组装配、写了 4 套 chunk+merge+plot。
3. **多原子**：**两体引擎已全**（4 个 `*_pair`）；**三体及以上零脚手架**。若目标只是
   **微波/V_dd 主导的多体**（freeze/swap 这类无光学场），改动**不大**（新装配层，几百行，
   不动积分器）；若要**同时有光学场**，难点在 `_MixedSetup` 的光子块要"全局化"（见 §4.3）。

## 2. 实测摩擦点（都有证据，不是感觉）

| # | 现象 | 证据 | 代价 |
|---|---|---|---|
| 1 | **基组装配只在 GUI**：要复刻 `ui_dynamic._current_states`（超精细 else mJ + Zeeman + DC Stark） | 我在 ≥5 个脚本里复制了同一段 ~20 行 | 重复代码 + 与 GUI 漂移风险 |
| 2 | **没有扫描/归并/绘图抽象** | 写了 4 套 `*_chunk` + `*_merge`；每个脚本自己写按流形归并 `agg()` | 每轮 100–150 行样板 |
| 3 | **每频点重建场**：`build_fields_exact` 的 A 矩阵**与 ω 无关**（只有 `omega_L_mhz` 变） | 手动 `fld[0]['omega_L_mhz'] = om` 后，122 次运行 148 s；走 app 逐点约 4 s/点 ≈ 8 min | 差 3–5×，且该技巧无文档 |
| 4 | **ARC 首次访问会 DROP/CREATE `literatureDME`** → 并发建表竞争 | 直接起 14 进程：**只成 1/14**（`sqlite3.OperationalError: database is locked`）；先单进程预热 + 错开 3 s → **14/14** | 并行不可用，除非自己写预热 |
| 5 | **不支持的组合静默降级** | 波形 `pol='椭圆偏'` 时 `q=_POL_Q.get(pol,0)` → **按 π 算**（t85 已修） | 静默错物理，最难查 |
| 6 | **入口签名/容器不统一** | `tol` vs `rtol/atol`；`fields`(list) vs `fields_meta`(dict)；pair 版要**两套场** | 通用驱动器必须逐引擎特判（`route.py`/`evolve_worker.py` 里全是分支） |
| 7 | 只能用私有名 | `core._sublevel_energy`、`_POL_Q`、`_MixedSetup`、`_P.get` | 脚本脆，重构即碎 |
| 8 | **没有引擎级质量报告** | max Ω/ω（模型是否越界）、`N_eff=1/Σp²`、`nfev`、‖ψ‖漂移，都得自己算 | 每个脚本重算；"是否可信"靠人判断 |
| 9 | 进度只有 3 元 `progress_arr`（GUI 协议） | headless 无回调/迭代器 | 长扫描只能靠 print |

## 3. 优化建议（按性价比排序，均含验收标准）

### S1 把基组装配搬进 core（最值）
```python
st = core.build_states(cache, groups, B=21.7, E_vpcm=0.0)   # 单一真源
# 每个 state 带：n,l,j,m,kind,E_mhz,label,manifold
```
- 涉及：新增 `src/core/basis.py`（或并入 `atomic_levels.py`）；`ui_dynamic._current_states` 改为调用它。
- 验收：新增 `checks/basis_assembly_test.py`，同一配置下与**改前**的 `_current_states` 输出**逐位一致**；脚本侧不再出现超精细/DC-Stark 复刻代码。

### S2 一个 `sweep` + 结果对象
```python
res = core.sweep(st, engine='mixed', waves=[w], psi0=('60P_1/2', -0.5),
                 freqs=(7350, 7650, 2), t_max=120, npts=2401,
                 hoist_field=True,      # A 矩阵只建一次（把摩擦点 3 官方化）
                 parallel=14)           # 内置 ARC 预热+错开（把摩擦点 4 封装掉）
res.by_manifold()       # 归并布居（消灭摩擦点 2 的重复）
res.quality()           # maxΩ/ω、N_eff、nfev、‖ψ‖漂移（消灭摩擦点 8）
res.to_npz(path)        # 统一落盘
```
- 涉及：新增 `src/core/sweep.py`（依赖 `multiprocessing`，需先修 S5）。
- 验收：用 `core.sweep` 复现本轮 `final_chunk`+`final_merge` 的 npz（≤1e-12）；调用方代码从 ~150 行降到 ≤20 行；16 核上 ≥10× 加速。

### S3 统一入口签名与容器
- `tol/atol` 二选一（建议全局 `rtol/atol`，`tol` 作兼容别名）；场容器统一 `fields`（`fields_meta` 降为内部）；pair 用 `fields_by_atom=[fA, fB]`，为 N 体铺路。
- 验收：`route.py` / `evolve_worker.py` 的引擎分支显著收缩；现有自检全绿。

### S4 校验代替静默（沿 t85 的做法）
- 不支持/越界就**明确报错或 warn**：椭偏缺参数、`Ω/ω ≫ 1`（提示"已出 RWA 适用区，建议 hard/两场"）、t 网格过粗（提示欠采样）。
- 验收：故意构造越界配置时**看得见原因**，不再出现"数值可信、物理可疑"的静默结果。

### S5 ARC 首访建表加锁/幂等
- 目标：不做预热、直接并发也 14/14。
- 涉及：`core` 里 `ArcCache`/ARC 数据初始化处（`scripts/setup_arcdata.py` 同源）。
- 验收：无预热 + 14 进程并发全成功；`multiprocessing.Pool` 可直接用（沙箱禁命名管道是环境问题，另记）。

### S6 公共分析小工具
- 落盘 + 双栏/多栏对齐绘图模板（本会话重写 4 次）；CSV/npz 约定。
- 建议位置：`src/analysis/`（或 `scripts/` 模板），不进 `src/core/`。

## 4. 多原子扩展评估

### 4.1 现状
- **两体已全**：`evolve_mixed_pair` / `evolve_sambe_pair` / `evolve_hard_pair` / `evolve_two_field_pair`，
  走 `vdd_matrix`（N²×N² 稀疏/稠密）或 `R_um/theta_deg`+cache 现算；`static_pair.py` 有完整 V_dd 机制。
- **三体及以上：全项目零脚手架**（`atom3|chain|lattice|N_atom` 全部搜不到）。

### 4.2 微波/V_dd 主导的多体（无光学场）→ 改动不大
依据（本轮实测）：纯微波时 **P=1、AC 化 0 态、`dim`=全基组、无 M 截断**，引擎退化为
"全基组 + 实验室系精确积分"。因此多体只需**新装配层**：

1. `build_natom_basis(states, n_atoms, …)`：张量积 / 对称约化。**维度是主要约束**（38ⁿ：38³≈5.5万、
   38⁴≈210万）→ 需单激发子空间、平移对称或距离截断；
2. `assemble_H(...)`：单体块（复用每原子的 `A`）+ **按对求和** `vdd_sparse`（稀疏 + 距离截断）；
3. 观测量：逐原子布居、⟨nᵢnⱼ⟩ 关联、熵 / `N_eff`（热化研究正需要）。

**不动的部分**：`dop853.py`、耗散（`decays`）、`field_build.py`、选择定则 / 偶极 / 静力学。
粗估：**一个新模块几百行 + 自检**。

### 4.3 若同时要光学场 → 明显变大
`_MixedSetup` 的光子块 / φ-帧假设**一个原子索引空间**；N 个原子共享一个光场时，
**光子块是全局的**，`P/M` 记账必须泛化。这是设计上最需要先想清楚的一处，别在实现里临时打补丁。

### 4.4 建议的接缝（一次到位，顺带消掉 S3 的分支）
```python
evolve_mixed(states, fields_by_atom, psi0, t, interactions=[(0, 1, V01), (0, 2, V02), …])
# 单原子 = interactions=[]；两体 = 一项；N 体 = 多项 —— 一套代码路径
```

### 4.5 工作量与风险
| 目标 | 改动 | 风险 |
|---|---|---|
| 单体/两体 API 统一（S3+4.4） | 中 | 触及全部引擎签名 → 需现有自检兜底 |
| 微波多体（N≥3） | 小—中（新模块） | 维度爆炸、关联观测量定义 |
| 微波+光学多体 | 大 | 光子块全局化（4.3） |

## 5. 复用经验规则（写脚本时别忘）

1. **不要追单点尖峰**（用户 2026-09-11 的判据）：布居随时间/参数剧烈抖动时，
   单点取值会长毛刺。用**包络** `(maxₜ−minₜ)/2`、时间平均或"粗阶梯上的整体最优"，
   并同时给一个**对照量**（如 `mean_T`）判断 min 是否为孤立尖刺。
   —— 本会话踩过两次：先是单点 P_end，后是"在 4 档脉宽里取 min"，后者造出一列**假梳齿**。
2. **场 hoist**：`build_fields_exact` 的 A 与 ω 无关，扫频只改 `omega_L_mhz`（摩擦点 3）。
3. **并行**：独立进程分块 + 各自落盘 + 合并（绕开 ARC 竞争与沙箱管道限制）；
   启动顺序：**先 `-1` 预热，再错开 3 s**。
4. **纯微波 ⇒ 结果可信**：`P=1`、无 AC 化、无 M 截断（`audit_trunc.py` 实测日志，
   该脚本已随草稿区清理归档）。
   反之若加光学场，必须重新审 AC 化/R_CRIT 与 M 截断的影响。
5. **模型边界要报出来**：`max|Ω|/ω` 是硬指标。1000 mW/cm² 时实测 **Ω/ω=15.5 ≫ R_CRIT=0.0135**，
   那种强度下数值收敛但物理存疑；打印这个比值应当成为习惯。
6. **多光子通道要求中间态在基组里**（2026-09-12 实测踩坑）：引擎的多光子耦合是由**基组内真实的
   单光子矩阵元串起来的**。若想做 60P→58G 的三光子踢出，基组里必须有 59D（≈10.2 GHz）与
   58F（≈11.2 GHz）作为中间态；只放 `60P/58G` 时**60P 到 58G 之间根本没有单光子矩阵元可串**，
   于是"频率对、强度对，却一点都踢不动"（实测：freeze 脉冲打上去，58G 布居一个都没有）。
   → 别把"基组裁剪"当成纯提速手段，先确认目标跃迁的中间态在不在。
   → 建议在 S4 里加一条校验：给定基组与目标跃迁，若缺少达到该跃迁所需的中间态，**明确警告**。
8. **离线批量通道的基组必须与"登记册"同源，否则结论会静默分叉**（2026-09-12 使用者发现）：
   `scripts/tmp/contrast_scan.py` / `dual_scan.py`（已随草稿区清理归档）用
   `make_levels(..., kind='mJ')` 对**所有**组展开
   （6P 当 4 个 mJ 态 → 68 态）；软件登记册把 6P_3/2 展开成 **16 个 (F,m_F)** 态（N=84）。
   本次两条通道 **4 位小数吻合**（`C=0.9982`、60S 保留 0.9994），但那是碰巧——
   6P 在 296 THz 外、纯 AC Stark 贡献可忽略。**换个场景就会静默分叉。**
   → 离线脚本要么走 S1 的 `core.build_states`（单一真源），要么在脚本头**显式声明基组差异**。
7. **两体运行的成本量级**（2026-09-12 实测，用于估时）：`N=36 态 → 1296 两体态` 时
   `nfev≈4.3e5`、`dt_ns≈0.002`（被 GHz 载波钉住）、**单次 ≈2 分钟**；
   `N=48（加 59D/58F/58G_9/2）→ 2304 两体态 + 光学场（光子块 P>1）` 单次已足以把
   MCP 传输层打穿（`fetch failed` / `-32001`）。**两体 + 光学场的窗口要开短（≤200 ns、npts≈101）**，
   或者必须走 `run_python_async`。

## 8. S7：分时截断与拼接（时变阈值提速）

> 用户 2026-09-12 提出："电磁场是时变的，阈值按哪个时刻截断？能不能每个时刻用不同截断、再拼接起来提速？"

### 8.1 现状：阈值只算一次，键在"峰值 + 总时长 T"

| 判据 | 代码位置 | 键在什么上 |
|---|---|---|
| 成本窗 `ΔD_max = PHASE_BUDGET/(C·T)` | `coupling.py:91 mw_cap_mhz(T_ns,…)`，调用 `evolve_mixed.py:208` | **总时长 T**（`_MixedSetup.T = t_end_ns`，`:205`） |
| 精度判据 `Θ = C·T·Ω²/max(Ω,Δ) ≥ PHASE_TOL` | `coupling.py:128`（`mw_candidate_mask`） | **总时长 T × 峰值 Ω** |
| AC 化 `r = Ω/ω ≤ R_CRIT` | `evolve_mixed.py:34 classify_pairs(A, ω, r_crit)` | **峰值场幅度 A**（与 t 无关） |
| `near_cutoff` / `bw_opt` / `MW_MAX_MHZ` | `params.py`、`evolve_mixed.py:208-211` | 静态过滤，与 t 无关 |

`setup = _MixedSetup(...)` 每次 `evolve_mixed` **只构造一次**（`:409`），随后
`dop853_driver_mixed(X0, t, T, …)` 把整条时间网格一次积完（`:479`）——**积分过程中不重估任何判据**；
包络的时间依赖只进 ODE 系数，不进"保留哪些对"。

- **为什么必须这样**：ODE 右端要是固定结构的哈密顿量（固定对集 / φ-帧 / 态序），
  否则自适应误差控制与归一化记账都失效。
- **代价（本设想的动机）**：判据保守 —— `Θ ∝ T`、窗宽 `∝ 1/T`，
  所以"长窗口里只有一小段有脉冲"时，保留的对**远多于任何瞬时所需**。

### 8.2 设想的正确性四条件

1. 段 k+1 的子空间必须包含切换时刻**所有有布居的态**（被丢补空间布居 < ε）；
2. 被丢耦合在**该段内**的相位误差 < 容差 —— 即把判据里的 T 换成段长 Δt（`Θ = C·Δt·Ω²/max(Ω,Δ) ≥ PHASE_TOL`），**提速就来自这里**；
3. φ-帧 / 光子块逐段重建并变换 ψ：光学场开关会改变 P/M 与态空间维数；
   "场关掉足够久、光子扇区回到真空"时，到原子维的映射就是**精确投影**（`sector_sum_amp`，`evolve_mixed.py:1074`）；
4. 段数别太多（每段都有 setup 开销，配对分类 + AC 化 + 光子块是秒级）；边界划在**包络很小处**（脉冲尾巴），不要划在脉冲中间。

### 8.3 三步落地

1. **零引擎改动先验证**：`evolve_*` 返回值里有 `psi_amp`，脚本可"跑段 1 → 取 `psi_amp` → 作段 2 初态 → …"。
   在 freeze 场景做 **1 段 vs 3 段（关/开/关）vs 5 段**，比末态布居与耗时；
2. 若末态差 <1e-3 而耗时降 5–10×，再加显式 API `segments=[(t0,t1,opts),…]`：
   内部逐段重建 `_MixedSetup`（T = 段长、Ω = 段内峰值），边界做**布居泄漏 + 范数 + 帧变换**检查，
   并把每段 `nfev / 步数 / 丢弃对数` 记进 `get_diag`；
3. 验收：与单段全跑末态差 ≤1e-3；给出耗时降幅；每段泄漏 ≤1e-6。

### 8.4 风险（别当成普适 10×）

- 拼接误差**不受积分器容差保护**：跨段投影/丢态是人为的，误差系统性累积，尤其"某态在段内被慢慢布居却一直被截掉"时不会触发任何告警；
- 只对**低占空比**脉冲划算。若场几乎全程强开（例如"频移光从 t=0 常开"），可省的段本就不多，分段还可能丢掉段内慢积累的弱耦合 → **先量占空比再决定**。

## 10. freeze kick 的"平坦性"问题：窄三光子共振与候选路线（2026-09-12 使用者实测）

> 与 E1 是**两条独立的线**：E1 是"配对筛选对基组不稳定"（引擎问题，T2 在做）；
> 本节是"kick 本身是个窄共振"（**物理**，不是缺陷）。两者都会让"结果抖动"，
> 但一个要修、一个要给交付条件。

### 10.1 定性：**物理**（不是数值伪结构）
同一 ω 下变 `tol`(1e-7/1e-9) 与 `npts`(1501/3001)：`C` 极差 **3×10⁻⁷~6×10⁻⁷**，
比 5 MHz 步长引起的 ~0.15 **小六个数量级**。工作点 (7380 MHz, I=5) 的 ±1% 平坦区
只有 **1/45** 格点；相邻 5 MHz 摆 ±0.15；**而 60S 保留单调平滑**
（0.922→0.981→0.997→0.9996→1.0000）→ 精细结构出在**踢出**那一路。

### 10.2 机制（使用者离线裸共振表）
- 60P_{3/2} 两个 m 态经 3 光子到 58G 各子能级的**裸共振**在 **7219–7347 MHz**；
- 同一 J 内相邻子能级间隔/3 ≈ **9–11 MHz** ⟷ 实测峰间隔（7380 与 7390 = 10 MHz）
  以及"5 MHz 就换一个峰"完全对上；
- 实测峰整体比裸共振**高约 +40 MHz**（I=5 的 AC Stark 位移）
  ⇒ **不能按裸共振布点，必须扫**。
- 共振宽 ≈ 1/(3τ) ≈ **4 MHz**（τ = FWHM 40 ns，三光子过程 ⇒ 线宽/3）。

### 10.3 交付条件（由此推出）
1. **必须给频率精度要求（~1–2 MHz 级）**——工作点是窄三光子共振，
   频率抖动本来就会改结果，"结果抖动"不是 bug；
2. "**参数抖动平坦**"在当前方案下**不成立**，需要另找平台点或改宽带方案（10.4）。

### 10.4 平坦化路线（使用者已否掉一条）
- ❌ **纯圆偏振不行**（使用者扫 ω=7300–7420 步 5，τ=40 ns、I=5，纠缠态口径）：
  **σ+ 全窗口 `C_ent ≤ 0.42`**（多数 0.0–0.3，甚至为负）→ 踢不动。
  机理：椭圆偏（σ± 等权）能同时驱动 Δm=0,±1,±2,±3 多条路径、覆盖多个 58G 子能级，
  故踢得干净；纯 σ± 只剩**单条** Δm=±3 路径，而每个圆分量只有总场强的 1/√2，
  三光子振幅 ∝ (1/√2)³ ⇒ 概率掉到 ~0.12 量级，同强度下补不回来
  （提强度则 60S 开始损伤：I≥5.5 时保留掉到 0.73–0.94）。
- ✅ ① 接受窄共振 + 给频率精度要求（10.3）；
- ⚠ ② 更短脉冲（τ↓ → 带宽↑），但要更高 I，**有 60S 损伤风险**（I≥5.5 已见 0.73–0.94）；
- ⭐ ③ **啁啾/绝热脉冲**（使用者倾向）：扫频 ⇒ 天然宽带、对频率不敏感。
  **通道已就绪**：微波**任意波形（完整时域驱动）** 由 `hard` 引擎直接支持，
  `sambe`/`mixed` 遇它会自动改道 `hard`（见 SKILL「波形格式」一节）；
  ⚠ 但任意波形不经 `set_waves` 提供，需走存档 —— 若真要上这条路，
  开发者可考虑给 AI/脚本一个显式入口（新登记项或 `set_waves` 扩展），**等用户口径**。
- ⏸ 路线选择**等用户裁决**（使用者原话：倾向 ③，但那是新设计）。
