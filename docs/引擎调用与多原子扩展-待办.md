## 0. 三句话结论

1. **物理接口是好的**：核心入口是"状态列表 + 场 + 初态 + 时间网格"的纯函数，与 GUI 无关；
   而且**纯微波场景下引擎是精确的**（见 §5.3），脚本可以放心用。
2. **工程外壳不好**：基组装配只存在于 GUI、没有扫描抽象、并行会被 ARC 的建表竞争打死、
   入口签名/容器不统一。我因此重复了 ~5 段基组装配、写了 4 套 chunk+merge+plot。
3. **多原子**：**两体引擎已全**（4 个 `*_pair`）；**三体及以上零脚手架**。若目标只是
   **微波/V_dd 主导的多体**（freeze/swap 这类无光学场），改动**不大**（新装配层，几百行，
   不动积分器）；若要**同时有光学场**，难点在 `_MixedSetup` 的光子块要"全局化"（见 §4.3）。

## 2. 实测摩擦点（都有证据，不是感觉）

| # | 现象 | 证据 | 代价 |
|---|---|---|---|
| 1 | **基组装配只在 GUI**：要复刻 `ui_dynamic._current_states`（超精细 else mJ + Zeeman + DC Stark） | 我在 ≥5 个脚本里复制了同一段 ~20 行 | 重复代码 + 与 GUI 漂移风险 |
| 2 | **没有扫描/归并/绘图抽象** | 写了 4 套 `*_chunk` + `*_merge`；每个脚本自己写按流形归并 `agg()` | 每轮 100–150 行样板 |
| 3 | **每频点重建场**：`build_fields_exact` 的 A 矩阵**与 ω 无关**（只有 `omega_L_mhz` 变） | 手动 `fld[0]['omega_L_mhz'] = om` 后，122 次运行 148 s；走 app 逐点约 4 s/点 ≈ 8 min | 差 3–5×，且该技巧无文档 |
| 4 | **ARC 首次访问会 DROP/CREATE `literatureDME`** → 并发建表竞争 | 直接起 14 进程：**只成 1/14**（`sqlite3.OperationalError: database is locked`）；先单进程预热 + 错开 3 s → **14/14** | 并行不可用，除非自己写预热 |
| 5 | **不支持的组合静默降级** | 波形 `pol='椭圆偏'` 时 `q=_POL_Q.get(pol,0)` → **按 π 算**（t85 已修） | 静默错物理，最难查 |
| 6 | **入口签名/容器不统一** | `tol` vs `rtol/atol`；`fields`(list) vs `fields_meta`(dict)；pair 版要**两套场** | 通用驱动器必须逐引擎特判（`route.py`/`evolve_worker.py` 里全是分支） |
| 7 | 只能用私有名 | `core._sublevel_energy`、`_POL_Q`、`_MixedSetup`、`_P.get` | 脚本脆，重构即碎 |
| 8 | **没有引擎级质量报告** | max Ω/ω（模型是否越界）、`N_eff=1/Σp²`、`nfev`、‖ψ‖漂移，都得自己算 | 每个脚本重算；"是否可信"靠人判断 |
| 9 | 进度只有 3 元 `progress_arr`（GUI 协议） | headless 无回调/迭代器 | 长扫描只能靠 print |

## 3. 优化建议（按性价比排序，均含验收标准）

### S1 把基组装配搬进 core（最值）
```python
st = core.build_states(cache, groups, B=21.7, E_vpcm=0.0)   # 单一真源
# 每个 state 带：n,l,j,m,kind,E_mhz,label,manifold
```
- 涉及：新增 `src/core/basis.py`（或并入 `atomic_levels.py`）；`ui_dynamic._current_states` 改为调用它。
- 验收：新增 `checks/basis_assembly_test.py`，同一配置下与**改前**的 `_current_states` 输出**逐位一致**；脚本侧不再出现超精细/DC-Stark 复刻代码。

### S2 一个 `sweep` + 结果对象
```python
res = core.sweep(st, engine='mixed', waves=[w], psi0=('60P_1/2', -0.5),
                 freqs=(7350, 7650, 2), t_max=120, npts=2401,
                 hoist_field=True,      # A 矩阵只建一次（把摩擦点 3 官方化）
                 parallel=14)           # 内置 ARC 预热+错开（把摩擦点 4 封装掉）
res.by_manifold()       # 归并布居（消灭摩擦点 2 的重复）
res.quality()           # maxΩ/ω、N_eff、nfev、‖ψ‖漂移（消灭摩擦点 8）
res.to_npz(path)        # 统一落盘
```
- 涉及：新增 `src/core/sweep.py`（依赖 `multiprocessing`，需先修 S5）。
- 验收：用 `core.sweep` 复现本轮 `final_chunk`+`final_merge` 的 npz（≤1e-12）；调用方代码从 ~150 行降到 ≤20 行；16 核上 ≥10× 加速。

### S3 统一入口签名与容器
- `tol/atol` 二选一（建议全局 `rtol/atol`，`tol` 作兼容别名）；场容器统一 `fields`（`fields_meta` 降为内部）；pair 用 `fields_by_atom=[fA, fB]`，为 N 体铺路。
- 验收：`route.py` / `evolve_worker.py` 的引擎分支显著收缩；现有自检全绿。

### S4 校验代替静默（沿 t85 的做法）
- 不支持/越界就**明确报错或 warn**：椭偏缺参数、`Ω/ω ≫ 1`（提示"已出 RWA 适用区，建议 hard/两场"）、t 网格过粗（提示欠采样）。
- 验收：故意构造越界配置时**看得见原因**，不再出现"数值可信、物理可疑"的静默结果。

### S5 ARC 首访建表加锁/幂等
- 目标：不做预热、直接并发也 14/14。
- 涉及：`core` 里 `ArcCache`/ARC 数据初始化处（`scripts/setup_arcdata.py` 同源）。
- 验收：无预热 + 14 进程并发全成功；`multiprocessing.Pool` 可直接用（沙箱禁命名管道是环境问题，另记）。

### S6 公共分析小工具
- 落盘 + 双栏/多栏对齐绘图模板（本会话重写 4 次）；CSV/npz 约定。
- 建议位置：`src/analysis/`（或 `scripts/` 模板），不进 `src/core/`。

## 4. 多原子扩展评估

### 4.1 现状
- **两体已全**：`evolve_mixed_pair` / `evolve_sambe_pair` / `evolve_hard_pair` / `evolve_two_field_pair`，
  走 `vdd_matrix`（N²×N² 稀疏/稠密）或 `R_um/theta_deg`+cache 现算；`static_pair.py` 有完整 V_dd 机制。
- **三体及以上：全项目零脚手架**（`atom3|chain|lattice|N_atom` 全部搜不到）。

### 4.2 微波/V_dd 主导的多体（无光学场）→ 改动不大
依据（本轮实测）：纯微波时 **P=1、AC 化 0 态、`dim`=全基组、无 M 截断**，引擎退化为
"全基组 + 实验室系精确积分"。因此多体只需**新装配层**：

1. `build_natom_basis(states, n_atoms, …)`：张量积 / 对称约化。**维度是主要约束**（38ⁿ：38³≈5.5万、
   38⁴≈210万）→ 需单激发子空间、平移对称或距离截断；
2. `assemble_H(...)`：单体块（复用每原子的 `A`）+ **按对求和** `vdd_sparse`（稀疏 + 距离截断）；
3. 观测量：逐原子布居、⟨nᵢnⱼ⟩ 关联、熵 / `N_eff`（热化研究正需要）。

**不动的部分**：`dop853.py`、耗散（`decays`）、`field_build.py`、选择定则 / 偶极 / 静力学。
粗估：**一个新模块几百行 + 自检**。

### 4.3 若同时要光学场 → 明显变大
`_MixedSetup` 的光子块 / φ-帧假设**一个原子索引空间**；N 个原子共享一个光场时，
**光子块是全局的**，`P/M` 记账必须泛化。这是设计上最需要先想清楚的一处，别在实现里临时打补丁。

### 4.4 建议的接缝（一次到位，顺带消掉 S3 的分支）
```python
evolve_mixed(states, fields_by_atom, psi0, t, interactions=[(0, 1, V01), (0, 2, V02), …])
# 单原子 = interactions=[]；两体 = 一项；N 体 = 多项 —— 一套代码路径
```

### 4.5 工作量与风险
| 目标 | 改动 | 风险 |
|---|---|---|
| 单体/两体 API 统一（S3+4.4） | 中 | 触及全部引擎签名 → 需现有自检兜底 |
| 微波多体（N≥3） | 小—中（新模块） | 维度爆炸、关联观测量定义 |
| 微波+光学多体 | 大 | 光子块全局化（4.3） |

## 5. 复用经验规则（写脚本时别忘）

1. **不要追单点尖峰**（用户 2026-09-11 的判据）：布居随时间/参数剧烈抖动时，
   单点取值会长毛刺。用**包络** `(maxₜ−minₜ)/2`、时间平均或"粗阶梯上的整体最优"，
   并同时给一个**对照量**（如 `mean_T`）判断 min 是否为孤立尖刺。
   —— 本会话踩过两次：先是单点 P_end，后是"在 4 档脉宽里取 min"，后者造出一列**假梳齿**。
2. **场 hoist**：`build_fields_exact` 的 A 与 ω 无关，扫频只改 `omega_L_mhz`（摩擦点 3）。
3. **并行**：独立进程分块 + 各自落盘 + 合并（绕开 ARC 竞争与沙箱管道限制）；
   启动顺序：**先 `-1` 预热，再错开 3 s**。
4. **纯微波 ⇒ 结果可信**：`P=1`、无 AC 化、无 M 截断（`audit_trunc.py` 实测日志）。
   反之若加光学场，必须重新审 AC 化/R_CRIT 与 M 截断的影响。
5. **模型边界要报出来**：`max|Ω|/ω` 是硬指标。1000 mW/cm² 时实测 **Ω/ω=15.5 ≫ R_CRIT=0.0135**，
   那种强度下数值收敛但物理存疑；打印这个比值应当成为习惯。
