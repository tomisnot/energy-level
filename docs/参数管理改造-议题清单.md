## 0. 模式切换架构规范化 ✅ 方向已定（2026-09-10，用户方案）

- 三轴分离：真值源（registry，与切换无关）/ UI 组织（各切换用各自最简单
  手段，不做统一总线）/ 登记时机（**登记跟真值源走，不跟显隐走**——
  建控件处就地登记，模式只 setVisible，注册面永远全量）；
- ①静态/动态：不动（共享的是数据，组件各自独立，无真值源问题）；
- ②单/双原子：✅ 已做（2026-09-10）——wave_panel/wave_panel_A 拆独立实例，
  `_place_shared_waves` 已删，切换纯显隐；serialize/restore v3 三面板独立
  + v2 旧档 A 数据自 waves 回填兼容；拖放接力：波形拖到「双原子」钮 =
  单原子全部深拷贝进原子 A 并切模式（同 MIME 机制）；ui_selftest 58/58；
- ③上帝模式：**t82 改判**——原为"先不纳入注册（不入册不存档）"，
  现改为**入册**：模式开关升级为"凌驾各页的界面模式"（菜单栏行分段钮，
  见 app_entry.set_mode），而**引擎参数**（`src/core/params.py` 的 SPECS）
  登记为 `engine.*`（`pm_setup._reg_engine_params`）——理由与议题 0 的
  三轴分离一致：**登记跟真值源走，不跟显隐走**，极简模式下照样在册、
  照样生效；顺带让 AI 经 `set_param` 自动可及（AI 可及面 = 在册面）。
  设计见《上帝模式-AI接入设计.md》。代价：引擎参数进入 v3 存档
  （"登记即存档"），即算例会带走它——视为可复现性收益。
- 与参数管理的矛盾消解：登记不看模式 → 无"隐藏参数存不存"问题。
