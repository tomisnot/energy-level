# 引擎参数总表

> 三个主力引擎（sambe / hard / mixed）中所有硬编码参数的集中登记。
> 改任何一项前先看"依据"列——多数参数有实测锚，盲改会破坏已验收的数值基线。
>
> 单位约定：频率 MHz；时间 ns；`_CONV = 2π×1e-3`（rad/ns per MHz）。

## 0. 怎么改参数（正式入口：注册表 + 覆写快照）

`params.py` 是**注册表**（不是一堆裸全局变量）：`SPECS` 描述每个参数
（默认值 / 分层 / 单位 / 说明 / 类型），`DEFAULTS` 存默认值，
**覆写存在线程本地的栈里**，以"每次运行一个快照"生效。

### 三条使用规则

| # | 规则 | 说明 |
|---|---|---|
| 1 | **读**用 `P.get('NAME')` | `from . import params as _P`；**不要**在函数签名默认值里写 `P.NAME`（import 时求值会绕过覆写）。签名默认写 `None`，体内 `x = _P.get('NAME') if x is None else x` |
| 2 | **覆写**用 `with P.override({...}):` | 退出即还原；未知名 → `KeyError`（早失败，不静默无效）；可嵌套（就近优先） |
| 3 | `P.NAME` 仍可用 | PEP 562 `__getattr__` 回落到 `get()`，旧代码/脚本零改动；但只在"无覆写生效"时等于默认值 |

### GUI 路径（主入口）

上帝模式 → 检视器最后一页 **「引擎参数」**。该页由 `params.SPECS`
**自动生成**（新增/改名参数只改 `params.py` 即可），按【A~E】分层分组，
留空 = 默认，填了 = 只对本次运行生效。运行链路：

```
检视器「引擎参数」页 → param_overrides() 快照
  → engine_kwargs['param_overrides']
  → EvolveWorker.run() 里 with params.override(snapshot): 引擎(...)
```

线程本地栈 ⇒ 工作线程里的引擎读到覆写、主线程不受影响，且天然可重入。

> **场景级旋钮仍在各自页**（不是引擎参数）：`r_crit` → 处理链；
> `tol` / `max_step` / `per_freq_M` → 求解过程。那里填的值**优先**于本页同名参数。

**非法输入的处理（不弹模态）**：输入框即时校验，非法项标红 + tooltip 提示
"应为 int；留空即用默认值"，顶部计数显示"生效 n 项 · 非法 m 项已忽略"，
运行前再在状态栏提示一次。**只忽略该项，不牵连其它覆写、不打断运行**
（早期版本会弹 `QMessageBox` 并把整批覆写一起丢掉，已改）。

**引擎覆写只有一个来源**：`MainWindow.engine_overrides`（会话真值）。
检视器页与参数注册表 `engine.*` 都是它的读写通道；worker 运行时把它装进
`params.override()` 快照。`god_values()` 只负责场景级旋钮 + `diag`。

## 0b. 控制面契约（t80）

**"引擎算多准"的全部旋钮 = 5 个无量纲量（+ 一组积分容差）**，其余常量
都不是精度旋钮。这是 `params.py` 的分层脊柱（§A~§E 与源码分节一一对应）：

| # | 参量 | 值 | 问什么 | 判据 |
|---|---|---|---|---|
| ① | `PHASE_TOL` | 1e-4 rad | 这项**重要吗**（精度） | Θ=C·T·\|V\|²/max(\|ΔE\|,\|V\|) ≥ θ → 保留（V_dd + 微波对共用） |
| ② | `PHASE_BUDGET` | ~~4e4 rad~~（**已迁 `solve.COST_BUDGET`，默认空＝不限**；见 §6/§14） | 这项**付得起吗**（成本） | 窗宽 ΔD_max = PHASE_BUDGET/(C·T) → 最坏总步数 ≈ 值/0.5，**与 T、体系无关** |
| ③ | `R_CRIT` | 0.0135 | 远强对能否留在光子块 | r=Ω/ω > 值 → 剔除，位移走 far_sos |
| ④ | `RWA_TOL` | 1e-4 | RWA 近似本身够不够准 | Ω/ωL < 值 → RWA 有效（ip4 遗留引擎） |
| ⑤ | `M_EST_TOL` | 1e-6 | 光子块截断够不够 | (r/4)^{2(M−1)} ≤ 值 → M 收敛 |
| + | `DEFAULT_RTOL`/`DEFAULT_ATOL` | 1e-8/1e-10 | 积分器容差 | DOP853（`DEFAULT_ATOL` 由 rtol 派生，**不出现在 UI**） |

③ 与 ④ 是**同一族的两个不同要求**（相差 2 个量级是物理要求不同，不是漂移）；
①② 是同一族的**两个方向**（精度 vs 成本），都用相位表达、都随 T 自适应。

**有量纲的"窗"已全部移出控制面**：
- 微波候选窗 → 由 ② 在运行时派生（`coupling.mw_cap_mhz(T)`），
  旧 `MW_NRES_BW_MHZ` / `MW_M_BW_MHZ` / `_TF_MW_M_BW_MHZ` **已删**；
- M 估计窗三处重复 → 合并为 `M_EST_BW_MHZ`（唯一值 2e4）；
- `AC_FAR_DETUNE_CUTOFF_HZ` **已删**（只是 MHz 版的定义式 + 死导入）。

余下三类**不是**精度旋钮，见 §【C】/~【D】/~【E】：
结构/物理事实（微波-光场分界、里德堡下限、截断阶数上限）、
模型边界（光场反旋窗 `BW_OPT`、两场光场窗 `OPT_NRES_BW_MHZ`、AC 近远分流）、
性能/数值保护（稠密分流、稀疏保护、GMRES、查表点数）。

> 自检：`checks/params_registry_selfcheck.py`（**6 个不变式包 / 40 子条件**）——注册表一致性、
> 覆写/嵌套/还原、**线程隔离**、端到端"覆写真的改变引擎行为"
> （`PHASE_BUDGET`→候选窗、`MW_MAX_MHZ`→候选窗上界、`PHASE_TOL`→判据双向、
> `_RHS_ENV_TAB_N`→表尺寸），以及**控制链路源码级契约**（本页必须由
> `params.SPECS` 生成、worker 必须在 `override()` 里跑引擎）；
> 另有 `checks/gui_params_page_test.py`（4 包 / 13 子条件）把 QDialog 真建起来验读写。

## 14. 控制面收敛：已办与考察后不做

> 原则：**只留无量纲的精度/成本旋钮；有量纲的窗尽量由物理量派生。**

### 已办（t80）

| 项 | 处置 |
|---|---|
| 微波保留窗 | `MW_NRES_BW_MHZ` 删除 → `PHASE_BUDGET/(C·T)` 派生 |
| 三处 M 估计窗 | 合并为 `M_EST_BW_MHZ` |
| 三处行内表点数 | 收成 `_RHS_ENV_TAB_N` / `_AC_ENV_TAB_N` |
| 行内 `1e5` | sambe 6 处 + tensor_fields 1 处改引用 `MW_MAX_MHZ`；route.py 副本改导入 |
| `_VDD_RWA_TOL_MHZ` | 无量纲化为 `FRAME_TOL_REL`（=1e-6，相对 `max(|d_rot|,|d_lab|)`）；两场自检 TP3a「保留 4 / 丢弃 2」为锚 |
| 死参 / 死导入 / 死桩 | `_DENSE_MAX_PAIR`、`AC_FAR_DETUNE_CUTOFF_HZ`、`field_build.arbitrary_field` 桩、`_CONV`/`_group_by_freq` 等未用导入 |

### 考察后**不做**（附证据，避免重复论证）

1. **查表点数按 rtol 派生** —— `_TAB_N` 不是纯精度旋钮，而是**接口契约**：
   任意波形可驱动带宽 = 0.5·(_TAB_N−1)/T，软件把它作为"引擎侧 Nyquist"报给
   用户（`waveforms.f_max_mhz` / `ui_waves`），按 rtol 缩它就改变了承诺的带宽。
   `_RHS_ENV_TAB_N` / `_AC_ENV_TAB_N` 是内存预算。且派生式对尖沿包络
   （SquareEnv edge=1 ns）会算出 ~7e6 点 → 仍需上下限夹取，复杂度不值。
2. **`AC_EFFECT_THRESHOLD_MHZ` 移出 params.py** —— 明确**不移出**：参数集中
   管理优先。它已标注为"UI 显示阈值，非引擎精度旋钮"。
3. **`_DENSE_MAX` / `_TF_DENSE_MAX` 合并** —— 不可合并：标准两场两体 22 态为
   484×5 = **2420 维**，必须留稠密，否则 `backend` 翻成 `tf-sambe-sparse`
   （有两场自检断言该契约）；反向合并到 2200 同理会改变 sambe 侧 backend。
4. **`MW_MAX_MHZ` 与 `adaptive_split_threshold`** —— 同一件事的固定/自适应两条路；
   自适应已 clamp 到 [1e4,1e6] 并以 `MW_MAX_MHZ` 兜底，视为一式（不再动）。
5. **`_VDD_RWA_TOL_MHZ` → 相对式** —— **已做**（见上表）。
