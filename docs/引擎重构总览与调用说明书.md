# 四、引擎调用使用说明书

## 4.1 两条路：静态页 vs 动态页

```
静态页（能级/谱线/跃迁）          动态页（布居 vs 时间）
   不进演化引擎                      进演化引擎
        │                                 │
  base_sublevels()                 runspec.build_run(p)
        │                                 │
  build_level_rows()               runspec.evolve_run(run)
  spectrum_lines()                        │
  collect_transitions()            runspec.result_summary(run, res)
```

**两页的能级基准现在是同一个函数**（`base_sublevels`）——态集合与能量**逐位一致**，
由判据 `levels_twopage_selfcheck` 钉住。

## 4.2 动态页：三步

```python
from src.core import runspec as RS
from src.core.static_atom import ArcCache
from arc import Rubidium87

cache = ArcCache(Rubidium87())

p = {                                   # 登记册快照（纯 dict）
    'groups.list': [dict(n=60, l=0, j=0.5), dict(n=60, l=1, j=1.5)],
    'field.B_gauss': 21.7, 'field.E_vpcm': 0.0,
    'dynamic.mode': 0,                  # 0 单体 / 1 两体
    'dynamic.method': 'mixed',          # 'mixed' | 'sambe' | 'hard'
    'dynamic.t_max': 200.0, 'dynamic.npts': 201,
    'dynamic.psi_single': <身份键>,       # ← 见 §4.8 坑 1
    'dynamic.decay_index': 0,           # 0 自动 / 1 禁用 / 2 自定义
}

run = RS.build_run(cache, p)            # ② 配置 → RunSpec（纯容器，可 pickle）
res = RS.evolve_run(run)                # ③ RunSpec → 结果
summ = RS.result_summary(run, res)      # ④ 摘要（不搬大数组）
```

## 4.3 `RunSpec` 的键（`build_run` 的产物）

| 键 | 含义 |
|---|---|
| `version` / `two_body` / `method` / `method_in` | 版本、单体还是两体、**实际**引擎、快照里选的引擎 |
| `t` / `t_max` / `npts` | 时间网格 |
| `states` / `labels` | 基组（`make_levels` 输出）与标签 |
| `fields` 或 `fields_A`/`fields_B` | 场（单体 / 两体） |
| `psi0` 或 `psi0_A`/`psi0_B`/`psi0_pair` | 初态 |
| `decays` 或 `decays_A`/`decays_B` | 衰变通道 |
| `vdd_matrix` / `pair` | 两体 V_dd 与几何 `R/θ/φ` |
| `frozen_h_ns` / `per_freq_M` | sambe 的旋钮 |
| `engine_kwargs` | 运行级 kwargs（由 `solve.*` 映射而来） |
| `warnings` | **明确报出的"被忽略/改道"**（不静默） |

## 4.4 `Result` 的统一契约（第 1 刀立的）

**所有六个引擎返回同一组键**：

| 键 | 形状 | 说明 |
|---|---|---|
| `t` | `(n_t,)` | 时间轴（ns） |
| **`pops`** | `(n_t, M)` | 布居。**单体 M=N，两体 M=N²** |
| **`states`** | `list[M]` | **与 `pops` 各列一一对应**的身份 dict（含 `label`） |
| `method` / `backend` | str | 声明的方法与实际后端（**两者可能不同**，见 §4.8 坑 4） |
| `error_report` | dict | 引擎自报 |
| `diag` | dict \| None | 诊断快照。**只有 mixed 家族产出**（见 §4.8 坑 5） |
| （单体附加）`loss` | `(n_t,)` | 离开建模空间的累积布居 |
| （两体附加）`pops_A`/`pops_B` | `(n_t, N)` | 两原子**边缘分布** |
| （两体附加）`loss_A`/`loss_B` | `(n_t,)` | 两个原子各自的损失通道 |

**⇒ 取标签永远走 `res['states']`，不要再按单体/两体分支。**
这正是历史上"直接照搬单体标签会把 N² 维布居标错（2026-09-10 教训）"的根治。

## 4.5 六个引擎与选择

| | 单体 | 两体 | 何时用 |
|---|---|---|---|
| **mixed** | `evolve_mixed` | `evolve_mixed_pair` | 光场光子块 + 微波当场硬积分。**默认**，支持任意波形微波 |
| **sambe** | `evolve_sambe` | `evolve_sambe_pair` | 免 RWA 精确。⚠ **单体遇耗散会转 `evolve_reference`（Lindblad）** |
| **hard** | `evolve_hard` | `evolve_hard_pair` | 微波零近似硬积分（numba）。纯微波/任意相位的最快路线 |

**唯一分派表**：`runspec._ENGINE_TABLE`，用 `runspec.engine_fn(method, two_body)` 查。
**判据直接调引擎函数**（它们本身就是公开面），不必经 method 字符串间接。

| `sambe.py` | `M_EST_BW_MHZ`、`_M_START`、`_M_MAX`、`_DENSE_MAX`、`_ENV_PROBE_N`、`_DT_MIN_FRAC`、`_SPARSE_SEG_MAX`、`_SPARSE_MAX_DEPTH`、`_NODE_LADDER`、`_VOLT_MAX_ITER`、`_VOLT_PICARD_FRAC`、`_VOLT_PRE_SWEEPS` |

| `field_build.py` | `_ENV_SAMPLES` |
| `hard.py` | `_TAB_N` |

**分层原则**：
- **运行级旋钮**（`tol`/`r_crit`/`bw_opt`/`max_step`/`phase_budget`…）**已经是引擎函数的 kwarg**，
  默认值 = 本模块常量 ⇒ 想覆写**直接传参**
- **实现常量**（`_SPARSE_*`/`_VOLT_*`/`_DENSE_MAX`/`_TAB_N`/`_ENV_*`）**不是旋钮**，
  就地定义、不做运行级覆写
- **物理事实**（`MW_MAX_MHZ`/`RYDBERG_N_MIN`）就地定义
- **判据参数**（`PHASE_TOL`）放在**定义判据的模块**（`coupling`）

**运行级参数**（`solve.*`）走另一条路：`runspec.SOLVE_KWARG` 映射 → `engine_kwargs`，
按**引擎签名**筛（`_filter_kw(engine_fn(...), ...)`），被丢掉的写进 `warnings`。

## 4.8 坑（都是实测踩过的）

**① `dynamic.psi_single` 收的是"身份键"，不是 label**
`('mJ', 60, 0, 0.5, 0.5, <E 六位小数>)` 或 `('F', n, l, j, mF, E)`，由 `atomic_levels.state_key()` 产出。
喂 label 会被 `resolve_psi` **明确拒绝**（绝不静默回落 0 号态）。

**② 单位**：B=Gauss，E=V/cm，t=ns，微波 freq=**MHz**，光频=**Hz**，Γ=**MHz**。

**③ `solve.MAX_STEP` 只管起步**（`dop853` 只在起步取 `min(..., max_step)`）；
要**真**压步长用 **`solve.MAX_STEP_HARD`**（每步复核，只对 mixed/hard 的 DOP853 生效）。

**④ `method` 与实际后端可能不同**：`sambe` 单体遇耗散会转 `evolve_reference`（Lindblad），
`backend` 会显示 `reference-bdf`。**判断"谁在跑"要看 `res['backend']`。**

**⑤ 诊断只有 mixed 产出**：`res['diag']` 非 None 的只有 `evolve_mixed[_pair]`。
别的引擎给的是 `None`，`diag.summarize` 会**点名引擎**说明这一点（不会误导你"该传 diag=True"）。

**⑥ 两体自定义衰变只支持"丢失"落点**（显式落点会 `NotImplementedError`）。
且两体只支持丢失。

**⑦ `runspec.build_run` 的 `warnings` 要看**：非 mixed 的运行级参数、sambe 遇任意波形改道 hard
等都会写在那里——**这是"不静默"的出口**。
