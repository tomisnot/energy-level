> **减轻每次 AI 调用的工作量**，就是架构和效率兼得。"

## 1. 一句话

新增 `submit_sweep(axes={...})` 等 5 个 MCP 工具：AI **一次调用**把整个参数网格交给
**独立 runner 进程**的多进程池，逐点进度在 GUI 右下角悬浮窗与画布顶部一行文本上
实时可见，结果按点落盘、按需取用。

## 2. 问题：为什么现在不行

| 现状 | 后果 |
|---|---|
| AI 跑网格只能写 `run_python` 脚本，逐点 `run_compute_and_wait` | **串行** + 一个脚本占满整个回合，50 点 = 50 倍墙钟 |
| 并行只存在于 `scripts/tmp/_scan2d_par.py` 这类离线脚本（自建 `ProcessPoolExecutor` + ARC 预热错开） | 不进 journal、不进作业表、**GUI 完全看不见**；AI 每轮重写样板 |
| 离线脚本自己复刻基组装配 | 与登记册**静默分叉**（SKILL 坑 18：6P 展开成 4 个 mJ 还是 16 个 (F,m_F)） |

## 3. 架构：三层 + 一条进程边界

```
GUI / MCP 进程
  ├─ src/core/runspec.py      ← 无 Qt：params 快照 → (基组,场,初态,衰变,引擎kwargs)
  ├─ src/sweep/registry.py    ← 提交侧：建目录/写 spec/起 runner/查状态/取消
  └─ src/ui/sweep_panel.py    ← 人侧可见面（悬浮窗 + 画布条），只读 status.json
        │  进程边界（subprocess）＋ 文件（status.json / points/*.npz|json）
        ▼
  scripts/sweep_runner.py     ← 轻 __main__（spawn 会重导入它，所以只放三件事）
        │  src/sweep/runner.py：ARC 预热 + 预检 + 并行度定档 + 进程池 + 进度聚合
        ▼
  W × worker 进程（spawn）    ← src/core/runspec.evolve_run：与"人点运行"同一段引擎代码
```

### 3.1 为什么是**独立 runner 进程**，而不是 GUI 里的进程池

- 本项目有 Qt 线程生命周期的事故史（2026-09-12：`QThread: Destroyed while thread is
  still running` → 0xc0000409，**整进程静默消失、24 分钟成果全丢**）。
  把 `multiprocessing` 池塞进 Qt 进程，同时引入"spawn 重新导入 GUI 入口"与
  "池子崩了带走软件"两种风险。
- **runner 崩了软件照常活着**；而且 runner 能**脱离软件单跑**（headless 复现/自检）。
- 代价：runner 需要**非 frozen** 解释器（`sys.executable` 能执行 .py）。打包运行下
  `submit` 会**明确报错**，不静默退化。

### 3.2 为什么输入是"登记册快照"而不是一堆参数

`registry.submit(params=…)` 收的是 `sim_state.to_dict()['params']`，**就是存档里那份**
（登记册即真值，P5）。于是：

> 扫描在构造上 = "把人点运行的那份配置跑 N 次"

AI 不需要复述任何配置，只需要说"哪个参数取哪些值"。这也是"减轻每次 AI 调用工作量"
的主要来源。

### 3.3 进度通道：共享内存 + **引擎现成的取消协议**（零改引擎）

每个点分配 `Array('d', 3N)` 的 3 槽，做成 numpy 视图后**当 `progress_arr` 传进现有
evolve 调用**——正是引擎已经在用的协议：

| 槽 | 含义 | 谁写 |
|---|---|---|
| `[0]` | 阶段内进度 0..1 | 引擎（`coupling.stage_progress` / DOP853 驱动） |
| `[1]` | 取消标志 | **父进程**写 1.0 → 引擎自己 `raise RuntimeError('用户取消')` |
| `[2]` | 阶段（0 准备/1 积分/2 收尾） | 引擎 |

⇒ 进度可见与取消**都不用改引擎一行**。另有 `Array('i', N)` 记录每点的
queued/running/done/failed/cancelled（worker 自己写，父进程汇总进 status.json）。

### 3.4 成果抗崩溃：每点自己落盘

`points/pt_XXXX.json`（摘要，worker 完成即写）+ `points/pt_XXXX.npz`（数组）。
runner 被硬杀也只丢**正在跑**的那几个点——这是 2026-09-12 事故的直接对策。

### 3.5 并行度：自动按 **内存 + 核数** 定档，并给出理由

```
W = min( cpu − 1 , 可用内存×40% ÷ 单进程峰值 , 点数 )      # 显式 workers 优先
```

两体单进程峰值用**实测锚点** dim=4624 → 1.36 GB 做 dim² 外推
（`src/core/cost.py`，偏保守上界）。**为什么是这个数**写进
`sweep_status()['workers_why']`（一句人话），不做黑箱。

> 定档放在**runner**里而不是 `submit` 里：`submit` 必须立刻返回，不能在主线程
> 建一次完整基组（大基组几十秒）。runner 反正要建，用它知道的**真实 N** 定档。

子进程统一 `OMP/MKL/OPENBLAS/NUMEXPR/NUMBA=1`——否则 W 进程 × 16 线程互相超订。

## 4. AI 面（MCP 工具 + CodeAct）

| 工具 | 语义 |
|---|---|
| `submit_sweep(axes, points, workers, tag, record, record_npts, diag, states, top_n, reason)` | 声明式提交，**立即返回** sweep_id |
| `sweep_status(sweep_id, points_limit)` | 逐点状态/百分比/耗时 + 汇总（只读文件） |
| `sweep_result(sweep_id, states, with_points)` | 逐点摘要 + **`selected_table`**（行=点、列=态） |
| `cancel_sweep(sweep_id, reason)` | 先优雅（已完成点保留），超时才 `taskkill /T /F` |
| `list_sweeps(limit)` | 与 `list_jobs` 同构的作业视图 |

**轴语法**（= `list_params` 的名字，可选索引）：

```
'dynamic.t_max'                  'field.lights[0].intensity'
'dynamic.waves_A[0].env'         'groups.list'（整表替换）
取值： [4,5,6] | {'linspace':[起,止,点数]} | {'arange':[起,止,步长]}
      | {'logspace':[起,止,点数]} | {'value': 整表}      # 解析规则：第一个 [ 之前是登记键
多轴 = 笛卡尔积（轴名排序，最后一个轴变化最快）
```

CodeAct 白名单同步注入：`submit_sweep / sweep_status / sweep_result / cancel_sweep /
list_sweeps / run_sweep_and_wait`，脚本里"提交 → 立刻返回 → 下次调用取结果"不再阻塞回合。

**结果口径**：点摘要是 **6 位小数舍入**（与 `job_result` 一致）；**全精度**在 npz 的
`final_pop`（float64）。位级对拍读 npz，别读摘要。

## 5. 人侧可见面（用户明确要求）

| 部件 | 位置 | 内容 |
|---|---|---|
| `SweepProgressWindow` | 主窗口**右下角悬浮**（`Qt.Tool`，不抢焦点） | **纵向一叠逐点进度条**，每行 `pt07 tag 状态`；表头给 `完成/总 · 进程数 · 耗时`；超 24 行折叠成"其余 N 点"聚合行；「取消扫描」「最小化」 |
| `CanvasBanner` | **画布顶部一行文本** | `⚡ 并行扫描运行中：12/25 点 · 4 进程 · 34s（点这里看逐点进度）`；终态切成"完成/失败/取消"；结束后 8 s 自动收起 |

两条硬约束：

1. **人机同源（P2）**：两者都只读 `registry.status()` → `status.json`，
   与 AI 的 `sweep_status` 读的**是同一份事实**，不存在两套口径。
2. **主线程绝不被阻塞**：取消按钮只调 `registry.cancel_request()`（写 cancel 文件后
   立即返回），等待与结论交给 1 Hz 轮询——本项目 Qt 事故史的直接教训。

> 形态选择：用户原话是"底栏的进度条纵向多出一批"，但状态栏只能横排，纵向堆叠
> 会长很高；经用户裁决改为**右下角悬浮小窗**（同样纵向一叠），并额外加画布那行字。

## 6. 同源收敛（P4）：把配置解析从 GUI 里提出来

原先"配置 → (基组,场,初态,衰变,引擎kwargs)"**只存在于** `ui_dynamic._run_single_body`
`/_run_two_body`。现在提取为无 Qt 的 `src/core/runspec.py`，GUI 与 runner **都调它**：

| 函数 | 作用 |
|---|---|
| `build_states(cache, groups, B, E, pump)` | 动态基组（原 `ui_dynamic._current_states` 逐行搬入） |
| `build_fields_single / build_fields_pair` | 逐引擎场容器 + 任意波形改道（sambe→hard） |
| `resolve_psi / resolve_decays` | 初态身份键 / 叠加态；三档自发辐射 |
| `god_kwargs_from_params` | `engine.*`/`solve.*` → 引擎 kwargs（带**签名白名单**过滤） |
| `evolve_run(run, progress_arr, log, cache)` | 逐分支照抄 `evolve_worker.py` 的引擎调度 |
| `check_run` | 运行前自检（零波形 + 零耗散 = 空演化） |

**顺带的两处架构清理**（都是为"runner 真正 headless"服务的）：

1. `src/__init__.py` 的 8 行 `from .ui import …` 改成 **PEP 562 惰性属性**。
   原先任何 `import src.core.X` 都会连带拉起 PyQt5、`pm_setup` 以及外部依赖
   `param_manager`。改后 `import src.core.runspec` **零 Qt、零 param_manager**
   （`sweep_spec_selfcheck.py` 的 G 包用子进程把这条钉住）。
   `from src import ui_theme` 等既有写法完全不变。
2. `state_key` / `find_state_index` 从 `src/ui/ui_waves.py` 搬到
   `src/core/atomic_levels.py`（runner 要按身份键解析初态，不能 import ui_waves）；
   `成本/内存标定` 从 `src/ai/sim_state.py` 搬到 `src/core/cost.py`（理由同上）。
   两处都**保留同名再导出**，既有调用方零改动。

**等效性怎么保证（不靠"我觉得一样"）**：`checks/sweep_e2e_selfcheck.py` 的 G 包按
**生效值**对拍——GUI 的 `_collect_god_kwargs()`（只带用户改过的键）与 runspec 的
`god_kwargs_from_params()`（带登记册全量）喂进 `params.override` 后，**32 个引擎参数
逐个相等**；自发辐射通道解析结果逐字段相等。

## 7. 实测踩到的坑（都已在代码里修 + 有回归钉）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | **整轮扫描被标 failed**，4 点里跑完 3 点也照样失败 | runner 每秒 `os.replace(status.json)`，撞上 GUI/MCP 正在读同一文件 → Windows `PermissionError: [WinError 5] 拒绝访问`。**是聚合回归在 `--jobs 3` 下抓出来的**，单跑时碰不到 | `_write_json` 加**退避重试**（10×）+ 退路原地直写；monitor 循环里的状态写一律 `_status_try` **绝不让写进度中断计算**。回归 = `sweep_spec_selfcheck` 的 I 包（读者线程一直读、写者写 150 次） |
| 2 | `'c_double_Array_12' object has no attribute 'get_obj'` | `mp.Array(..., lock=False)` 给的是**裸 ctypes 数组**，带锁时才是 SynchronizedArray | `_slot()` 两种都吃 |
| 3 | 扫描用了 1 个进程（明明传了 workers=2） | `submit` 把定档写进 `plan`，runner 却读 `_workers` —— 键名没接上 | spec 里写 `workers`，runner 读 `workers` |
| 4 | `record='pops'` 序列点数越过 `record_npts` | `stride = int(len(t)/want)` 向下取整 → 101/20 → 21 点 | 改向上取整 `-(-a//b)` |
| 5 | 位级对拍"失败" | 点摘要是 **6 位舍入**，直接跑是全精度 | 断言改读 npz 的 `final_pop`（并单独断言摘要 = 该值的 6 位舍入） |
| 6 | `TypeError: unexpected keyword argument 'frozen_h_ns'`（潜在） | 登记册 `solve.*` 的读回值会全量进 kwargs，而 `frozen_h_ns` 只有 sambe 两体认；GUI 靠"只传用户改过的键"绕开了 | runspec 按**签名白名单**过滤（`_MIXED_SINGLE_KW`/`_MIXED_PAIR_KW`），被丢的键写进 `warnings` |
| 7 | 引擎参数"两套写法不一致" | 登记册快照走 JSON（`json_safe`），`_NODE_LADDER` 默认是 **tuple**、快照回来是 **list** | 断言按 list/tuple 归一后比，并把"未归一时只允许这一个原因"也写成子条件 |
| 8 | runner 子进程 import 失败 | 软件本体依赖**项目外的包**（`param_manager` 是同级另一个仓库，靠调用方 sys.path 才可见） | `submit` 把父进程 `sys.path` 经 `EL_SWEEP_SYS_PATH` 传给 runner；`sweep_runner.py` 注入 |
| 9 | 取消测试"假红"：取消时全跑完了 | 点跑得比 1 Hz 轮询还快 ⇒ "取消时还有活干"根本发生不了 | 测试改用**故意慢**的工作点（2000 ns 窗口要解析 17 GHz 载波），并把"取消前确实还有点在跑"也写成断言 |

## 8. 验收证据

### 8.1 新增自检（4 个脚本，进聚合）

| 脚本 | 项(包) | 子条件 | 覆盖 |

| `checks/sweep_e2e_selfcheck.py` | 7 | 33 | **扫描≡单点（npz 全精度逐位）**、**串行≡并行（每点逐位）**、轴真生效、**取消+无孤儿进程**、落盘、record 档位、**runspec⇄GUI 同源** |

### 8.2 关键锚点（真引擎跑出来的，不是接口自检）

- **A 包**：同参数下扫描第 0 点的 `final_pop` 与直接 `build_run+evolve_run`
  **逐位相等**（`==`，Δ=0.0）。
- **B 包**：同一批 4 点，`workers=1` 与 `workers=3` 的**每点终态布居逐位相等**
  ⇒ 并行不改变物理。
- **D 包**：半途取消 → 状态 `cancelled`、已完成点保留、runner 进程已退出、
  **`ParentProcessId=runner` 的子进程数 = 0**（无孤儿）。
- **G 包**：32 个引擎参数生效值逐个相等 + 自发辐射解析逐字段相等 + 基组/初态/方法一致。

## 9. 已知限制 / 未做

1. **frozen（PyInstaller）下不可用**：`submit_sweep` 明确报错并指向开发入口。
2. **每个 worker 独立付一次导入/JIT**：`hard` 引擎 numba JIT 每进程各编一次。
   点很短时"并行"可能比串行慢——**点越多越划算**。
3. **位级一致只在 BLAS 单线程下成立**：runner/worker 钉 1 线程；GUI 交互跑用默认
   线程数 ⇒ "GUI 单跑 vs 扫描点"只到积分器容差级。
4. **`V_dd` 按 worker 记忆化**：不碰 `R_um/theta_deg/phi_deg` 的轴每 worker 只算一次；
   碰了这三者就每点重算（很贵）。
5. **扫描不进 `_jobs`**：它是独立的作业族（`list_sweeps`），避免污染
   `summary()['running_job']` 与"已有演化在运行"的判定。GUI 侧由其自己的
   悬浮窗呈现。
6. **未做**：扫描的自动续跑/断点重连、结果自动绘图、跨机并行、把
   `arbitrary_mw_group`（任意波形）也纳入轴（目前轴只能改波形的**字段**，
   整张波形表可用 `'dynamic.waves_A'` 换）。

## 10. 怎么用（最短路径）

```python
# AI 侧（MCP）
r = submit_sweep(axes={'field.lights[0].intensity': [4, 5, 6],
                       'dynamic.waves_A[0].freq_mhz': {'linspace': [7300, 7420, 25]}},
                 states=['60S', '60P', '58G'], tag='freeze-2d')
sweep_status(r['sweep_id'])                          # 进度
sweep_result(r['sweep_id'], states=['60S', '58G'])['selected_table']   # 趋势表
cancel_sweep(r['sweep_id'])                          # 取消

# 人侧：什么都不用做——右下角出现逐点进度窗，画布顶部出现一行"⚡ 并行扫描运行中"
# 手工脱离软件跑（headless 复现/排障）：
#   python scripts/sweep_runner.py --spec runtime/sweeps/<sid>/spec.json
```
