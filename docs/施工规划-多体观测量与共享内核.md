## 1. 目标与范围

### 1.1 要达成的结果

1. **R1**：Pauli 串从"逐引擎接线"收成**一个求值入口**，后端只声明"能否给态"。
2. **R2**：CPU MPS 含时（`tebd`/`tdvp`/`tdvp-single`/`tdvp-adaptive`）支持 Pauli 串，
   一次接线覆盖四个后端，ED 对拍 <1e-6。
3. **R3**：GPU MPS（`tebd-gpu`/`swap-tebd-gpu`）支持 Pauli 串，CPU 对拍 <1e-8，不静默退化。
4. **R4**：近似后端（轨迹/经典/PEPS）要么算并显式标注语义，要么拒绝并说明。
5. **R5**：没有多体态的后端（QMC/KPM/free-fermion/gpu-batch）拒绝时给可用替代。
6. **R6**：运行卡片能投影 Pauli 串（低优先，不崩即可）。
7. **R7**：每次改动后四条基准必须重跑并记录。

同时完成（已获认同的类级改进）：

- **能力矩阵**：`backends.py` 补全，schema/GUI/preview/estimate/测试从它派生；
- **通道共享**：CPU/GPU/稀疏装配共用一套 XOR 通道语义，CPU matvec 去掉每步重复搜索；
- **测量层**：公共观测量只定义一次，后端只供态/概率/系综；
- **Pauli 预计算**：位翻转索引与相位按字符串预计算，跨时刻复用；
- **DMRG 路由去编译化**：数跨切割键不再建 MPO；
- **基准基座**：随机非对称复 calib + 精确稠密参考 + 不变量，供新判据复用；
- **旧接线清理**：多体 GUI/存档里已删除的 `manybody.atoms/second_order/...` 键。

### 1.2 明确不做

- 不改单体/两体引擎（除共享层被动受益）。
- 不加 `chirality`/CSL 专用键或专用算符名；引擎只算 Pauli 串。
- 不恢复 `manybody.terms/template` 用户输入；不改 `calib` 形状。
- 不做结构因子、拓扑判据、热力学极限、并行扫描入口。
- 不做 GPU 大规模性能优化；R3 只要求"能算且对"。
- 不整体重写 `eq_route`/`runspec_mb`；只做局部的声明化与删除死分支。

## 3. 目标结构（改完后）

```
schema_mb / protocol
   └─ 由 backends 能力表派生枚举、默认、拒绝面
        │
runspec_mb / eq_engine
   └─ 只做快照→RunSpec、线程边界、选项转发
        │
        ├─ channels.py（新）        一套 XOR 通道语义
        │     ├─ build_H_sparse 消费 → CSR
        │     ├─ matrix_free 消费   → CPU/GPU matvec
        │     └─ 缓存按内存预算，可降级
        │
        ├─ measurement.py（或 observables 扩展）
        │     ├─ 公共观测：pops/spin/link/loop/entropy/corr/pauli
        │     ├─ 后端只供 state/probability/ensemble + 语义标签
        │     └─ PauliPlan：按字符串预计算 perm/phase，跨时刻复用
        │
        └─ engine_*（薄）
              ├─ ED：全空间/受限基
              ├─ MPS：TeNPy
              ├─ GPU MPS：torch（duck-typed 适配器，不把 torch 拉进 core 顶层）
              ├─ PEPS/轨迹/经典：显式 approximation 语义
              └─ 结果 → results.describe_result → data_schema
```

**关键取舍**：语义一份，编译表示可以多份。CSR、LinearOperator、MPO、torch 张量是同一
物理问题的不同表示；每一份都要与同一份通道/测量语义对拍。

### P2 通道共享 + CPU matvec 优化（3–5 人日）

**目标**：一套 XOR 通道语义；CPU Lanczos/扇区 matvec 不再每步重算掩码与搜索。

**设计**

- 新增 `src/core/manybody/channels.py`（若评估后更合适，也可并入 `matrix_free.py`，
  但必须被 `assemble` 与 `matrix_free` 两个消费者使用，避免悬空）：
  - `channel_spec(calib, Om, delta, gamma, terms)` → 对角项 + 通道列表
    `(kind, site_or_pair, mask, selection, amp)`；
  - `ChannelTable(basis, spec, budget_bytes)`：
    - 全空间：目标索引 = `code ^ mask`，无需搜索；
    - 受限基：`pos` 表（`2^n` int32，n≤26）或 `searchsorted` 回退；
    - 每通道的 `cols/loc` 可**惰性缓存**，按预算裁剪；超预算则按块处理或回退到按需计算；
  - `matvec(v)`：`y = diag*v`；每通道 `y[tgt] += amp * v[cols]`（XOR 单射，无重复）。
- `assemble.build_H_sparse`：消费同一 `channel_spec` 生成 COO；保持现有 `basis_indices`
  映射与 MSB 位序；输出与改前**逐元素相等**。
- `matrix_free.hamiltonian_linear_operator`：消费 `ChannelTable`；保留旧实现作为
  `reference` 路径（判据用），产品默认走新路径。
- GPU `_channel_arrays`：改为消费 `channel_spec`，保持现有分组/预算逻辑。

**验收**

- 随机复 calib（含 Ω/δ/γ、I1/I2/I3）上：
  - `build_H_sparse` 新旧逐元素 `max|Δ|=0`（或 <1e-14）；
  - `matvec` 新旧 `max|Δ|<1e-12`；
  - 与稠密 `build_H_ed` 的 `H@v` 对拍 <1e-12；
- N=16/20 扇区基态：Lanczos 总时间有可重复的改善（记录中位数），峰值内存不超预算；
- `equibench_engine_ed`、`manybody_sector_scan`、`equibench_router` 绿。

**风险**：通道表内存爆炸 → 必须惰性 + 预算 + 回退；不得为了快而改变符号约定。

### P3 测量层 + R1 统一 Pauli 入口 + Pauli 预计算（4–6 人日）

**目标**：公共观测只定义一次；Pauli 串一个入口；三套现有实现结果逐位不变。

**设计**

- `src/core/manybody/observables.py`：
  - `PauliPlan`：按 `(n, strings)` 预计算
    - 全空间：`perm`（翻转索引）与 `phase`（±1/±i），使
      `⟨P⟩ = Σ conj(ψ) * phase * ψ[perm]`；
    - 受限基：`cols`、`loc`、`phase`；
    - MPS：`[(site, axis)]` 与解析后的局域算符名。
  - `measure_pauli_strings(state, specs, *, basis_states=None, n=None, order=None)`：
    - `np.ndarray` + `basis_states` → 受限基路；
    - `np.ndarray` 长度 `2^n` → 全空间路；
    - 有 `sites`/`expectation_value_term` → TeNPy MPS 路；
    - 有 `pauli_expectation(plan)` 方法 → 委托（torch 适配器用，不 import torch）；
    - 其他 → `TypeError` 点名支持的形态。
  - `PauliPlan` 是唯一实现；不再保留并行的全空间/受限基函数。
- `src/core/manybody/engine_ed.py`：`_reduce` 用 `PauliPlan`（建一次，逐时刻复用）；
  `bit_matrix`/`entropy_in_basis` 的映射按 `(n, dim)` 或 `(basis, cut)` 缓存。
- `src/core/manybody/eq_route.py`、`dmrg.py`：改用统一入口；保持结果形状。
- `src/core/manybody/results.py`：确认 `data_schema` 不变。
- `checks/manybody_pauli_string_selfcheck.py`：用**独立稠密参考**与跨形态对拍。

**验收**

- 全空间/受限基/MPS 与稠密参考逐位一致（R7 基准表）；
- 统一入口在 ED/受限基/TeNPy MPS 上结果一致；
- Pauli 求值在 N=12/24 串/13 时刻上有可测加速；
- `pauli_strings=None` 时所有结果与改前逐位一致；
- `manybody_pauli_string_selfcheck` 只增不减。

**风险**：`PauliPlan` 的相位/位序错 → 用独立稠密参考 + 手性验收脚本钉住。

### P4 R2：CPU MPS 含时 Pauli（2–4 人日）

**目标**：一次接线覆盖 `tebd/tdvp/tdvp-single/tdvp-adaptive`。

**改动**

- `src/core/manybody/engine_mps.py`：`evolve_mps(..., pauli_strings=None)`；
  在逐时刻归约处调用 `measure_pauli_strings(psi, specs)`；结果写
  `observables.pauli_strings` / `pauli_string_labels`。
- `backends.py`：四个后端 `pauli='mps'`；`validate_time_capabilities` 按其判定。
- 注意 `conserve='Sz'` 的局域基序：优先用簇模型注册的 `SZ/P/M`，不直接用 TeNPy 的
  `Sigmaz/Sp/Sm`；回退逻辑保持 `observables._mps_axis_terms` 的现有判据。
- 新判据 `checks/manybody_pauli_mps_selfcheck.py`：同 calib、同初态、同 `t_grid`，
  ED vs TDVP 逐点 <1e-6；登记 `run_checks.py::CORE`。

**验收**

- 上述判据绿；12 点 kagome 撤场基准四值

### P5 R3：GPU MPS Pauli（3–5 人日，需 CUDA）

**目标**：`tebd-gpu`/`swap-tebd-gpu` 能算且对；不静默退化。

**路线（建议 a）**：GPU 内直接算。

- `mps_torch.py`：给 `TorchMPS` 加 `pauli_expectation(plan)`，复用现有
  `transfer_left`/张量收缩；局域算符表由 `PAULI_LOCAL` 转成 torch 常量（只在 GPU 后端初始化时转一次）。
- `engine_mps_gpu.py`：逐时刻调用适配器；结果字段与 CPU 完全同形；`error_report` 标注
  `backend/order/dtype/device`。
- `backends.py`：两个 GPU 后端 `pauli='torch'`。
- 新判据 `checks/manybody_pauli_gpu_selfcheck.py`：无 CUDA 诚实 SKIP；有 CUDA 时
  与 CPU `tdvp` 对拍 <1e-8；登记 `CORE`（SKIP 不伪造通过）。

**不选 (b) 的理由**：转 TeNPy 只在小 N 可行，且引入隐式转换与额外内存；违背
"原生态不隐式互转"的既有约定。若最终因工期选 (b)，必须在结果与文档中写清边界。

**验收**：对拍通过；GPU 结果不因 `swap-tebd` 的路由 SWAP 丢符号；失败时明确报错。

**风险**：显存/ dtype；SWAP 路由改变 MPS 顺序 → 先按 `order` 映射回原子序再求值。

1. **先止血（低风险，0.5–1 天）**：移除已删除键的控件/写入路径；多体页只保留
   "读当前 calib / 从 `build_calib` 生成"的入口；旧存档载入时给明确迁移提示
   （"该存档使用已退役的 manybody.atoms；请用 build_calib 重新生成 calib"）。
2. **再迁移（可选，2–4 天）**：点云表 → `ManyBodyModel` → `calibrate` →
   `manybody.calib`（复用 `calibrate_memo`，主线程执行）；删除 `second_order/n_window/
   guard` 控件，改用固定默认值 + 文档说明；`gui_manybody_selfcheck` 覆盖。

**验收**：多体页加原子/运行不再触发 `UnknownKey`；旧存档给出可操作提示；
`gui_manybody_selfcheck` 绿；不改变 AI 面契约。

**决策门 G4**：迁移 vs 只止血。建议先止血，迁移单独排期。
