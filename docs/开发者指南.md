 # Energy Level 开发者指南
 
 Energy Level 是一个面向 Rb-87 原子能级、外场驱动、耗散演化和多体体系的研究软件。领域代码位于 src，mecha_v2 负责与统一操作者体系连接，GUI 和 MCP 只是宿主。
 
 ## 1. 分层
 
 | 层 | 目录 | 责任 |
 |---|---|---|
 | 物理模型 | src/core/atomic_levels.py、static_atom.py、static_pair.py | 原子态、能级、静态场、偶极和相互作用 |
 | 输入协议 | src/core/protocol.py、runspec.py、param.py | 参数描述、运行规格、单位和默认值 |
 | 外场 | src/core/waveforms.py、tensor_fields.py、field_build.py、field_loss.py | 光场、微波、张量场和损耗 |
 | 单体演化 | src/core/evolve_reference.py、evolve_rwa.py、evolve_mixed.py、evolve_twofield.py | 精确、RWA、mixed、双场路径 |
 | 多体 | src/core/manybody/ | ED、DMRG、KPM、平衡态和观测量 |
 | 扫描 | src/sweep/ | 规格展开、点调度、状态和结果 |
 | 项目协调 | mecha_v2/engine.py | ElEngine，线程边界、缓存、演化和摘要 |
 | 操作者接线 | mecha_v2/bridge.py、tools.py、control.py | GUI、MCP、Gate、Jobs 和工具 |
 | GUI | src/ui/、app_entry.py | 参数界面、图表、检查器和后台 worker |
 
 ## 2. 项目协调器
 
 ElEngine 是 EL 内部协调器。它拥有 ARC cache 和物理计算线程的生命周期，负责：
 
 - 读取和规范化快照；
 - 构建能级和场；
 - 预览、估算和正式演化；
 - 观察取消标志并报告进度；
 - 生成摘要和诊断；
 - 把结果交给 Bridge、Jobs 或 GUI。
 
 mecha 不承载物理 Engine。ElEngine 也不负责写权、工具 schema 或 MCP 传输。更改 ElEngine 时，应同时考虑 GUI 和 MCP 的调用语义。
 
 ## 3. 配置和运行规格
 
 配置状态由 Bridge/Session 管理，写入经过 Gate。运行时先复制快照，再应用 spec_patch：
 
 ~~~text
 当前配置
   -> effective snapshot
   -> spec_patch
   -> validate
   -> estimate/preview/run
 ~~~
 
 spec_patch 只描述本次计算的差异，不能静默修改共享配置。参数键、单位和默认值由 runspec/protocol 定义；GUI 与工具都从这些描述生成表单或 schema。
 
 运行规格至少应明确：
 
 - 原子种类和态选择；
 - 外场、极化、频率、强度和相位；
 - 时间网格和终止时间；
 - 演化路径和误差容限；
 - 初态、衰减和观测量；
 - 资源和最大步长。
 
 ## 4. 数值路径
 
 ### 静态能级
 
 atomic_levels、static_atom 和 static_pair 负责能级、场致位移、偶极和两体静态数据。缓存按原子、基组和场参数组织。修改缓存结构时要验证缓存命中、线程亲和和重复计算。
 
 ### 单体演化
 
 - reference：直接数值参考路径，适合小规模核对；
 - rwa：旋转波近似和耗散路径，适合满足近似条件的驱动；
 - mixed：按频率和耦合规模混合处理；
 - twofield：同时处理光场和微波场。
 
 选择逻辑在 EL 领域代码中完成。工具层只传递明确的 method、backend 或 auto 请求，并返回采用的路径和诊断。
 
 ### 多体
 
 src/core/manybody/ 下的 assemble、model、equilibrium、engine_ed、dmrg 和 kpm 负责多体构造与求解。多体输入包括体系几何、相互作用、扇区、温度、边界和目标观测。大矩阵和谱通过产物或结果文件返回。
 
 ### 扫描
 
 src/sweep/spec.py 负责轴展开和点生成，registry.py 保存 sweep 身份、状态和结果，runner.py 执行点并更新进度。扫描点必须有稳定索引和独立结果目录；单点失败不能伪装为零值。
 
 ## 5. 工具和操作边界
 
 mecha_v2/tools.py 的工具分为：
 
 - 查询参数、能级、波形和资源估算；
 - 写入配置和驱动设置；
 - 预览和正式演化；
 - submit_job、read_job、cancel_job；
 - run_actions 组合只读或动作步骤。
 
 查询不写配置。写入通过 Bridge.write 或项目命令经过 Gate。后台演化共享 ElEngine 的正式路径，不在 job 闭包内复制 solver。
 
 run_actions 的每一步应返回 name、ok、result 和错误信息。组合动作遇到失败要说清已完成步骤和下一步查询。
 
 ## 6. 线程和缓存
 
 ARC 和部分物理对象要求在创建线程使用。ElEngine 通过自己的计算线程边界保证线程亲和。GUI worker、MCP job 和共享模式都必须把计算提交到正确的执行上下文。
 
 禁止：
 
 - 从 GUI 线程直接操作计算线程独有 cache；
 - 在模块导入时构建全局 cache；
 - 将 numpy、ARC 或 Qt 对象跨线程随意传递；
 - 让关闭路径遗留 worker 或端口。
 
 ## 7. 任务与取消
 
 长演化和 sweep 使用 mecha Jobs。ExecutionContext 的取消标志由 solver 在安全点读取。取消后回执应说明：
 
 - 请求前状态；
 - 是否已经终止；
 - 已完成的时间或点数；
 - 是否有部分结果；
 - 结果引用和清理状态。
 
 max_step、rtol、atol 和网格大小会直接影响耗时与精度。estimate 只做资源规划，不替代实际演化。
 
 ## 8. 诊断和结果
 
 diag.py 汇总 solver steps、频率比、相位预算、RWA 适用性、损耗和快照尺寸。结果解释至少包含：
 
 - 选择的路径；
 - 基组和截断；
 - 时间范围和采样；
 - 误差容限；
 - 外场规格；
 - 警告与近似条件。
 
 开发者新增求解器时要提供统一摘要和可读失败，不能只返回裸 numpy 数组。
 
 ## 9. 新增求解路径
 
 1. 在 src/core 中实现纯领域函数；
 2. 定义输入和输出协议；
 3. 加入小规模 reference 对照；
 4. 在 ElEngine 的路由和 schema 中登记；
 5. 加入 estimate、preview 和正式 run 的行为；
 6. 将取消、进度、警告和诊断接入；
 7. 更新引擎能力边界和用户手册；
 8. 补 GUI/MCP 接线测试。
 
 不要把特定 solver 参数写进 mecha 核心。只有当多个项目确实共享同一机制时才考虑提取。
 
 ## 10. 扫描扩展
 
 扫描规格应通过 spec.py 的路径访问器表达嵌套参数。新增轴类型要明确：
 
 - 值的类型和单位；
 - 展开顺序；
 - 重复值处理；
 - 点身份；
 - 结果命名；
 - 失败重试和取消。
 
 registry 的 status 必须区分 queued、running、completed、failed 和 cancelled。部分结果可读取，但不能把未完成状态标成完成。
 
 ## 11. GUI 与 MCP 入口
 
 app_entry.py 负责启动 GUI、MCP 或二者并行。mecha_site.py 负责站点声明和统一启动。GUI 通过 Bridge 读取快照、写入配置和提交 worker；MCP 通过 Hub/Tools 访问同一 Bridge。
 
 修改 GUI 参数表时同时检查：
 
 - protocol/runspec 是否有定义；
 - Gate 是否允许写入；
 - schema 是否投影正确；
 - 运行时是否使用 spec_patch；
 - 结果和错误是否能在 MCP 中表达。
 
 ## 12. 测试
 
 常用验证包括：
 
 ~~~powershell
 python run_checks.py                 # 默认 smoke，<1 min
 python run_checks.py --cascade       # smoke 失败才展开 core
 python run_checks.py --changed       # 按工作区改动选判据
 python run_checks.py --core          # 共享层改动/合并前
 python checks/core_selfcheck.py
 python checks/runspec_contract_selfcheck.py
 python checks/engine_contract_selfcheck.py
 python checks/control_channel_selfcheck.py
 python checks/sweep_spec_selfcheck.py
 python checks/evolve_exact_selfcheck.py
 python checks/evolve_dissipative_selfcheck.py
 python checks/mcp_entry_smoke_selfcheck.py
 python checks/gui_run_flow_selfcheck.py
 ~~~
 
 新算法至少需要纯函数、reference 对照和最小接线测试。涉及缓存、线程、任务或工具时，必须补对应生命周期测试。
 
 ## 13. 维护规则
 
 - 物理语义留在 src/core；
 - ElEngine 只协调 EL 的计算；
 - mecha 提供写权、任务、事实和宿主能力；
 - 配置快照与 spec_patch 分离；
 - estimate/preview 不能冒充正式结果；
 - 近似条件和单位写入领域文档；
 - 结果摘要和原始数组分离；
 - 失败需要说明输入、路径和可操作建议；
 - 关闭时释放线程、cache、HTTP 和端口。
 
 接手任务时先看 mecha_v2/bridge.py 的装配，再看 engine.py 的调用路径，最后进入对应 src/core 模块。
